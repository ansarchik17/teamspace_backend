# BRD-005: доска, список и поиск (backend)

Оба представления используют одинаковые фильтры и проверяют доступ текущего пользователя:

- `GET /api/v1/kanban/board/filtered?board_id=<uuid>` — объект `board`, все колонки, в каждой `tasks` текущей страницы. Пустые колонки сохраняются.
- `GET /api/v1/kanban/tasks/search?board_id=<uuid>` — массив карточек для списка (совместимый формат). Без `board_id` ищет по всем доступным доскам.

Общие query-параметры:

| Параметр | Семантика |
|---|---|
| `q` | Подстрока в названии, описании, ключе задачи или статусе; без учёта регистра; до 256 символов. `%`, `_`, `\` — обычный текст. |
| `author_ids` | ID постановщиков (`created_by`), а не исполнителей |
| `statuses` / `status` | Несколько статусов / один статус; совпадение со статусом задачи либо ключом/названием колонки. Стандартные TODO, IN_PROGRESS, TEST, DONE также принимают русские названия статусов. |
| `assignee_ids` | ID исполнителей |
| `column_ids`, `column_keys` | UUID / ключи колонок |
| `priorities` | Приоритеты, без учёта регистра |
| `label_ids`, `sprint_ids`, `sprint_id` | Метки, спринты, один спринт |
| `date_from`, `date_to` | Границы срока включительно, RFC3339 |
| `limit`, `offset` | По умолчанию 100 и 0; максимум 200; стабильный порядок `created_at DESC, id DESC` |

Массивы передаются повторением параметра: `author_ids=1&author_ids=2&statuses=TODO&statuses=DONE`. Внутри группы действует OR, между группами AND. Некорректные UUID, ID пользователей, даты и пагинация дают 400, а не расширяют выборку.

Пагинация доски применяется ко всей выборке перед группировкой по колонкам. `total_tasks` колонки — число карточек **в текущей странице**, не общий счётчик совпадений. Для загрузки следующей страницы увеличивать `offset` на `limit`, пока вернувшихся задач меньше `limit`. Для списка та же схема. При конкурентном изменении данных offset-пагинация не обеспечивает снимок.

Старые параметры доски сохранены: `name` — псевдоним `q` (q приоритетнее), `date=YYYY-MM-DD` — целый день UTC (переопределяет date_from/date_to), `user_id` — владелец дефолтной доски, **не автор задачи**. Чужая доска доступна только её участникам; запрос не создаёт доску другому пользователю. Без board_id/user_id используется своя дефолтная доска.

## Производительность и запуск

Миграция `20260924000400_task_search_indexes.sql` добавляет pg_trgm/GIN индексы для текстового поиска и индексы доски/автора/порядка. Применить штатным запуском мигратора перед развёртыванием backend. Создание индексов обычное, на большой таблице потребуется окно обслуживания. Для коротких строк менее трёх символов PostgreSQL может выбрать последовательное сканирование.

Карточки страницы загружаются четырьмя SQL-запросами независимо от их количества: задачи, исполнители, вложения, метки. Удалены дубли от JOIN исполнителей и исправлены параметры SQL при фильтрации по спринту с пагинацией.

Интеграционные тесты проверяют одинаковую выдачу доски/списка, пересечение фильтров, доступ, удалённые записи, кириллицу, ключи, экранирование, пагинацию, данные вложений/меток, миграцию и поиск среди 20 003 доступных задач. Фронтенд не изменяется: переключение представлений и передача фильтров подключаются к этим API.
