# Фоновые операции без отдельной служебной квоты

Изменение согласовано 20.10.2026. Этот документ заменяет прежнее правило
`Qservice` в спецификациях бюджетов, API и инструкции запуска.

- Пользовательские обращения, включая вызовы модели для истории, инструментов
  и заголовка, расходуют личные окна сотрудника и недельный бюджет компании.
- Доверенные фоновые операции без пользователя расходуют только недельный
  бюджет компании. Отдельного выделения, служебного лимита и пятичасового окна
  у них нет. Произвольный клиент не может выбрать такого плательщика.
- Общий остаток: `max(0, бюджет − фактический расход − все активные резервы)`.
  Квоты сотрудников — ограничения, а не отдельные кошельки: фоновые задачи
  могут уменьшать общий остаток даже при назначенных личных квотах.
- Выделено: сумма недельных квот сотрудников. Обязательства: прежняя сумма
  `max(квота, расход + резерв)` по сотрудникам плюс фактический фоновый расход
  и его активные резервы. Старое служебное выделение не добавляется.
  Пример: бюджет 1000, квоты 800, фон потратил 50 и удерживает 20 — обязательства
  870, доступно для распределения 130. Повторного суммирования зеркальных
  счётчиков периодов нет.
- Без настроенного бюджета и при бюджете 0 enforced запрещает также фоновые
  вызовы. Observe записывает превышения компании без отдельного service gate.
  Неизвестные usage/модели не становятся бесплатными; правила общего исполнителя,
  идемпотентности, сверки, изоляции и целочисленных вычислений сохраняются.
- История, сервисные счётчики и неизвестные резервы не удаляются. TTL не
  освобождает неизвестный расход; смена периода переносит активные удержания.

## Совместимость HTTP и БД

В PUT бюджета обязательны `weekly_budget_microcredits`, `max_five_hour_microcredits`
и `revision`. Старое поле `service_weekly_quota_microcredits` необязательно:
корректное неотрицательное строковое значение принимается для совместимости,
но не назначает деньги и не влияет на revision при прочих неизменных настройках.
Неверный формат, диапазон, дубликаты и неизвестные поля по-прежнему отклоняются.

В GET старое поле возвращается как `"0"`, `capabilities.set_service_quota=false`.
`service.used/reserved/carried_reserved_microcredits` продолжают показывать
реальный фоновый расход; старое `service.available_microcredits` означает общий
остаток компании. Новый интерфейс показывает фоновый расход и резерв, а не квоту.
Новый frontend отправляет legacy-поле `"0"` для совместимости со старым API.
Исторические события аудита могут содержать прежнее служебное выделение.

Существующий столбец БД сохраняется, но не читается при допуске и расчётах.
При изменении бюджета записывается 0; массового обнуления, изменения периодов
или переписывания старого аудита нет. Новая миграция не требуется.

## Обновление

Обновлять все API и отдельные worker-процессы одной версией до обновления
интерфейса. Смешанные старые/новые процессы применяют разные правила к фону.
Оставить observe до проверки. Ранее созданные образы и архивы автоматически
этого изменения не получают: нужна новая сборка backend и frontend.
Откат старого приложения возвращает прежнюю семантику служебной квоты;
не откатывать журнал и не освобождать резервы для обхода этого ограничения.

Проверки: `TestAIBackgroundUsesSharedBudgetWithoutAllocation`, конкурентный
`TestAIReserveConcurrent/service`, административные summary/update тесты,
проверки строгого JSON и frontend `test-ai-budget-regressions.cjs`.
