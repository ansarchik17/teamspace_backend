# DRV-001 — структура файлов

Бэкенд поддерживает личный корень, вложенные и общие папки, multipart-загрузку, авторизованное скачивание и публичные ссылки с токеном. Общая папка — обычная папка с выданными правами; отдельное хранилище не создаётся.

## API

Все пути имеют префикс `/api/v1`.

- `POST /drive/folders`: `{"name":"Документы","parent_id":null}` → 201, объект папки. Для вложенной папки передать UUID родителя.
- `GET /drive/items/own`, `GET /drive/items/shared`: личные и предоставленные пользователю ресурсы.
- `GET /drive/folders/{id}/children`: содержимое папки.
- `POST /drive/permissions`: существующий API выдачи viewer/editor/owner для ресурса. Viewer читает, Editor может создавать папки и загружать; права наследуются по дереву.
- `POST /drive/files`: multipart/form-data, поле `file` (можно несколько), необязательный `folder_id`. Один файл → 201 с объектом файла; несколько → объект с count/files. Каждый файл сохраняется отдельно: запрос из нескольких файлов не является общей транзакцией.
- `GET /drive/files/{id}/download`: Bearer JWT в заголовке или `access_token` в query; права на файл проверяются.
- `POST /drive/share/link`: `{"resource_type":"file","resource_id":"UUID","role":"viewer","expires_in_sec":3600}` → токен и срок ссылки.
- `GET /public/drive/files/{token}/download`: скачивание по публичному токену без JWT. Истёкший токен → 403; неизвестный токен или удалённый файл → 404.

Повторная загрузка того же содержимого в ту же папку возвращает 409. Предельные размеры определяет FileService: обычный файл 500 MiB, изображение 50 MiB, видео 1 GiB, аудио 100 MiB. Ошибки не означают, что клиент должен автоматически повторять запрос бесконечно.

## Изменения и проверка

Проверка одинаковых названий корневых папок теперь ограничена владельцем, включая создание, переименование и перемещение. В общей папке одинаковые имена по-прежнему конфликтуют. Удаление объекта после ошибки сохранения метаданных использует отдельный контекст с таймаутом: отмена запроса больше не отменяет очистку. Ошибки самой очистки журналируются; распределённой транзакции между PostgreSQL и MinIO нет.

Имена скачиваемых файлов передаются стандартным Content-Disposition с корректным кодированием Unicode и кавычек. При ошибке Stat закрывается объект MinIO.

`TestDriveStructureIntegration` запускается с `TEST_MESSENGER_DATABASE_URL`, `TEST_DRIVE_MINIO_ENDPOINT`, `TEST_DRIVE_MINIO_ACCESS_KEY`, `TEST_DRIVE_MINIO_SECRET_KEY`. Создаёт отдельную схему и временный бакет, удаляет их после теста. Проверяет личные корни, общие вложенные папки, роли Editor/Viewer, постороннего пользователя, точность содержимого, пустой файл, лимит размера, публичный/истёкший/неизвестный токен, удалённый файл, дубликаты, отказ MinIO, откат при ошибке БД и очистку при отменённом контексте.

Проверено 25.09.2026: полный `go test ./...` с PostgreSQL и MinIO, `go vet ./...`, `go build ./...`; живой HTTP-цикл через localhost:5174: папка/файл 201, списки 200, скачивание по Bearer JWT, access_token и публичному токену 200 с точным совпадением байтов. Тестовые ресурсы перемещены в корзину. Это функциональная проверка, не нагрузочное испытание.
