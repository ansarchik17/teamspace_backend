# Group Creation Flow For Mobile

## Что важно понимать

Текущий backend **не умеет** добавлять произвольных пользователей прямо в `POST /groups`.

При создании группы происходит только:

1. создание записи группы
2. автоматическое добавление **создателя** в `group_members` с ролью `owner`

Остальные участники добавляются **отдельным запросом**:

- `POST /groups/{group_id}/members`

Это соответствует текущей реализации:

- `internal/handler/group_handler.go`:
  - `CreateGroupRequest` не содержит `user_ids`
  - `CreateGroup` вызывает только `groupService.CreateGroup(...)`
- `internal/service/group_service.go`:
  - после `CreateGroup` вызывается `AddMember(..., creatorID, "owner")`
- `internal/handler/group_handler.go`:
  - отдельный handler `AddMember`

## Как мобильное приложение должно работать

Если UX требует "создал группу и сразу выбрал пользователей", на мобильной стороне это нужно делать как **цепочку из двух API-вызовов**.

### Шаг 1. Пользователь выбирает данные группы

Мобилка собирает:

- `name`
- `description`
- `type`
- `max_members`
- список выбранных пользователей `selectedUserIds`

Пример локальной модели:

```json
{
  "name": "Project Team",
  "description": "Main working chat",
  "type": "private",
  "max_members": 200,
  "selectedUserIds": [12, 45, 77]
}
```

### Шаг 2. Создать группу

Запрос:

```http
POST /groups
Authorization: Bearer <token>
Content-Type: application/json
```

Body:

```json
{
  "name": "Project Team",
  "description": "Main working chat",
  "type": "private",
  "max_members": 200
}
```

Ожидание:

- backend создаст группу
- backend автоматически добавит текущего пользователя как `owner`
- в ответе придет объект группы с `id`

Критично:

- нужно сохранить `group.id`
- только после этого можно добавлять остальных участников

### Шаг 3. Добавить выбранных пользователей

После успешного ответа от `POST /groups` мобильный клиент должен вызвать:

```http
POST /groups/{group_id}/members
Authorization: Bearer <token>
Content-Type: application/json
```

Рекомендуемый body:

```json
{
  "user_ids": [12, 45, 77]
}
```

Backend также поддерживает одиночное добавление:

```json
{
  "user_id": 12
}
```

Но для мобильного сценария "создать группу и сразу пригласить несколько людей" лучше использовать именно `user_ids`.

## Правильный клиентский сценарий

Рекомендуемая последовательность на мобильном клиенте:

1. Пользователь вводит название группы и выбирает участников.
2. Мобилка отправляет `POST /groups`.
3. Если группа создана успешно, мобилка берет `group.id` из ответа.
4. Если есть выбранные пользователи, мобилка отправляет `POST /groups/{group_id}/members`.
5. После успеха мобилка открывает экран группы и обновляет список участников.

## Псевдокод

```ts
async function createGroupWithMembers(payload) {
  const group = await api.post("/groups", {
    name: payload.name,
    description: payload.description,
    type: payload.type ?? "private",
    max_members: payload.maxMembers ?? 200,
  });

  const userIds = (payload.selectedUserIds ?? []).filter(Boolean);

  if (userIds.length > 0) {
    await api.post(`/groups/${group.id}/members`, {
      user_ids: userIds,
    });
  }

  return group;
}
```

## Что показывать в UI

Лучший UX для мобильного клиента:

1. На экране создания группы дать выбрать название и участников сразу.
2. На submit показывать единый loading state: "Создаем группу..."
3. Внутри этого loading state выполнить оба вызова последовательно.
4. Если оба вызова успешны, открыть чат группы.

Для пользователя это будет выглядеть как один сценарий, хотя на backend это два запроса.

## Как обрабатывать ошибки

### Если не прошел `POST /groups`

Значит группа вообще не создана.

Что делать:

- показать ошибку
- не выполнять запрос на добавление участников

### Если группа создалась, но упал `POST /groups/{group_id}/members`

Значит группа уже существует, но участники добавились не полностью или не добавились совсем.

Что делать:

- показать сообщение вроде:
  - "Группа создана, но не удалось добавить всех участников"
- открыть уже созданную группу
- дать возможность повторить добавление участников

Это важно, потому что первый запрос уже был успешен и откатывать состояние на клиенте как будто группы нет нельзя.

## Практическая рекомендация

Для мобильного клиента безопасный и корректный вариант такой:

1. всегда сначала `POST /groups`
2. потом `POST /groups/{group_id}/members`
3. не пытаться отправлять `user_ids` в `POST /groups`, потому что backend их сейчас не использует

## Итого

Если мобилка хочет "при создании группы сразу добавлять пользователей", это нужно реализовывать **на клиенте как orchestration двух последовательных вызовов**:

1. создать группу
2. добавить участников в созданную группу

Backend уже поддерживает этот сценарий, но не одним endpoint, а двумя.
