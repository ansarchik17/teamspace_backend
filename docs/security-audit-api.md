# BAS-018: журнал безопасности и экспорт

Перед запуском применить `20261012000500_security_audit.sql`. Она создаёт отдельный `security_audit_events`, переносит записи BAS-017 и зеркалирует новые административные события в одной транзакции с исходным аудитом. История задач, заметок и BAS-017 остаётся доступной через прежние API.

## Доступ и API

Все запросы требуют Bearer JWT. Директор определяется владельцем компании; название должности и email прав не предоставляют. Роль платформы — `admin`. Актуальные права проверяются при каждом чтении и экспорте.

| GET | Доступ |
| --- | --- |
| `/api/v1/organizations/current/security-audit` | Директор своей активной компании |
| `/api/v1/organizations/current/security-audit/export` | Те же права |
| `/api/v1/platform/security-audit` | Платформа, все компании, включая события без компании |
| `/api/v1/platform/security-audit/export` | Те же права |
| `/api/v1/platform/organizations/{organization_id}/security-audit` | Платформа, выбранная компания |
| `/api/v1/platform/organizations/{organization_id}/security-audit/export` | Те же права |

Сотрудник не имеет доступа к административному журналу. Директор не может выбрать чужую компанию или использовать platform API для своей. Директор приостановленной компании получает 404; платформа может читать её историю. Компания пользователя сохраняется в событии при записи: его последующий перевод не переносит старую историю. Для событий файлов и задач это компания действующего пользователя, а не владельца доступного ему ресурса. Неидентифицированные попытки входа и публичные операции без пользователя не приписываются компании; они доступны только платформе.

## Фильтры

Одинаковы для списка и экспорта, объединяются через AND:

- `ip`: точный IPv4/IPv6 или сеть CIDR, например `192.0.2.10`, `192.0.2.0/24`, `2001:db8::/32`.
- `action`: точный стабильный код действия.
- `actor_id`: положительный ID пользователя.
- `outcome`: `success` или `failure`.
- `from`, `to`: RFC3339 с часовым поясом, нижняя граница включена, верхняя исключена.
- `before_id`: курсор следующей страницы.
- `snapshot_id`: верхняя граница ID из первой страницы, чтобы события с более новыми ID не попадали в текущий обход.
- `limit`: 1–100 для списка, по умолчанию 50. Экспорт использует собственный предел 10 000.

Неверный фильтр — `VALIDATION_ERROR` / 400. Порядок — `id DESC`. Пример:

```http
GET /api/v1/organizations/current/security-audit?ip=192.0.2.0%2F24&action=auth.login&outcome=failure&limit=50
Authorization: Bearer <token>
Accept-Language: kk
```

Ответ: `items`, `snapshot_id`, опциональный `next_before_id`. Для продолжения передавать оба `snapshot_id` и `before_id=next_before_id`. У события поля `id`, `created_at`, `organization_id`, `actor_id`, `action`, `outcome`, `ip`, `request_id`, `method`, `route`, `status`, `administration_audit_id`, `object_type`, `object_id`. При наличии UUID в параметре маршрута сохраняется идентификатор объекта; идентификаторы публичных ссылок исключаются. Для создания и batch поля объекта могут быть пустыми. IP, пользователь, компания и ссылка на административный аудит могут быть null. Для транзакционных административных записей HTTP status равен 0, method/route пустые: результат операции зафиксирован аудитом, а HTTP-ответ ещё не сформирован.

## События и коды действий

- `auth.login`: пароль, PIN, серверные callback/exchange/bootstrap/handoff потоки входа. Неуспешный callback с редиректом также имеет outcome=failure. Попытки входа не содержат введённый email, ИИН, пароль или PIN.
- `auth.logout`: выход и выход со всех устройств.
- `auth.password.change`: смена пароля.
- `access.denied`: HTTP 401/403 за исключением попыток входа; route указывает шаблон запрошенного API.
- `admin.<action>`: действия BAS-017, например `admin.module.update`, `admin.user.block.update`, `admin.storage.quota.update`. `administration_audit_id` связывает запись с безопасными before/after в прежнем журнале.
- `admin.request`: прочие запросы изменения административных настроек и неуспешные попытки; успешные BAS-017 изменения не дублируют транзакционный аудит.
- `audit.export`: запрос экспорта и его результат; событие создаётся после формирования ответа и не входит в собственный экспорт.
- `file.download`: скачивание Drive, версии файла или файла по публичной ссылке.
- Остальные действия файлов и задач формируются из безопасного шаблона маршрута: префикс `file` / `task`, статические части маршрута, затем `create` для POST, `update` для PUT/PATCH, `delete` для DELETE. Параметры `:id` / `:token` исключаются, дефисы заменяются `_`.

Примеры: загрузка Drive — `file.files.create`; изменение файла — `file.files.update`; удаление — `file.files.delete`; новая версия — `file.files.versions.create`; права — `file.permissions.create/update/delete`; публичная ссылка — `file.share.link.create/delete`; перенос — `file.items.move.create`; восстановление — `file.trash.restore.create`. Задачи: `task.tasks.create/update/delete`, `task.tasks.status.update`, `task.tasks.move.update`, `task.tasks.files.create/delete`, `task.tasks.comments.create`, `task.comments.update/delete`. Изменения досок и участников также фиксируются, например `task.boards.members.role.update`. Поиск, избранное и обычные успешные просмотры списков не записываются.

Для файлов и задач фиксируется завершение HTTP-операции, включая пакетные операции: одно событие на запрос. Outcome отражает HTTP-результат, а не подтверждение получения ответа клиентом. Это не подробная история всех отдельных объектов внутри batch. Существующая транзакционная история задач сохраняется. Фоновые операции без HTTP-контекста не получают выдуманный IP.

## Экспорт

`GET .../security-audit/export?format=csv` (по умолчанию) или `format=json`, с теми же фильтрами. CSV — UTF-8 с BOM, заголовками колонок и защитой от формул таблиц. JSON имеет структуру страницы. Оба ответа имеют Content-Disposition attachment и Cache-Control no-store.

Экспорт ограничен 10 000 записями. Если выборка больше, возвращается 409 без усечённого файла; сузить период/фильтры. Произвольные тела запросов, содержимое файлов и задач, заголовки Authorization/Cookie, токены ссылок, параметры URL и секреты в журнал/экспорт не попадают. Поле route содержит шаблон, а не фактический URL.

## IP за reverse proxy

`SECURITY_AUDIT_TRUSTED_PROXIES` — список CIDR доверенных непосредственных прокси через запятую. Например, для прокси на loopback: `127.0.0.1/32,::1/128`. Использовать реальные адреса инфраструктуры. Без настройки сохраняется IP TCP-соединения; клиентский X-Forwarded-For игнорируется. При настроенном прокси цепочка обходится справа до первого недоверенного узла. Некорректный CIDR останавливает запуск с ошибкой конфигурации. Не задавать весь интернет как доверенный прокси.

## Хранение и эксплуатация

UPDATE, DELETE и TRUNCATE журнала запрещены триггерами, удаления пользователей/компаний не удаляют историю. Это защита от обычных SQL-операций, а не от администратора БД, способного менять схему. Автоматическая очистка не включена. Down миграции удаляет новый журнал; перед откатом сохранить его отдельно.

Административная запись и зеркало атомарны: ошибка вставки откатывает административную операцию. HTTP-события входа, файлов и задач записываются после обработчика с отдельным таймаутом 3 секунды; ошибка записи попадает в серверный error-log, но не откатывает уже выполненную операцию. Для гарантированной доставки при недоступной БД нужен отдельный durable outbox; текущая реализация его не обещает. При эксплуатации контролировать `security audit persistence failed`.

## Проверки реализации

На Go 1.24.7 и отдельной PostgreSQL 16 выполнены `TestSecurityAuditIsolationFiltersAndImmutability`, `TestSecurityAuditHTTPExportAndAuthorization`, `TestSecurityClientIPTrustedProxies`, `TestSecurityAuditHTTPClassificationAndPrivacy`, проверки CSV и фильтров. Проверены IPv4/IPv6/CIDR, роли и изоляция, отказ изменения истории, откат зеркала с исходным аудитом, snapshot/cursor, CSV/JSON и предел 10 000.

Проверены все затронутые пакеты, release-upgrade миграции, service-suite, `go vet ./...` и сборка API. Из Windows-запуска исключены существующие тесты удаления открытых логов; MinIO и конвертеры документов требуют своих сервисов в CI. Данные реальных компаний и production-сервисы для тестирования не использовались.
