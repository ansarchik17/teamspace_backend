# Удаление компаний и сотрудников

Удаление заменяет блокировку в интерфейсе управления компанией. Это логическое удаление: связанные документы, переписка, начисления и аудит сохраняют ссылки, но записи исчезают из рабочих списков и теряют доступ. Восстановления через интерфейс нет. Slug компании остаётся занятым. ИИН, email и логин удалённого сотрудника сохраняются в закрытом неизменяемом архиве `retired_user_identities` и освобождаются для новой учётной записи. Старый user_id, Keycloak ID, имя и все ссылки документов, переписки и начислений остаются у удалённой записи. Повторное добавление создаёт новый user_id и новую SSO identity, без переноса прежней истории или прав.

- Суперадмин удаляет компанию целиком, включая её директора и сотрудников, либо отдельного сотрудника выбранной компании.
- Директор определяется по `organizations.owner_id`, а не названию должности; он удаляет только сотрудников своей текущей активной компании.
- Отдельно нельзя удалить себя, суперадмина или владельца компании. Для владельца сначала нужна передача компании. Компания с учётной записью суперадмина не удаляется.
- Права, текущее владение и принадлежность сотрудника повторно проверяются под блокировками в транзакции. Ошибка не оставляет частичного удаления или успешной записи аудита.

## API

- `DELETE /api/v1/platform/organizations/:organization_id` — только суперадмин, ответ 204.
- `DELETE /api/v1/platform/organizations/:organization_id/administration/users/:user_id` — только суперадмин, ответ 204.
- `DELETE /api/v1/organizations/current/administration/users/:user_id` — директор своей компании (либо суперадмин с текущей компанией), ответ 204. Компания из тела запроса не используется.
- Существующий `DELETE /api/v1/users/:user_id` сохраняет ответ 200 и использует ту же проверку и операцию удаления. Старые маршруты блокировки сохранены для совместимости клиентов.
- Защищённая учётная запись: 409 `ADMIN_DELETION_PROTECTED` с сообщением ru/kk. Чужой сотрудник недоступен; чужой platform scope для директора запрещён.

Компания получает терминальный `status=deleted`, её сотрудники — `deleted_at` и `is_active=false`. Управленческие связи очищаются, websocket-сессии закрываются после коммита. Проверка активности валидации токенов закрывает последующие HTTP-запросы. Аудит содержит `organization.delete` или `user.delete`. Списки компаний и статистика исключают удалённые компании.

Очередь `administrative_identity_deletions` записывается в той же транзакции. Встроенный API-воркер каждые 30 секунд удаляет соответствующие Keycloak identities; при ошибке задача остаётся в очереди с повтором не раньше минуты. Ответ 404 Keycloak считается успешной очисткой. Историческая локальная identity сохраняется, SSO не может её восстановить. Очередь не удаляет несвязанные или действующие учётные записи. Если создание сотрудника получило 409 от Keycloak, сервер синхронно обрабатывает только совпавшие архивные записи с подтверждённым удалением и точным SSO ID из очереди; затем один раз повторяет создание. Обычный конфликт с действующим сотрудником по-прежнему возвращает USER_IDENTITY_CONFLICT. При недоступности SSO новая карточка не создаётся, задача очистки сохраняется для повтора. Внешние сервисы с собственными независимыми сессиями требуют отдельной политики отзыва; этот API не удаляет их данные.

## Обновление

Перед новым backend применить `20261022130000_administrative_deletion.sql`, затем обновить frontend. Миграция добавляет очередь и защитные триггеры; не удаляет существующие компании или сотрудников. Новых настроек и зависимостей нет. Пользователь подтверждает удаление в диалоге с названием компании или сотрудника и описанием последствий.

Для повторного использования реквизитов нужна миграция `20261027000200_retired_user_identity_reuse.sql` перед обновлением backend. Она архивирует и освобождает реквизиты уже удалённых сотрудников, создаёт недостающие задачи очистки SSO и устанавливает триггер для будущих удалений. Архив не доступен через публичные API. Изменения frontend и переменных окружения не нужны. Автоматический откат запрещён: освобождённые реквизиты уже могут принадлежать новым карточкам.
