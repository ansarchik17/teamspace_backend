# Личные лимиты ИИ (22 октября 2026)

Все активные, неудалённые аккаунты, включая директора и суперадмина без организации, получают доступ по личным лимитам. Блокировка аккаунта и приостановка его компании сохраняют действие.

По умолчанию: **20 000 кредитов / 5 часов**, **100 000 кредитов / 7 дней**. Это стартовые значения для рабочих диалогов, а не гарантия количества сообщений. Отсутствующая запись или NULL означают default. Миграция `20261027000100_ai_personal_quota_defaults.sql` однократно заменяет ранее назначенные личные лимиты, включая нулевые, на эти значения. Для сотрудников меняются только записи текущей компании; освобождённые назначения прежних компаний сохраняются. Для аккаунтов без компании обновляются персональные настройки. До/после записываются в `ai_personal_quota_policy_resets`, ревизии изменённых настроек увеличиваются. Расход, резервы и сроки периодов не сбрасываются. После миграции новые ручные значения сохраняются. Ноль отключает соответствующее окно. GET не создаёт настройки или периоды.

`credits-v1` и исторические цены не меняются. Для GPT-OSS-120B входной токен = 1000 микрокредитов, выходной = 3000. Пример 78 входных + 150 выходных = 528000 микрокредитов (0,528 кредита). Reasoning внутри completion_tokens повторно не списывается. Полная история, инструкции, документы и дополнительные вызовы учитываются по подтверждённому usage. Неизвестный расход сохраняет резерв, а не считается нулём.

Для личных запросов `effectiveFiveHour=min(H,Q)`. Общий бюджет компании, его отсутствие, исчерпание, Hmax и сумма выданных квот не блокируют личные запросы. Организация остаётся историческим атрибутом журнала и областью доступа к данным. Фоновые вызовы payer_kind=service сохраняют существующий общий бюджет.

Оба личных периода начинаются с первого принятого запроса после окончания прошлого окна. Обычный отказ и GET /ai/limits не запускают отсчёт. Проценты отражают доступный остаток с резервами. Executor уменьшает допустимый выход модели под остаток; если даже вход не помещается, платный вызов не выполняется. Принятый последний запрос расходует остаток личной квоты отдельным списанием и сохраняет уведомление об исчерпании — [правила cutoff](ai-final-request-cutoff.md).

## Настройка

Директор своей компании и суперадмин используют прежние GET/PUT `/organizations/current/administration/ai-budget/users/:user_id` и `/platform/organizations/:organization_id/administration/ai-budget/users/:user_id`. Проверяются актуальные права в БД. Сотрудник и директор чужой компании получают отказ. `revision` защищает от потери изменений; `company_revision` остаётся обязательным в старом DTO для совместимости, но не ограничивает личную квоту. Бюджет компании для назначения не требуется. Новый H должен быть <= Q. Аудит и изменение атомарны.

Для аккаунтов без компании: GET/PUT `/api/v1/platform/ai/users/:user_id/quota`, только суперадмин. PUT принимает строковые `weekly_quota_microcredits`, `five_hour_limit_microcredits`, `revision`. Ответ содержит эти же строковые поля и числовой user_id; без override revision="0". Для сотрудника компании применяется прежний API организации. Before/after сохраняются в user_ai_personal_quota_audit.

Фронт настроек компании показывает личные квоты и новые рекомендации. Отдельная форма настройки аккаунта без компании пока не добавлена; для неё доступен новый API.

## Обновление

Нужны миграция `20261022100400_ai_personal_access_policy.sql`, backend и frontend. Новые переменные окружения не нужны. NULL organization_id разрешён только личным операциям; триггер проверяет принадлежность попытки/окна. Фиктивная организация не создаётся. Исторические цены, суммы и резервы не переписываются. Автоматический откат миграции запрещён для защиты новой финансовой истории.
