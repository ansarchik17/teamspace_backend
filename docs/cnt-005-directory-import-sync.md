# CNT-005 — Импорт и синхронизация сотрудников

В этой задаче импортируются профили справочника. Новые записи users имеют role=user,
keycloak_id=NULL, без локального пароля. Учётные записи/пароли/федерация для входа
настраиваются в существующем Keycloak/корпоративном SSO отдельно. Импорт не создаёт
пароли, не отправляет приглашения и не меняет роли/аватары/SSO ID существующих пользователей.
У существующего сотрудника login email и username сохраняются; входящие email становятся
рабочими контактами. Для связывания входа с импортированным профилем SSO должен отдавать
соответствующий email и корректную организацию; реальная SSO-приёмка не выполнена.

## CSV / Excel

POST `/api/v1/contacts/import?dry_run=true` (BearerAuth, multipart `file`).
Только активный владелец компании/глобальный администратор своей активной компании.
По умолчанию dry_run=true; dry_run=false применяет изменения. Поддерживаются UTF-8
CSV (BOM, запятая/точка с запятой) и XLSX с одним листом. Старые XLS/XLSM не поддерживаются.
Лимиты: 10 MiB, 5000 строк сотрудников; распакованный XLSX до 64 MiB. В Excel
сохраняйте external_id/phone как текст, чтобы не потерять ведущие нули/знак +. Excel формулы
не вычисляются, читаются сохранённые значения. Первая строка — заголовки.

Обязательные столбцы: username, email, first_name, last_name.
Дополнительные: external_id, position, department, manager_username, work_email,
phone, is_active. Неизвестные/повторные столбцы отклоняются (включая role/password).

```csv
external_id,username,email,first_name,last_name,position,department,manager_username,phone,is_active
employee-42,anna,anna@example.com,Анна,Иванова,Разработчик,Разработка,ansar,+77011234567,true
```

- external_id — стабильный ключ до 512 байт. Если не указан, используется username
  без учёта регистра. Для смены логина/email используйте постоянный external_id.
- username/имена обязательны, до 50 символов. Email — один корректный адрес до 254
  байт, нормализуется в нижний регистр. Телефон проверяется/нормализуется как CNT-002.
- department — имя ровно одного существующего активного подразделения своей компании,
  без учёта регистра. Неоднозначное/неизвестное имя — ошибка строки; подразделения
  сначала создаются через CNT-003. Пустое значение снимает назначение.
- manager_username — ровно один активный сотрудник своей компании либо строка того
  же импорта. Порядок строк не важен; циклы отклоняются. Пустое значение снимает руководителя.
- Пропущенный дополнительный столбец сохраняет существующее значение; пустая ячейка
  в присутствующем столбце очищает его. Пустой is_active сохраняет состояние существующего
  сотрудника (для нового — true). Допустимы true/false и варианты strconv.ParseBool.
- work_email, если столбец отсутствует, берётся из входящего email. Login email существующей
  записи не меняется. is_active=false скрывает профиль в Contacts; это не отзыв SSO-сессий.
  Владелец компании и глобальный администратор не могут быть деактивированы импортом.

Ответ 200: `{dry_run, applied, total, created, updated, issues:[{row,field,message}]}`.
Сначала проверяются все входящие строки, затем атомарно разрешаются записи/отделы/руководители.
При любой ошибке весь пакет откатывается, applied=false. created/updated — счётчики
обработанных/планируемых строк, при issues они не означают применённых изменений.
Dry-run выполняет тот же путь с откатом; последовательность IDs может получить пропуски.
Структурно неверный файл/параметр — 400, отсутствие прав — 403, нет активной компании — 404.
Бизнес-конфликты возвращаются в issues; клиент должен проверить applied и issues.

Повторы связываются по (компания, источник file/ldap, external_id). При первом импорте
существующая запись сопоставляется по username или email только внутри компании;
неоднозначность/зарезервированный чужой email отклоняются без раскрытия чужих данных.
Удалённые/переданные другой компании записи по старому ключу не восстанавливаются/не перехватываются.
Изменения своей компании сериализуются; повтор/параллельный импорт не создаёт копии.
Отсутствующие в файле/каталоге сотрудники не отключаются и не удаляются.

## LDAP / Active Directory

GET `/api/v1/contacts/directory` — настройки без пароля, revision, last_sync_at/count.
PUT `/api/v1/contacts/directory` — полная замена настроек, сохранение/ротация пароля:

```json
{
  "type": "ad",
  "url": "ldaps://ad.company.example:636",
  "base_dn": "DC=company,DC=example",
  "bind_dn": "svc-directory@company.example",
  "bind_password": "<provided securely>",
  "enabled": true,
  "attributes": {},
  "ca_cert_pem": ""
}
```

Поддерживаются type ldap/ad. URL ldaps или ldap с обязательным StartTLS; проверка
сертификата всегда включена, TLS >=1.2. Системные CA плюс необязательный корпоративный
CA PEM. Bind — read-only service account, simple bind поверх TLS. Пароль обязателен
при первом сохранении, при пропуске/null сохраняется прежний; пустая строка отклоняется.
Пароль зашифрован AES-256-GCM с привязкой к компании и никогда не возвращается/не логируется.
Один коннектор на компанию, выключение через enabled=false.

POST `/api/v1/contacts/directory/sync` с `{"dry_run":true}` — предпросмотр;
`{"dry_run":false}` — применение. Пустой объект означает предпросмотр. Полная выборка
страниц по 250 записей, максимум 5000 сотрудников; timeout запроса 2 минуты, соединения
10 секунд, LDAP-операции 15 секунд. Ошибки поиска, лимит сервера, referrals, неподдерживаемая
пагинация или неполный результат не применяют частичный снимок. Коннектор только читает LDAP.
Плановый запуск выполняется внешним scheduler через этот API с dry_run=false; встроенного
периодического worker нет. Перед применением повторно проверяются права и revision настроек.
Успешное применение обновляет last_sync_at/count и revision; ошибка/предпросмотр не обновляет их.
Revision отражает состояние коннектора, включая последний применённый снимок: одновременно
прочитанный старый снимок получает конфликт и требует повторного чтения.

Настройки attributes (поле профиля → LDAP attribute) по умолчанию:
external_id=entryUUID, username=uid, email=mail, first_name=givenName, last_name=sn,
position=title, department=department, phone=telephoneNumber, manager_dn=manager.
Для AD: external_id=objectGUID (стабильный hex сырых 16 байт), username=sAMAccountName,
account_control=userAccountControl. Бит ACCOUNTDISABLE отражается в локальном is_active.
Generic LDAP не меняет is_active существующих сотрудников. Пустые атрибуты должности/
отдела/телефона/руководителя очищают эти поля; обязательные атрибуты должны быть заполнены.
Email становится work_email; существующие данные входа сохраняются. Руководитель по DN
должен входить в тот же полный результат поиска, иначе пакет отклоняется. После первого
применения URL/base_dn/type/attribute external_id нельзя сменить, чтобы не перепривязать
профили к другому источнику. Filter и остальные mappings можно изменить.

## Развёртывание

Применить предыдущие миграции Contacts и `20261001160000_employee_directory.sql`.
Настроить CONTACTS_DIRECTORY_ENCRYPTION_KEY — base64 32 случайных байт; хранить в secrets,
ключ сохранять/резервировать (потеря ключа требует повторного ввода bind password).
CONTACTS_LDAP_ALLOWED_HOSTS — разрешённые точные URL authorities host[:port] через запятую,
например ad.company.example:636. По умолчанию LDAP-подключения запрещены. Секреты не должны
попадать в CSV/Excel, логи или контекст проекта. Настройки описаны в .env.example.
Фронтенд/production/рабочий каталог не менялись.

Проверки: go test ./...; Contacts CNT-001–005 на одноразовой PostgreSQL, миграции Up/Down,
CSV/XLSX, dry-run/повторы/параллельный импорт/полный rollback, иерархия/ACL/защита владельца,
шифрование/изоляция секрета, изменение конфигурации во время чтения, AD mapping.
LDAP-протокол проверен на тестовом сервере (LDAPS/StartTLS, пагинация, неполная выдача, недоверенный CA).
Реальная AD/LDAP и связка с корпоративным SSO требуют отдельной приёмки в окружении компании.
