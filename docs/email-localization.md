# BE-05: email-уведомления

Переводы email находятся в `internal/i18n/emails.json`, обе версии — `ru`
и `kk`. Общие серверные уведомления также используют шаблоны BE-04.
Язык выбирается из профиля адресата, а не из HTTP-запроса инициатора.
Пустой или неподдерживаемый язык даёт fallback на русский.

Покрытые шаблоны и пути отправки:

- Общие системные уведомления: тема, обращение, подсказка, кнопка,
  отметка времени и автоматическая подпись. Тело заново рендерится на
  языке адресата из серверного шаблона, без ограничения длины push.
- Календарь: обычные уведомления, приглашение, изменение и отмена встречи;
  подписи полей, значения по умолчанию и кнопки принятия, отклонения,
  предварительного согласия и открытия приложения. ICS и коды действий
  сохраняют прежний формат.
- Рассылки публикаций: тема, уровень важности, заголовок оповещения,
  кнопка и подпись. Каждое письмо формируется отдельно для получателя;
  язык загружается вместе с аудиторией рассылки.
- Пересылка входящих писем: серверная тема и оболочка используют профиль
  пользователя, найденного по целевому адресу. Тестовые письма тоже
  используют профиль целевого адресата. Адрес без профиля получает `ru`.

`NotificationEmailTemplateInput` и `CalendarInviteEmailInput` принимают
`Language`. Каждый производственный вызов передаёт язык получателя.
HTML содержит соответствующий атрибут `lang`, а HTML и plain-text части
содержат одинаковые переведённые элементы.

Имена, названия встреч, описания, пользовательские темы и контент не
переводятся. Пользовательские параметры в HTML автоматически экранируются;
форматированный контент публикаций проходит существующую HTML-очистку.
Поля `ActionText` и `FooterText`, если заданы, считаются уже готовым текстом;
для стандартных переводимых кнопок и подписей используются пустые значения.

Новые миграции не нужны: используется `users.language` из BE-01.
Тесты проверяют обе локали, fallback, варианты календаря, письма разным
адресатам через подменённый SMTP-транспорт, сохранность пользовательских
параметров, экранирование, наличие языка у всех вызовов шаблонов и наличие
двух версий каждой записи email-каталога.
