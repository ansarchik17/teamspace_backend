# Общий интерфейс выполнения платных вызовов

Задача 21. Точки входа: `domain.AIPaidCaller`, `domain.AIPaidCallParams`, `service.AIPaidCallerService.ExecutePaidCall` и generic-обёртка `service.ExecutePaidCallTyped`.

Механизм объединяет проверку серверного контекста, резервирование, проверку идемпотентности, фиксацию отправки, вызов провайдера, фиксацию фактического расхода и обработку ошибок в единый переиспользуемый цикл для всех ИИ-агентов, чатов и фоновых воркеров.

## Проверенная идентичность и контекст

`domain.AIPaidCaller` представляет подтверждённую сервером сущность, несущую финансовую ответственность за вызов:
- `OrganizationID uuid.UUID` — обязательный непустой идентификатор компании.
- `UserID *int64` — обязателен для пользовательских вызовов (`*UserID > 0`); `nil` исключительно для доверенных сервисных сценариев компании (`IsService=true`).

Передача проверенной идентичности осуществляется через `context.Context` с помощью функций `domain.WithAIPaidCaller` и `domain.AIPaidCallerFromContext`, либо явно через `domain.AIPaidCallParams.Caller` (при наличии обоих источников они обязаны строго совпадать, предотвращая подмену контекста).

### Защита от вызовов мимо учёта

**Ключевое правило:** вызов без необходимого проверенного контекста не проходит незаметно мимо учёта.
- Если в `context.Context` и параметрах отсутствует проверенная идентичность, возвращается `ErrAIPaidCallMissingContext`.
- Если идентификатор компании или пользователя невалиден (нулевой UUID, неположительный ID пользователя для личного вызова), возвращается `ErrAIPaidCallInvalidCaller`.
- Если контекст и параметры содержат несовпадающие данные, возвращается `ErrAIPaidCallContextMismatch`.
- Во всех этих случаях обращение к провайдеру (`dispatch`) **категорически блокируется** — счётчик обращений к провайдеру остаётся нулевым. Никакие запросы не уходят в сеть и не выполняются скрыто.

Нулевое значение `params.Caller` означает, что личность в параметрах не передана. Частично заполненное значение считается ошибкой, даже при корректной личности в контексте. Явно помещённая в контекст некорректная личность также отклоняется, включая нулевое значение; подстановка личности из параметров не выполняется.

## Жизненный цикл платного вызова

`AIPaidCallerService.ExecutePaidCall` реализует строгую последовательность:

1. **Проверка контекста:** вызов `params.ResolveCaller(ctx)` и валидация параметров `params.ToReserveRequest(caller)`.
2. **Резервирование и проверка идемпотентности:** вызов `reserveAIOperation`:
   - При повторе ранее принятой операции (`Created=false`) обращение к провайдеру не производится, возвращаются сохранённые данные попытки и списания.
   - При нехватке бюджета или квоты возвращается `AIReservationDenied` без отправки запроса.
3. **Guard отправки:** если контекст отменён до отправки, регистрируется отказ `AIFailureNotDispatched` (источник `local_dispatch_guard`) и вызов прерывается.
4. **Атомарная фиксация отправки:** `MarkSent` фиксирует переход `reserved` → `sent` перед выходом в сеть.
5. **Вызов провайдера:** вызывается `dispatch` с оригинальным контекстом. Функция возвращает прикладной ответ (например, результат генерации), подтверждение расхода `domain.AISettleRequest` и ошибку.
6. **Обработка ошибок:** при сбое вызова исход фиксируется через `recordAIDispatchFailure` в изолированном контексте БД (5 секунд), защищённом от отмены клиента:
   - При наличии подтверждённого usage фиксируется `confirmed_usage` (`AIFailureCharged`).
   - При таймауте, отмене или сетевом сбое без подтверждения — `unknown` (`AIFailureUnknown`).
7. **Фиксация расхода:** при успешном вызове выполняется `SettleSuccess` в изолированном контексте. Закрывается резерв, пересчитываются зеркальные счётчики и возвращается `AIPaidExecutionResult` с прикладным ответом `Response`, обновлённым резервом и фактом списания `Settlement`.

Для типизированных прикладных ответов доступен generic-хелпер:
```go
resp, reservation, settlement, err := service.ExecutePaidCallTyped[MyResponse](
    ctx, callerService, params,
    func(ctx context.Context, res domain.AIReservation) (MyResponse, domain.AISettleRequest, error) {
        // вызов конкретного провайдера
    },
)
```

Если провайдер уже вызван, результат может возвращаться вместе с ошибкой: сохраняются полученный ответ и идентификаторы операции/попытки. Это правило действует и для `ExecutePaidCallTyped`. При ошибке списания `Settlement` остаётся `nil`, а `Reservation` содержит последнее известное состояние до обработки ошибки, не подтверждая успешное списание. Ошибку необходимо обработать; повторно запускать генерацию для восстановления учёта нельзя.

## Проверки

В `internal/service/ai_paid_caller_test.go` и `internal/domain/ai_caller_test.go` проверены:
- Полная блокировка вызова при отсутствии контекста, нулевом UUID компании, отсутствии UserID у сотрудника и несовпадении контекста (провайдер не вызывается);
- Успешное выполнение пользовательского вызова с проведением резерва, `MarkSent`, вызова провайдера и списания;
- Успешный сервисный вызов от имени компании (`IsService=true`);
- Работа generic-хелпера `ExecutePaidCallTyped`;
- Идемпотентный повтор запроса без повторного обращения к провайдеру;
- Отмена контекста до отправки (`local_dispatch_guard`, `not_dispatched`);
- Ошибки провайдера с фиксацией `unknown` и `confirmed_usage`;
- Ошибка проведения списания и отказ по бюджетным лимитам.
