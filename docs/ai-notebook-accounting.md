# Учёт платных генераций Notebook: задача 24

Подключён маршрут исследования и подготовки материалов `POST /api/v1/notebook/chats/:id/ask` через `NotebookResearchService`. Общий `AIPaidCallerService` инициализирован в `cmd/api/main.go`; отсутствие зависимостей учёта закрывает платный путь с ошибкой `domain.ErrAIPaidCallMissingContext` (HTTP 403 `AI_CHAT_ACCESS`). Идентичность пользователя и компании определяется исключительно на сервере через аутентификацию и `UserRepository.GetByID`. Идентификаторы плательщика из клиентского тела игнорируются. Плательщиком всегда выступает проверенный пользователь компании (`domain.NewAIPaidUserCaller`), подмена на служебного плательщика (`IsService=true`) категорически запрещена.

## Список фактических вызовов Notebook

1. **Первичная генерация (исследования и подготовка материалов)**:
   - Эндпоинт: `POST /api/v1/notebook/chats/:id/ask`.
   - Форматы: `text`, `report`, `compare`, `table`, `presentation`, `cards`, `test`, `chart`, `mermaid`.
   - Режимы: `fast` (модель по умолчанию `openai/gpt-oss-120b`) и `thinking` (модели глубокого рассуждения: `Qwen/Qwen3.5-397B-A17B`, `moonshotai/Kimi-K2-Thinking`, `deepseek-ai/DeepSeek-V3.2`).
   - Исправления и доработки: если пользователь запрашивает сокращение/переписывание предыдущего ответа, `followupDraft` включает проверенный черновик из истории в промпт. Полный объём контекста (включая черновик и фрагменты документов) полностью входит в расчёт резерва.
   - Идентификатор шага: `notebook:<operationID>:1`.

2. **Fallback первичной генерации**:
   - При отказе выбранной модели (`callErr != nil` или пустой ответ) в режиме `thinking` автоматически выполняется переход на резервную модель `DefaultAlemModel` (`openai/gpt-oss-120b`).
   - Каждая попытка является отдельным фактическим вызовом: неуспешный первый вызов фиксируется в журнале с исходом `unknown` и сохраняет удержание (hold) для сверки; вторая попытка под `DefaultAlemModel` открывает собственный независимый резерв по её тарифной сетке.
   - Идентификатор шага: `notebook:<operationID>:2`.

3. **Проверка ответа (Верификация)**:
   - В режиме `thinking` после успешного получения черновика автоматически запускается шаг верификации через `verifyNotebookAnswer`.
   - На вход модели передаются: исходный вопрос, системные правила проверки, недоверенный черновик, полный контекст источников и объективные сравнения PDF (`notebookTextComparison`).
   - Идентификатор шага: `notebook:<operationID>:<step>` (шаг 2 при успехе с первой попытки, либо шаг 3 при предварительном fallback).
   - Списание каждого выполненного вызова завершается **до** перехода к следующему. Ошибка верификации (таймаут, отмена или сетевой сбой) не отменяет и не откатывает списание за первичную генерацию черновика.

4. **Анализ частей больших документов (deep, map-reduce)**:
   - Если суммарный текст выбранных источников больше 150 000 символов, перед первичной генерацией каждая анализируемая часть (до 8) отправляется отдельным вызовом `DefaultAlemModel` (`MaxTokens` 1500), см. `docs/notebook-deep-research.md`.
   - У каждой части собственная цепочка шагов и детерминированный ключ `notebook:<operationID>:map:<source>:<chunk>:<step>`, не зависящий от порядка завершения параллельных вызовов. Повтор после занятого слота лимитера (`ErrAIConcurrencyLimitExceeded`, резерв не создавался) идёт следующим шагом той же части.
   - Отказ резерва, лимит частоты или ошибка учёта на любой части прерывает операцию; уже проведённые списания других частей сохраняются. Сбой провайдера на части не прерывает операцию: ответ получает статус `partial`.
   - Шаги первичной генерации, fallback и проверки после этого нумеруются как прежде: `notebook:<operationID>:1..3`.

5. **Неоплачиваемые локальные операции и внешние сервисы**:
   - `POST /chats/:id/context` и `GET /chats/:id/sources/:doc_id` — локальное чтение файлов, извлечение текста и цитат, без обращения к LLM (0 кредитов).
   - `POST /chats/:id/sync` (`SyncMessages`) и сохранение истории через `persist: true` в `/ask` — запись сообщений в БД без вызовов LLM. Ошибка сохранения не отменяет списание.
   - `GET /studio/presets` — статический каталог карточек Студии.
   - `POST /slides/2slides/generate` — сторонний генератор презентаций 2slides (внешний HTTP API, не расходует токены NITEC).
   - Пост-обработка (`repairNotebookMermaid`, `preserveNotebookIdentifiers`, `correctNotebookRelativeArithmetic`, `linkNotebookCitations`) выполняется детерминированно в памяти сервера без вызовов моделей.

## Модель стабильных идентификаторов

Цепочка вызовов связывается единым стабильным идентификатором пользовательской операции:
- Клиент может передавать `operation_id` в JSON-теле `NotebookResearchRequest`, либо в HTTP-заголовках `X-Operation-ID` / `Idempotency-Key`.
- При отсутствии идентификатора сервер генерирует стабильный UUID для всей цепочки.
- Шаги цепочки нумеруются строго последовательно: `notebook:<operationID>:1`, `notebook:<operationID>:2`, `notebook:<operationID>:3`.
- При повторной доставке операции (`replay` с тем же `OperationID` и шагом) механизм идемпотентности видит `!reservation.Created` и возвращает `domain.ErrAIReservationConflict`. Повторное обращение к провайдеру блокируется.

## Независимость списаний от сохранения истории

- Расход каждого шага списывается через `SettleSuccess` непосредственно после получения подтверждённого `usage` от провайдера, **до** возврата ответа клиенту.
- Ошибка сохранения сообщения в историю (в `SyncMessages` или на клиенте) не отменяет проведённый платёж. Повторная генерация ради восстановления истории чата не производится.
- При удалении блокнота или истории сообщений бухгалтерские записи в `ai_usage_operations` и `ai_usage_attempts` сохраняются в полном объёме.

## Фоновые продолжения и плательщик

- Контекст `paidCtx` содержит проверенную идентичность `domain.AIPaidCaller`.
- При передаче в фоновые продолжения или горутины используется `context.WithoutCancel(paidCtx)` с сохранением данных пользователя и компании.
- Подмена плательщика на сервисного запрещена.
- Фоновые задачи `POST /api/v1/notebook/chats/:id/ask/jobs` проверяют плательщика при создании и выполняют `Ask` под `context.WithoutCancel(paidCtx)` этого запроса; ключи шагов те же, что у синхронного `/ask`. Отмена задачи не откатывает уже проведённые списания. См. [notebook-deep-research.md](notebook-deep-research.md#асинхронный-режим-задачи).

## Обработка ошибок в API

- Отказ по балансу или лимитам квот (`AIReservationDenied`) транслируется в HTTP 429 с кодом `AI_CREDIT_LIMIT` (или 403 `AI_CHAT_ACCESS` при блокировке компании/пользователя).
- Отсутствие контекста плательщика, неактивный статус или несовпадение компании транслируется в HTTP 403 с кодом `AI_CHAT_ACCESS`.
- Внутренние диагностические данные, секреты и сырые ответы провайдера клиенту не возвращаются.

## Проверки

1. **Unit-тесты (`internal/service/notebook_accounting_test.go`)**:
   - Отсутствие проверенного плательщика (не настроен сервис, неактивный аккаунт, отсутствие компании, чужой контекст компании); блокировка обращений к провайдеру;
   - Отказ по квоте до вызова провайдера (`AIReservationDenied`);
   - Цепочка из нескольких вызовов с последним неуспешным: первичная генерация остаётся оплаченной (`settled`), сбой верификации фиксируется как `unknown`, проверка суммы списаний и удержаний;
   - Цепочка с fallback модели и верификацией: 3 вызова к провайдеру с раздельными ключами и попытками;
   - Защита от повторной генерации при повторной доставке операции (`ErrAIReservationConflict`, 0 вызовов к провайдеру);
   - Сбой сохранения истории после успешной генерации: вызов остаётся оплаченным.
2. **Тесты обработчика (`internal/handler/notebook_chat_error_test.go`)**:

   - Сокрытие внутренних деталей ошибок и секретов;
   - Извлечение стабильного `operation_id` из заголовков `X-Operation-ID` и `Idempotency-Key`.
3. **Интеграционные тесты (`internal/service/notebook_accounting_integration_test.go`)**:
