# DOC-004 — совместное редактирование и участники

Транспорт правок, курсоры/выделения соавторов и встроенный список участников
предоставляет ONLYOFFICE DocumentServer. Бэкенд использует общий document key
из DOC-003 и передаёт `coEditing: {mode: "fast", change: false}`: пользователи
одного файла присоединяются к одной сессии, переключение в strict-режим скрыто.
Тип визуального выделения зависит от редактора документа, таблицы или презентации.
Отдельный протокол передачи координат курсоров в API приложения не добавлен.

## Имена и аватары

Вместо `User <id>` конфигурация содержит имя и фамилию из профиля, затем username
или «Пользователь <id>» как резерв. ID пользователя стабилен для всех вкладок.
`editorConfig.user.image` получает URL аватара; если URL отсутствует или имеет
недопустимую схему, используется SVG-аватар с инициалами (data URL).

HTML-страница редактора обрабатывает `onRequestUsers` с `c=info`, получает
разрешённые профили у бэкенда и передаёт их в `DocsAPI.setUsers`. Запросы разбиваются
на группы до 100 ID. API возвращает только ID, имя и изображение, без email.
Профиль выдаётся, только если запрашивающий и целевой пользователь имеют доступ
к этому файлу. Удалённые пользователи и пользователи с отозванными правами
исключаются. Публичный анонимный office-preview не получает доступ к профилям.

URL фотографий должен открываться браузером DocumentServer без Bearer-заголовка;
для HTTPS-развёртывания следует использовать HTTPS-адреса. Интеграция не скачивает
произвольные avatar URL на бэкенде. Для `user.image`/`setUsers(c=info)` необходим
ONLYOFFICE Docs 8.0 или новее и редакция/лицензия с требуемой совместной работой.

## Активные редакторы

`GET /api/v1/docs/files/{id}/participants` (Bearer) возвращает массив:

```json
[{"id":"3","name":"Ансар Келес","image":"https://.../avatar.png","last_seen_at":"2026-09-29T10:00:00Z"}]
```

HTML регистрирует вкладку после `onDocumentReady`, отправляет heartbeat каждые
30 секунд и `leave` через sendBeacon при pagehide. Нет heartbeat 90 секунд —
вкладка больше не считается активной. Несколько вкладок одного пользователя
дают одного участника; закрытие одной не убирает оставшиеся. Просматривающие
пользователи в список **редакторов** не включаются. Права Editor проверяются на
каждом heartbeat и при чтении списка. Просмотр списка доступен Viewer и выше.

Нативный список и курсоры обновляются самим DocumentServer в реальном времени.
API приложения даёт снимок по heartbeat; это не поток курсоров и не WebSocket.
При потере сети или сильном ограничении фоновых таймеров браузером участник
исчезает по TTL и возвращается после следующего heartbeat. Последнее время
активности доступно клиенту в `last_seen_at`.

Смена ключа (финальное сохранение или внешняя версия Drive) исключает старые
сессии из списка. Force-save сохраняет сессию. Истёкшие записи удаляются при
следующем heartbeat; планировщик для корректного чтения списка не нужен.

## Внутренние маршруты страницы редактора

- `GET /api/v1/drive/onlyoffice/collaboration?file_id=...&token=...&ids=1,3` — профили
  для ONLYOFFICE, максимум 100 ID в запросе.
- `POST` на тот же путь, JSON `{"action":"heartbeat"}` или `{"action":"leave"}` —
  регистрация/удаление одной вкладки; ответ 204.

Оба маршрута требуют отдельный подписанный токен `onlyoffice_collaboration`.
Он привязан к file_id, user_id, document key, режиму и случайному session_id,
выдаётся HTML-странице на 24 часа. Он не разрешает скачивание, сохранение документа
или открытие editor-link и не взаимозаменяем с соответствующими токенами.
Для GET/heartbeat повторно проверяются права и активный ключ. Для leave удаляется
только запись пользователя и вкладки из токена, даже после отзыва доступа.
Ответы не кэшируются. Не записывать подписанные URL в аналитику/журналы запросов.

При 401/403/404/409 страница останавливает heartbeat и уведомляет родительскую
страницу сообщением `drive-office-session-ended` на тот же origin. Управление
правами и отключение редактирования внутри DocumentServer остаются частью его
сессии; бэкенд в любом случае повторно проверяет права при сохранении (DOC-003).

## Развёртывание и проверка

Применить `20260929160000_office_presence.sql` после миграций DOC-003, затем
обновить API. Дополнительных env-переменных нет; фронтенд приложения не менялся.
Изменена только HTML-страница редактора, которую уже отдаёт бэкенд.

`go test ./...` и интеграционные `TestOfficeCollaborationIntegration` с одноразовой
PostgreSQL проверяют профили и fallback-аватары, разделение токенов, роли,
несколько вкладок, leave/TTL, отзыв прав, force-save и смену ключа. HTML-тест
проверяет подключение onRequestUsers/setUsers и heartbeat.

Ручная приёмка: открыть один DOCX/XLSX/PPTX под двумя Editor-пользователями,
проверить взаимные курсоры/выделения, имена и фотографии; открыть третью вкладку
того же пользователя, закрыть одну и проверить список; отключить сеть и проверить
исчезновение после TTL. Такая проверка с настоящим DocumentServer пока не выполнена.

Документация протокола: [аватары](https://api.onlyoffice.com/docs/docs-api/get-started/how-it-works/setting-avatars/),
[метод setUsers](https://api.onlyoffice.com/docs/docs-api/usage-api/methods/),
[настройки редактора](https://api.onlyoffice.com/docs/docs-api/usage-api/config/editor/).
