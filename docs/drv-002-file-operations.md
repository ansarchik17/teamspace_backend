# DRV-002 — файловые операции

Существующие одиночные маршруты сохранены: `POST /api/v1/drive/items/copy`, `/items/move`, `PUT /folders/{id}`, `PUT /files/{id}`. Переименование принимает `name`. Перемещение в корень выполняется через `/items/move` с `target_parent_id: null`; у PUT отсутствующий/null parent сохраняет текущее расположение.

## Пакетные действия

`POST /api/v1/drive/items/batch`, Bearer JWT, Content-Type application/json:

```json
{
  "action": "move",
  "target_parent_id": "UUID папки назначения",
  "items": [
    {"resource_type": "file", "resource_id": "UUID файла"},
    {"resource_type": "folder", "resource_id": "UUID папки"}
  ]
}
```

Действия: `move`, `copy`, `rename`, `delete`. Для rename каждый элемент содержит `name`; для рекурсивного удаления папки — `recursive: true`. Не передавать target_parent_id для rename/delete. Для copy/move null или отсутствие target_parent_id означает корень. Владелец перемещаемого ресурса сохраняется; у копии владелец — текущий пользователь.

От 1 до 100 элементов. Некорректная структура, неизвестное действие/тип, нулевой UUID, повтор ресурса или некорректное имя отклоняют весь запрос с 400 до начала работы. Имя после trim: 1–255 символов, без разделителей пути, NUL, CR/LF и значений `.`/`..`.

Ответ 200, если все элементы обработаны; 207, если есть ошибки:

```json
{
  "succeeded": 1,
  "failed": 1,
  "results": [
    {"resource_type":"file","resource_id":"UUID","status":200,"result":{"name":"Отчёт.txt"}},
    {"resource_type":"file","resource_id":"UUID","status":403,"error":"no access to file"}
  ]
}
```

Элементы обрабатываются по порядку и коммитятся независимо. Пакет не является общей транзакцией: повторять следует только неудачные элементы, особенно при copy. Ответ result у copy/move — объект нового/перемещённого ресурса; у rename — сохранённое имя; у delete — существующий объект результата удаления, включая возможный запрос согласования. `succeeded` означает успешную обработку, а не обязательно немедленное удаление: фронтенд должен учитывать result.status. Пересекающиеся selections (папка и её потомок) также обрабатываются по порядку и могут давать последующую 404 после удаления родителя.

## Целостность и доступ

- Для каждого элемента используются проверки прав одиночных операций. Копирование папки требует чтения самой папки, а не только доступа к одному файлу внутри.
- Запрещено переносить/копировать папку внутрь себя или потомка. PUT папки тоже проверяет дерево. Транзакционная блокировка изменений родителей защищает от конкурентных A→B/B→A перемещений.
- Рекурсивное копирование использует согласованный снимок PostgreSQL и одну транзакцию: ошибка дочернего файла/версии откатывает всё дерево копии. Ошибки чтения списков не игнорируются.
- Копия получает новые ID, владельца, версию 1 и независимый ключ OnlyOffice; исходные ACL и публичные ссылки не копируются. Физические байты текущей версии разделяются по неизменяемому object_name, дальнейшая запись версии создаёт новый объект.
- Копирование папки в расположение с одноимённой папкой возвращает 409. Файлы сохраняют существующую политику: одинаковые имена допустимы, ресурс определяется UUID.
- Переименование сохраняет trimmed-имя. Копирование файла возвращает download_url.

## Проверки

Интеграционные тесты PostgreSQL/MinIO (описание запуска в DRV-001) дополнены копированием вложенного дерева и сравнением байтов, независимыми ключами, конфликтом имён, ограничением доступа к родительской папке, частичным успехом пакета, перемещением в корень, rename/copy/delete, запретом Viewer, повторными UUID, откатом дерева при ошибке file_versions и двумя конкурентными противоположными перемещениями. Это функциональные проверки, не нагрузочный тест.
