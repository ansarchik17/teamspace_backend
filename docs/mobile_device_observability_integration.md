# Интеграция наблюдаемости устройств (Mobile)

Данный документ описывает протокол интеграции со стороны мобильного клиента (iOS / Android) для отправки информации об устройствах в рамках прохождения аудита ГТС (Государственная Техническая Служба).

В соответствии с требованиями ГТС, собирается и отправляется только минимальный набор системных данных. Отправка геопозиции, IP-адресов, User-Agent, марки и модели устройства **отключена** на стороне сервера из соображений конфиденциальности.

---

## Общий рабочий процесс (Flow)

Для корректной работы мониторинга мобильный клиент должен выполнять одно действие:

1. **Регистрация метаданных устройства (`POST /api/v1/client/devices/metadata`)**
   Выполняется **один раз** при успешной авторизации пользователя (логин) или при первом холодном запуске приложения (если сессия уже сохранена).

---

## Авторизация
Запрос требует авторизационный заголовок с Bearer токеном:
```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

---

## Спецификация API

### Регистрация метаданных устройства
* **Метод**: `POST`
* **Эндпоинт**: `/api/v1/client/devices/metadata`
* **Описание**: Регистрирует текущее устройство и его минимальные характеристики (только разрешенные для ГТС).

#### Тело запроса (JSON):
| Поле | Тип | Обязательное | Описание | Пример |
| :--- | :--- | :--- | :--- | :--- |
| `device_id` | `String` | **Да** | Уникальный и постоянный UUID установки приложения | `"3f8c5b9e-1d2a-4c8e-8b9a-7f6e5d4c3b2a"` |
| `platform` | `String` | **Да** | Платформа мобильного клиента в нижнем регистре: `"ios"` или `"android"` | `"ios"` |
| `device_type` | `String` | **Да** | Тип устройства в нижнем регистре: `"mobile"` или `"tablet"` | `"mobile"` |
| `os_version` | `String` | Нет | Версия операционной системы устройства | `"18.5"` |
| `app_version` | `String` | Нет | Версия установленного приложения клиента | `"1.1.95"` |
| `build_number` | `String` | Нет | Номер сборки приложения | `"195"` |

#### Пример JSON запроса:
```json
{
  "device_id": "3f8c5b9e-1d2a-4c8e-8b9a-7f6e5d4c3b2a",
  "platform": "ios",
  "device_type": "mobile",
  "os_version": "18.5",
  "app_version": "1.1.95",
  "build_number": "195"
}
```

#### Пример успешного ответа (`200 OK`):
```json
{
  "message": "device metadata saved successfully"
}
```

#### Пример ответа при ошибке валидации (`422 Unprocessable Entity`):
```json
{
  "error": "Validation error",
  "details": "invalid request body"
}
```

#### Пример ответа при отсутствии авторизации (`401 Unauthorized`):
```json
{
  "error": "Unauthorized",
  "details": "Missing authentication token"
}
```

## Важные примечания для разработки

1. **Консистентность `device_id`**:
   `device_id` должен быть постоянным в рамках одного и того же установленного приложения. 
   * **iOS**: Используйте `identifierForVendor` (IDFV), сохраняя его в Keychain для предотвращения сброса при удалении приложения, либо сохраняемый локально UUID.
   * **Android**: Используйте локально сгенерированный UUID, сохраненный в EncryptedSharedPreferences.
   * *Не используйте одноразовые или случайные UUID при каждом старте.*

2. **Момент вызова**:
   Запрос отправляется один раз за сессию:
   * Сразу после успешного ввода логина/пароля/ПИН-кода.
   * При холодном старте приложения, если токен авторизации всё ещё валиден.
   * *Нет необходимости повторно вызывать API при обычных действиях или переходах между экранами.*
