# Чтение квот сотрудников: задача 12

Добавлены внутренние доменные модели AIEmployeeQuotaPage/AIEmployeeQuota/AIQuotaWindow, метод `OrganizationRepository.AdministrationAIUsers` и делегирование из OrganizationService. HTTP endpoint и JSON DTO пока не подключаются — задача 14. Существующие API сотрудников и дисковых квот не изменены.

## Права и пагинация

actor/org обрабатываются существующим accessScope внутри Repeatable Read / Read Only транзакции. Директор читает только свою активную компанию, администратор платформы — явно выбранную. Обычный сотрудник не получает административный список. Count и items используют один предикат и один снимок БД.

Фильтр — существующий AdministrationUserFilter. Limit обязателен в диапазоне 1–100, offset 0–2147483647. Значения по умолчанию 25/0 задаст будущий HTTP handler; repository не подменяет некорректный limit=0 значением по умолчанию. Query обрезается по краям, максимум 255 Unicode-символов после trim; некорректный UTF-8 отвергается. Поиск использует существующий подход администрации `strpos(lower(...),lower(query))` по ФИО/username/email. `%` и `_` не являются wildcard. Unicode case folding зависит от локали PostgreSQL, как в существующем списке сотрудников; новая collation не вводится.

Порядок userID ASC. Offset за концом возвращает непустой total и пустой items, не ошибку. Current company, deleted_at IS NULL: директор, заблокированные и неактивные включены; переведённые и удалённые исключены. IsBlocked определяется существующей таблицей organization_user_blocks. Отдельные запросы страниц не являются единым зафиксированным снимком списка.

## Настройки и расход

Возвращаются ФИО, username/email, состояния сотрудника, configured, revision назначения, Q/H и эффективный H=min(H,Q,Hmax). Без назначения Q/H=null, configured=false. Ранее освобождённая строка сохраняет свою revision, не превращается в новую запись с версией 0. Компания без настроенного бюджета даёт company_revision=0 и ненастроенный эффективный пятичасовой лимит.

Page содержит server_time, company_revision и вычисленные недельные границы/сохранённый periodID. User item содержит оба окна с лимитом, used/reserved/carried, available, процентом и состоянием unconfigured/disabled/active/exhausted. Представление микрокредитов и revision строками будет выполнено отдельным HTTP DTO. Отсутствующий материализованный период представлен внутренним PeriodID=nil, как в чтении бюджета задачи 10.

Недельный used — детализация текущей недели только выбранной компании. Пятичасовой used — текущий период стабильного userID, включая использование до перевода. Активные удержания берутся из журнала резервов без повторного сложения со счётчиками periods. Для недельного окна фильтруется исходная компания, для пятичасового — пользователь независимо от компании. Служебные операции исключены. Закрытые резервы не учитываются; незавершённые старые включаются как carried. Carried уже входит в reserved.

Committed=max(Q,weekly.used+weekly.reserved) с проверкой переполнения. Available ограничивается снизу нулём, процент округляется вниз и считается без float/переполнения. Положительный остаток меньше 1% отличается от exhausted состоянием active. Нулевой лимит — disabled, процент отсутствует; без настройки available/процент отсутствуют. Состояние окна описывает квоту, а не отменяет блокировку аккаунта/компании.

Только выбранная страница обрабатывается одним пакетным запросом расхода. Нет отдельных запросов на каждого сотрудника. Личные границы вычисляются общей domain.AIPeriodAt с единым server_time и передаются в SQL как типизированные значения. Чтение не открывает якоря/периоды, не сбрасывает расход и не меняет revision. Сведения о прежних компаниях и их операциях не возвращаются, только общий пятичасовой счётчик.

## Проверки

TestAdministrationAIUsers на отдельном временном PostgreSQL 16: без настройки, обычный сотрудник/чужая компания, platform scope, диапазоны пагинации, три последовательные страницы, offset за концом, literal `%_`, поиск по ФИО/email, исключение удалённых/переведённых, заблокированный сотрудник с назначением, текущий/старый расход и резервы разных компаний, новое окно после простоя без создания строк.

Регрессионные TestAdministrationAIBudget и TestSetAdministrationAIBudget также прошли. Fixture использует существующие административные таблицы и реальные миграции ИИ 05–07. Полный production-набор миграций и HTTP API не проверяются. Временный сервер после проверки остановлен. Unit-тест TestAIQuotaWindowPresentation проверяет отображаемые состояния, малый остаток и процент на границе int64.

Новых миграций, зависимостей или серверных настроек нет; требуются таблицы ИИ 05–07 и существующая миграция блокировок сотрудников. Фронтенд не меняется. Commit, push и развёртывание не выполняются.
