# Статус задачи и колонка

`PUT /api/v1/kanban/tasks/{id}/status` принимает `{"status":"DONE"}` (также канонический русский статус `ГОТОВО`). Ключ сравнивается с колонками этой доски без учёта регистра и пробелов по краям. Статусы TODO, IN_PROGRESS, TEST, DONE нормализуются в русские значения карточки. Ключ пользовательской колонки сохраняется как статус вместо прежнего молчаливого TODO.

Метод использует путь drag-and-drop: колонка, статус и запись аудита сохраняются одной транзакцией, после успеха участникам отправляется `kanban_task_moved`. Ответ — обновлённая карточка. Viewer получает 403; неизвестный/пустой статус или неоднозначный ключ колонок — 400. При одинаковых ключах колонок использовать перемещение с точным ID колонки.

Изменение статуса через общий PUT карточки также отправляет событие перемещения при смене колонки. Просрочка не является статусом по умолчанию: фоновый обработчик отправляет `kanban_task_overdue` только для незавершённой задачи с истёкшим due_at. Завершение исключает задачу из новых напоминаний; открытие заново задачи с прошлым сроком делает её просроченной. Уже сохранённые уведомления не удаляются, а отправленное до завершения уведомление не отзывается.

Существующие карточки массово не изменяются: следующий корректный запрос статуса синхронизирует колонку. Для проверки исторических расхождений на сервере нужны адрес API и доступ к нужной доске.

## Перемещение и «Мои задачи»

Для drag-and-drop: `PUT /api/v1/kanban/tasks/{id}/move` с `{"to_column_id":"UUID"}`. Общий `PUT /api/v1/kanban/tasks/{id}` теперь также принимает `{"column_id":"UUID"}`; ранее это поле молча игнорировалось. Колонка, статус, остальные поля карточки и их аудит сохраняются одной транзакцией. После успеха смена колонки отправляет `kanban_task_moved`. Передача противоречащих друг другу `column_id` и `status` возвращает 400, как и колонка другой доски.

`GET /api/v1/kanban/tasks/my-by-status` группирует назначения по ключу реальной колонки: TODO, IN_PROGRESS, TEST. DONE и пользовательские ключи в этот существующий ответ не входят. Разные ID колонок с одинаковым ключом TODO попадают в одну группу todo. Для диагностики нужны запрос переноса и список колонок с id/name/key, а не только ответ группировки.

Переименование колонки без `key` сохраняет её ключ. Явная смена `key` синхронно обновляет статусы её активных задач и пишет аудит в одной транзакции; участники получают `kanban_column_updated`. Уже существующие ключи колонок автоматически по названиям не исправляются.

Входящее WS-событие `kanban_task_moved` уведомляет об уже сохранённом перемещении: сначала выполнить REST-запрос. Само событие не заменяет сохранение задачи.
