# BAS-017 BE-03: журнал административных изменений

Перед запуском применить `20261012000100_company_administration_audit.sql`.
Миграция создаёт общий журнал `organization_admin_audit` и индексы пагинации.
Существующий журнал прав `organization_access_audit` сохраняется для совместимости.
История до применения новой миграции в общий журнал не переносится.

## API для фронта

| Endpoint GET | Доступ |
| --- | --- |
| `/api/v1/organizations/current/administration/audit` | Активный директор своей компании или администратор платформы в своей текущей компании |
| `/api/v1/platform/organizations/:organization_id/administration/audit` | Только активный администратор платформы, выбранная компания |
| `/api/v1/platform/administration/audit` | Только активный администратор платформы, все компании |

Требуется Bearer JWT. Компания директора определяется сервером. Сотрудник и
предыдущий директор после смены владельца получают `FORBIDDEN` / HTTP 403.
Директор приостановленной компании не получает журнал через текущую компанию;
администратор платформы может просматривать её историю через platform API.
Ответы имеют `Cache-Control: no-store`.

Query: `limit` (1–100, по умолчанию 50), `before_id` (неотрицательный int64).
Неверная пагинация возвращает `VALIDATION_ERROR` / 400. Записи отсортированы по
`id DESC`. Для следующей страницы передавать полученный `next_before_id`.

```json
{
  "items": [{
    "id": 12,
    "organization_id": "00000000-0000-0000-0000-000000000001",
    "actor_id": 1,
    "action": "organization.owner.assign",
    "object_type": "organization",
    "object_id": "00000000-0000-0000-0000-000000000001",
    "before": {"owner_id": 10, "name": "Компания", "slug": "company", "status": "active"},
    "after": {"owner_id": 20, "name": "Компания", "slug": "company", "status": "active"},
    "created_at": "2026-10-12T10:00:00Z"
  }],
  "next_before_id": 12
}
```

## События и гарантии

Стабильные действия: `organization.create`, `organization.update`,
`organization.owner.assign`, `unit.create`, `unit.update`, `unit.archive`,
`user.assignment`, `growy.roles.update`, `access.position`, `access.delete`,
`access.policy`, `access.application`, `access.member`, `access.unassign`,
`access.link`, `identity_provider.create`, `identity_provider.update`,
`identity_provider.delete`.

`before` и `after` — сохранённые состояния выбранных безопасных полей БД.
Для создания `before` равен null; для удаления `after` равен null. Архивирование
подразделения отражается флагом `archived`. Обновление статуса компании находится
в `organization.update`. Идентификаторы действий не зависят от языка; подписи
действий локализуются фронтом. Пользовательские названия не переводятся сервером.

Запись выполняется в той же транзакции, что и изменение Workspace. Сбой аудита
откатывает изменение. Неуспешные операции в журнал успешных изменений не попадают.
Права и компания повторно проверяются под блокировкой для изменения структуры.

Пароли, токены, параметры интеграций, диагностические ошибки и полные записи
пользователей не сохраняются. У провайдера входа фиксируются только тип, alias,
название, enabled, secret_set, status и время обновления; значение секрета не
сохраняется. Изменение настроек отражается событием без содержимого настроек.
Внешние вызовы Keycloak не входят в транзакцию PostgreSQL: журнал подтверждает
локальное сохранение настроек, а не атомарность изменения во внешней системе.

Общий механизм будет использоваться для квот и других операций следующих
задач BAS-017. API записи/редактирования/удаления истории отсутствуют.
