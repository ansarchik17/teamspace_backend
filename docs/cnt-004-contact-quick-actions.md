# CNT-004 — Быстрые действия из карточки сотрудника

## Получение действий

`GET /api/v1/contacts/{user_id}` теперь включает `actions`. Можно обновить только
данные действий через `GET /api/v1/contacts/{user_id}/actions`. Оба API требуют
BearerAuth, активную компанию и активного неудалённого сотрудника той же компании;
чужой/неизвестный/неактивный/удалённый сотрудник — 404. Неверный user_id — 400.
Чтение использует согласованный read-only снимок карточки CNT-002 и не создаёт
чат/событие и не отправляет письмо. Оно предназначено для открытия соответствующего
экрана после нажатия пользователем.

Пример ответа actions:

```json
{
  "chat": {
    "label": "Написать сообщение",
    "enabled": true,
    "method": "POST",
    "endpoint": "/api/v1/conversations",
    "peer_id": 42
  },
  "email": {
    "label": "Отправить email",
    "enabled": true,
    "address": "employee@example.com",
    "mailto_url": "mailto:employee@example.com"
  },
  "meeting": {
    "label": "Встреча",
    "enabled": true,
    "method": "POST",
    "endpoint": "/api/v1/calendar/events",
    "title": "Встреча: Анна Иванова",
    "attendee_ids": [42],
    "availability_endpoint": "/api/v1/calendar/events/check-availability",
    "suggest_times_endpoint": "/api/v1/calendar/events/suggest-times"
  }
}
```

Все действия имеют label и enabled. Если enabled=false, disabled_reason содержит
стабильный код, параметры запуска отсутствуют (attendee_ids у встречи — []).
Для собственной карточки chat/meeting отключены с `self_contact`. Письмо себе
разрешено, если доступен корректный email.

## Подключение интерфейса

1. «Написать сообщение»: отправить POST в chat.endpoint с JSON
   `{"peer_id": actions.chat.peer_id}`; существующий Conversations API возвращает
   личный чат или создаёт новый. По ID ответа открыть экран беседы в приложении.
   Само сообщение пользователь вводит и отправляет в чате штатным способом.
2. «Отправить email»: открыть email.mailto_url в почтовом клиенте, либо использовать
   email.address как To собственного редактора письма. Приоритет — корректный
   work_email из CNT-002, затем корректный email учётной записи. Оба адреса проходят
   проверку одного адреса без display name/CRLF, специальные URI-символы кодируются.
   Если нет корректного адреса — `email_unavailable`. Чтение карточки не отправляет
   SMTP-письмо. Пользователь заполняет тему/текст и отправляет письмо в клиенте.
3. «Встреча»: открыть штатную форму календаря с title и attendee_ids из действия.
   Пользователь выбирает время и остальные параметры. Организатор определяется
   авторизацией существующего Calendar API; в attendee_ids только выбранный сотрудник.
   При необходимости вызвать POST availability_endpoint или suggest_times_endpoint
   с временем и attendee_ids. После заполнения формы отправить POST meeting.endpoint
   с CreateEventRequest, например:

```json
{
  "title": "Встреча: Анна Иванова",
  "start_time": "2026-10-02T10:00:00+05:00",
  "end_time": "2026-10-02T10:30:00+05:00",
  "attendee_ids": [42]
}
```

Проверка конфликтов, календаря, онлайн-встречи и приглашения остаются в текущем
Calendar API. Уведомления отправляются штатно после фактического создания события.
Выданные данные — текущие параметры формы; API чата/календаря выполняют собственные
проверки при запуске. URI экранов приложения не зашиты в бэкенд: фронтенд использует
свой роутер для чата/редактора письма/календаря. После изменения контактов или перед
действием по давно открытой карточке получить свежие actions.

## Развёртывание и проверки

Новых миграций, настроек, способов отправки сообщений/писем нет. Требуются уже
работающие API Conversations/Calendar. Обновлены Swagger и описание карточки.
Фронтенд и production не менялись; кнопки нужно подключить на фронтенде.

Проверки: `go test ./...`; интеграционные Contacts CNT-001–004 на одноразовой
PostgreSQL. Проверены параметры существующих API, предзаполнение участника,
собственная карточка, приоритет/изменение/очистка email, некорректные legacy-адреса,
URI-символы и header injection, изоляция компаний и недоступный сотрудник.
Браузерная приёмка переходов и отправка настоящих писем/приглашений не выполнялись.
