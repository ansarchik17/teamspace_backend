# Кандидат ИИ-бюджетов: готовые файлы, 20.10.2026

Статус: подготовлен локально, production не обновлён. Main и реестр образов
не изменялись. Прямой SSH-доступ агента отсутствует; оператор выполняет
серверные команды в своей сессии. Пароли и ключи не передавать в чат.

Уточнение по почте: на целевом сервере COPY-сборка почтового образа дважды
завершилась `insufficient_scope` при получении слоя через закрытый реестр.
Предварительная загрузка публичного Node-образа не исправила этот путь.
Для продолжения использовать отдельный пакет `ai-mail-fix-20261020-01.tgz`:
он содержит полный сохранённый почтовый образ, проверенный без сети, и
`apply-fix.sh`. Скрипт проверяет контрольные суммы обоих пакетов, загружает
образ из файла, сверяет слои и конфигурацию с локально проверенным образом,
проверяет почтовую защиту и запускает подготовку v2. Почта больше не
пересобирается поверх образа из закрытого реестра. Работающий почтовый
контейнер не экспортируется, не коммитится и не перезапускается; его
runtime-переменные и данные в архив не попадают. Исходный ready-пакет и
его контрольные суммы на сервере не изменяются.

На сервере 8 GiB RAM, доступно около 2.3 GiB, swap практически заполнен.
Полную компиляцию Go/Node и установку LibreOffice на production не запускать.
Старый `build-ai-candidate.sh` из исходного архива для этого сервера не применять.

Архив `tmp/ai-ready-20261020-01.tgz` содержит собранные Linux/amd64 программы,
SQL-миграции, готовые интерфейсы основного приложения и почты. Секреты,
реальные `.env`, данные БД и зависимости сборки в архив не включены.
Он создаёт новые слои COPY поверх проверенных существующих runtime-образов,
без RUN, установки пакетов или компиляции. Это всё ещё использует дисковый
ввод-вывод и ресурсы Docker; нулевое влияние на нагрузку не гарантируется.

Предполагаемые текущие выпуски сверяются автоматически:

- backend и worker: `ghcr.io/west6ide/workspace-backend:cb1fb7e93cb0f3729ef05a2b62757b711651e764`;
- frontend: `ghcr.io/west6ide/workspace-front:1bd3af28bbe882c1d5027002f2b1337d46e4f632`;
- mail: зависимости сверяются по package.json, базой служит фактический image ID
  работающего контейнера, а не изменяемый тег main.

При отличии выпусков, нездоровом сервисе, недостатке памяти/диска или
несовпадении контрольных сумм подготовка прекращается. Основные теги,
контейнеры, Compose-файлы и `.env` не меняются. Создаются только новые
локальные теги образов, защищённая резервная копия и временные контейнеры.

После проверки контрольной суммы архива и распаковки оператор запускает
`bash prepare-ready.sh`. Скрипт:

1. Проверяет payload, базовые выпуски, здоровье, память и диск.
2. Формирует отдельные кандидатные образы из готовых файлов и проверяет nginx.
3. Создаёт свежий pg_dump рабочей БД и копии конфигурации в защищённом каталоге.
4. Проверяет восстановление и миграции на временной БД без внешней сети.
5. Проверяет все десять AI-миграций, сохранность iForm и повторный запуск.

Временная БД ограничена 512 MiB RAM, CPU 1, tmpfs 256 MiB; мигратор —
256 MiB RAM и CPU 1. Дополнительное использование swap ими запрещено.
Образы, volume и конфигурация рабочей БД к тестовым контейнерам не подключаются.
Используется только базовый PostgreSQL-образ и свежий архив данных.

Успешный результат сохраняет `REHEARSAL_BACKUP_PATH` и `REHEARSED_IMAGES.txt`.
Он означает готовность к отдельному шагу обновления, а не выполненное обновление.
До активации сверить реальные пути Compose почты, сохранить выбор образов,
подготовить observe для API/worker, применить миграции один раз, обновить
API/worker, frontend и mail, проверить здоровье и реальную сессию пользователя.
Схему назад не откатывать, журнал и неизвестные резервы не удалять.

Стартовая квота сотрудника — 100 кредитов в неделю и 20 на пять часов.
Сначала суперадминистратор выдаёт бюджеты компаниям, затем операторская команда
defaults назначает недостающие квоты через штатные проверки и аудит.
Существующие квоты и явные нули не заменяются. До проверки всех компаний и
расхода оставить observe; enforced глобален и пока не включается.

Ограничения сохраняются: lookup API Nitec отсутствует; неизвестный расход
сверяется по ручным доказательствам. Старые интеграции без подключённого учёта
остаются закрытыми, включая почтовую ИИ-генерацию. Их нельзя считать
восстановленными этим релизом. Учесть это до активации.
