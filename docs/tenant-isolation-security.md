# BAS-022: изоляция организаций в поиске и ИИ

## Правила доступа

Идентификатор пользователя берётся из проверенной сервером сессии. Значения user_id,
organization_id, Host и инструкции в сообщении модели не выдают дополнительных прав.
Каталог сотрудников ограничен актуальным organization_id пользователя из БД.
Общее ministry_id не объединяет разные компании. Для старых аккаунтов без компании
сохранена видимость внутри министерства, но корпоративные аккаунты в неё не входят.
Глобальная роль admin сохраняет доступ платформы; директор не получает глобальную роль.
Служебный SupportUserID остаётся явно предусмотренным исключением каталога.
Неактивный или удалённый пользователь не может читать поисковый каталог.

Файлы, задачи, сообщения и notebook используют права на конкретный объект: владение,
участие или явно выданное разрешение. Межорганизационная передача прав, если она уже
разрешена модулем, считается разрешённым доступом. BAS-022 не запрещает такую передачу.
Без членства/разрешения чужие идентификаторы не должны раскрывать содержимое,
название, фрагмент, карточку или увеличивать число доступных результатов.

## Исправления по результатам проверки кода

- Поиск сотрудников, оба общих поиска, календарный каталог, SmartAgent, инструмент
  Agent search и AI SearchContacts используют SearchVisibleTo с текущим исполнителем.
- Убраны методы репозитория, позволявшие этим путям искать сотрудников без исполнителя.
- Кеш результатов AI SearchContacts отключён: перевод сотрудника в другую компанию
  немедленно учитывается при следующем чтении.
- Drive Search требует репозиторий актуальных прав. Отсутствие репозитория или ошибка
  проверки не разрешает использовать ACL из Elasticsearch как единственный источник.
- Запрошенные file_ids проверяются до индексации по требованию, извлечения текста и
  отправки на embedding. Если доступных идентификаторов нет, возвращается пустой результат.
- После объединения lexical/vector результатов права повторно проверяются в БД до
  отправки текста и имён файлов внешнему reranker; total_files считается после фильтра.
- Запрос родительских секций дополнительно ограничен уже проверенным file_id и
  принимает только запрошенные section_id.

## Автоматизированные проверки

Новые тесты имеют префикс TestBAS022:

| Проверка | Место |
| --- | --- |
| Две компании с одним ministry_id; legacy аккаунт; разрешённые коллеги и чужие canary | service/tenant_isolation_integration_test.go |
| Общий поиск, пользовательский provider, календарь, SmartAgent, AI контакты | тот же интеграционный тест |
| Подмена actor/company в аргументах инструмента; заблокированный/несуществующий actor; смена компании | тот же интеграционный тест |
| Организация имеет приоритет над ministry_id | domain/user_scope_test.go |
| Устаревший индекс с чужим документом: нет текста в ответе и в запросе reranker | service/drive_search_service_test.go |
| Отзыв права; подмена file_ids; отсутствие живого ACL репозитория | тот же тестовый файл |
| Agent search использует аутентифицированного исполнителя | agent/tenant_isolation_test.go |

Существующие регрессии также проверяют членство и видимость сообщений
(TestMSG006SearchRespectsAccessAndVisibilityIntegration), права Kanban
(TestKanbanSearchIntegration), чужой notebook и отозванные источники
(TestNotebookResearchDeniesForeignNotebookUnattachedAndRevokedSources), подмену
параметров HTTP reader и session identity (TestAIReader* / TestPersonalAI*), tenant host.

Запуск из корня репозитория, Go 1.24.7, PostgreSQL 16 в отдельной тестовой БД:

```sh
export TEST_MESSENGER_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/workspace_test?sslmode=disable'
export IFORM_TEST_DATABASE_URL="$TEST_MESSENGER_DATABASE_URL"
psql "$TEST_MESSENGER_DATABASE_URL" -v ON_ERROR_STOP=1 -c 'CREATE EXTENSION IF NOT EXISTS btree_gist WITH SCHEMA public; CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;'
go test ./internal/domain ./internal/repository ./internal/service ./internal/handler ./internal/agent ./internal/middleware -count=1 -timeout=10m
go vet ./...
go build ./cmd/api
```

Без TEST_MESSENGER_DATABASE_URL интеграционные тесты пропускаются; это не подтверждает
изоляцию. Существующий Backend CI задаёт эту переменную и выполняет go test ./....
Для полной локальной проверки нужны также MinIO и конвертеры документов по настройкам CI.

## Pentest на стенде перед приёмкой

Эта работа включает анализ кода и автоматизированные adversarial проверки. Она не
является отчётом независимого pentest развёрнутой инфраструктуры.

1. На согласованном тестовом стенде создать компании A/B, директора и сотрудника
   каждой, платформенного admin. В B создать уникальные canary в профиле, документе,
   задаче, сообщении и notebook. Не выдавать аккаунтам A права на объекты B.
2. Под сессией A искать canary B через обычный и общий поиск, календарь и все ИИ
   интерфейсы. Проверить JSON, количество, карточки, фрагменты, ссылки и ответы модели.
3. Подставить идентификаторы B в detail/source/file_ids, фильтры, tool arguments и
   историю диалога. Попросить модель игнорировать ограничения и выбрать компанию B.
   Проверить журнал запросов тестового AI provider: canary B не должен попадать в него.
4. Подставить host компании B, сменить роль/компанию, отозвать права на документ при
   неизменённом индексе; повторить чтение в новой и прежней сессии. Директор A не должен
   получать права платформенного admin. Не подменять реальные production аккаунты.
5. Проверить положительные сценарии A и явно выданного object ACL; отзыв ACL должен
   закрыть последующие чтения. Проверить недоступность БД ACL: запрещён fallback к индексу.
6. Зафиксировать версии API/индекса/модели, запросы и обезличенные ответы, результаты,
   подтверждение отсутствия canary в AI запросах, все отклонения и повторную проверку.

За пределами локального отчёта остаются реальный reverse proxy, SSO, Elasticsearch,
внешние интеграции и AI provider, конфигурация логов/кешей на стенде. Тесты проверяют
указанные границы доступа; они не доказывают отсутствие всех возможных утечек.

## Результат локальной проверки 2026-10-12

Go 1.24.7, PostgreSQL 16: новые TestBAS022 и полный прогон domain, repository,
service, handler, agent, middleware прошли. Для middleware на Windows исключён
существующий TestHTTPLoggingFormats: открытый logger удерживает файл при TempDir
cleanup. В CI Linux этот тест не исключается. go vet ./... и сборка cmd/api прошли.
MinIO и внешние конвертеры в этой локальной проверке не запускались; соответствующие
опциональные тесты пропущены. Реальный pentest стенда и проверка CI после публикации
не выполнялись.
