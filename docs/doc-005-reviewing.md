# DOC-005 — комментарии, предложения правок и просмотр

Бэкенд запускает нативные режимы ONLYOFFICE через существующий API:

`GET /api/v1/drive/onlyoffice/editor-link?file_id=<uuid>&mode=<mode>`

Нужен Bearer пользователя. Ответ `{ "url": "...", "mode": "review" }` содержит фактический режим и подписанную ссылку для браузера. Ссылка действует 10 минут; права проверяются повторно при открытии. Параметр `mode` в URL страницы не переопределяет режим подписанного токена.

| mode | Действия | Минимальные права Drive |
| --- | --- | --- |
| `view` (по умолчанию) | Только чтение, просмотр комментариев и правок, скачивание/печать | viewer |
| `edit` | Редактирование, комментарии; в текстовом редакторе включение трекинга и принятие/отклонение правок | editor |
| `comment` | Комментарии без прямого изменения содержимого | editor |
| `review` | Предложения правок с трекингом, комментарии; без принятия/отклонения правок | editor |

`review` поддерживается для DOCX; для других форматов возвращается 415. Для комментариев и редактирования рекомендуются DOCX/XLSX/PPTX; преобразование старых форматов не входит в задачу. Трекинг текста не имитируется для таблиц и презентаций.

При недостаточных правах на запись режим понижается до `view`, как раньше для `edit`. Нет доступа к файлу — 403; удалённый файл недоступен. Неизвестный mode сохраняет прежнее поведение — `view`. Режим — ограничение конкретного запуска редактора, а не новая роль Drive: пользователь с editor может отдельно открыть `edit`.

## Интеграция и сохранение

Для `comment`/`review` DocsAPI получает `editorConfig.mode=edit`, но `document.permissions.edit=false`. Комментарии разрешены в обоих режимах; review разрешён только для предложений в текстовом документе. `reviewGroups=[]` запрещает принимать/отклонять предложения в review-сессии. В `review` включены `customization.review.trackChanges` и панель правок. В текстовом редакторе стартовый вид `markup` показывает правки, в том числе при просмотре; настройки отображения из localStorage ONLYOFFICE могут его переопределить.

В `view` отключены права изменения, комментирования, рецензирования, заполнения форм и автосохранение; callbackUrl не передаётся, callback с view-токеном отклоняется. Публичный preview остаётся только для чтения.

Комментарии/ответы и отслеживаемые правки хранятся в документе, отдельной таблицы или REST CRUD комментариев нет. Снимки DocumentServer сохраняются в версии того же файла Drive через DOC-003. Callback и heartbeat поддерживают `comment`/`review`, проверяют текущие права editor и ключ сессии. Автосохранение в Drive требует настройки autoAssembly из DOC-003. Конфигурация подписывается при заданном `ONLYOFFICE_JWT_SECRET`; секрет должен совпадать с DocumentServer.

Новых миграций и переменных окружения нет. Нужны миграции предыдущих задач; приложение-фронтенд не менялось. Интеграция использует существующий ONLYOFFICE (для аватаров DOC-004 — 8+).

## Проверки

Автотесты покрывают матрицу режимов/форматов, downgrade viewer, отказ постороннему пользователю, подписанный режим запуска, права в JWT, callback и heartbeat режимов рецензирования. Регрессия сохранений и ACL проверяется тестами Drive/DOC-003/DOC-004.

Браузерная приёмка с настоящим DocumentServer ещё не выполнена:

1. Создать DOCX, открыть `comment`, добавить комментарий и ответ; прямое редактирование недоступно.
2. Открыть `review`, предложить вставку/удаление текста. Правки видны как предложения; принятие/отклонение недоступно.
3. Открыть `edit` вторым редактором, принять/отклонить предложения. Сохранить/закрыть сессию, открыть заново и проверить комментарии и правки.
4. Открыть `view` владельцем и viewer: добавление комментариев/правок недоступно; проверить также публичный preview.
5. Проверить комментарии и повторное открытие XLSX/PPTX; `review` для них возвращает 415.
6. Отозвать права editor: новые запуски понижаются до view, heartbeat/callback не могут записывать изменения.
