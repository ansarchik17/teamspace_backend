# DOC-006 — автосохранение, восстановление и версии

## Поведение

Редактор автоматически передаёт изменения DocumentServer. Таймер autoAssembly периодически собирает снимок, который callback DOC-003 сохраняет в Drive. Автосохранение не закрывает общую сессию. Финальное сохранение меняет её ключ. Каждый подтверждённый снимок доступен в истории; повтор того же callback не создаёт повторную версию.

При временной недоступности API/хранилища callback возвращает ошибку. DocumentServer может повторить доставку по настроенному backoff. Ошибка скачивания/записи после начала обработки сохраняется в БД как `save_failed`, без URL/секретов. Статусы DocumentServer 3/7 записываются как `document_server_error`; их URL не применяется к файлу. Для этих уведомлений проверяются JWT (если включён), подписанная callback-сессия, editor ACL и текущий ключ. Ответ `error=0` подтверждает получение уведомления об ошибке, а не сохранение документа.

Запись ошибки относится к версии и ключу, с которыми начиналась операция. Успешная новая версия, откат или восстановление делают старую ошибку неактуальной. Ошибка не хранится только в памяти процесса API. Если сама БД недоступна, запись ошибки также может не состояться; callback при этом не получает успешное подтверждение сохранения.

## API

Все перечисленные API требуют Bearer и текущих прав Drive.

| Запрос | Результат и доступ |
| --- | --- |
| `GET /api/v1/docs/files/:id/save-state` | Последний сохранённый снимок: `version`, `saved_at`, опционально `failure_kind` и `failed_at`; viewer |
| `POST /api/v1/docs/files/:id/recover` | Восстановление последнего снимка в новой сессии; editor |
| `GET /api/v1/drive/files/:id/versions?limit=20&offset=0` | История от новых к старым: версия, размер, дата, автор, `is_current`; viewer |
| `GET /api/v1/drive/files/:id/versions/:version/download` | Скачать сохранённую версию; viewer; также доступен HEAD |
| `POST /api/v1/drive/files/:id/versions/:version/restore` | Откат к выбранной версии; editor |

Тело обоих POST: `{"expected_version": 5}`. Ответ: `{"version": 6}`. Версия должна соответствовать актуальному снимку: при параллельном сохранении/откате/восстановлении — 409, нужно заново прочитать состояние. Это защищает от повторного исполнения запроса с потерянным ответом. История не удаляется, восстановление добавляет новую версию, даже если используется последний снимок. Объект хранилища переиспользуется. Смена ключа запрещает запоздалому callback старой сессии перезаписать восстановленное содержимое. Исторический дубликат уже применённого callback может получить успех, но ничего не изменит.

`save-state` сообщает о подтверждённом снимке Drive, а не о количестве несохранённых правок, доступности DocumentServer или включении его таймера. Отсутствие `failure_kind` не означает, что все правки уже сохранены. `saved_at` берётся из версии файла, не меняется от переименования/перемещения. Событие отката/восстановления попадает в аудит Drive с `restored_from_version`.

## Восстановление после сбоя

1. После краткого обрыва связи дать ONLYOFFICE восстановить соединение или заново открыть обычный `editor-link`: сохраняющийся ключ позволяет вернуться в существующую сессию.
2. Если сессия невосстановима, прочитать `save-state` и при необходимости скачать снимок/предыдущие версии.
3. Явно вызвать `recover` с текущим `expected_version`. Это **отбрасывает несохранённое состояние старой сессии для всех её участников**. Клиент должен объяснить это пользователю до действия; автоматического восстановления с потерей правок нет.
4. Получить новый `editor-link`. Старые вкладки получат конфликт ключа при heartbeat/сохранении и должны открыться заново.
5. Для возврата к более раннему содержимому использовать `versions/:version/restore`, затем также новый `editor-link`.

Гарантированная точка восстановления — последний успешно записанный снимок Drive. Правки, оставшиеся только в браузере, либо в утраченных данных DocumentServer после последнего снимка, восстановить через этот API нельзя. Нет фонового скачивания файлов по устаревшим подписанным URL и обещания бессрочных повторов доставки. Подписанная callback-сессия действует 24 часа; длительную сессию нужно открыть заново.

## Развёртывание

1. Применить `20260930120000_office_save_failures.sql` и предыдущие миграции Docs/Drive, обновить API. Down удаляет только состояния ошибок, не документы/версии.
2. На установленном DocumentServer сделать резервную копию `local.json`, затем выполнить `python3 configure-autosave.py /etc/onlyoffice/documentserver/local.json` от пользователя с правами на конфигурацию. Скрипт находится в `deploy/onlyoffice/`, требует Python 3. Он атомарно объединяет настройки с существующим JSON, сохраняет права/владельца и остальные поля, не печатает секреты.
3. Скрипт включает autoAssembly: интервал 5 минут, проверка каждую минуту. Настраивает до 8 повторов callback для HTTP 429/5xx, с экспоненциальной задержкой от 1 до 30 секунд и jitter. Перезапустить DocumentServer в согласованное окно и проверить фактическую доставку status=6. Интервал не является гарантированным сроком сохранения при очередях/сбоях.
4. Повторять применение настроек при пересоздании контейнера, если `local.json` не сохраняется системой развёртывания. JWT должен совпадать с `ONLYOFFICE_JWT_SECRET` API. Ошибки ACL/устаревшей версии (403/409) backoff не исправляет.

В `docker-compose.onlyoffice.yml` добавлены именованные тома данных, кеша, PostgreSQL, Redis, RabbitMQ и 120 секунд на штатное завершение. Это предназначено для самостоятельного DocumentServer из overlay; при внешних БД/очередях долговечность обеспечивает их развёртывание. Для существующего контейнера сначала сохранить его данные и перенести в тома: пустой новый том не содержит прежних правок. Не использовать `down -v` для рабочего окружения. Сохранность томов не заменяет резервное копирование. Образ должен оставаться на протестированном теге/digest.

Рабочий DocumentServer/production этой задачей не изменялся. Фронтенд приложения не менялся: API готовы для подключения состояния сохранения и действий восстановления/истории.

## Проверки

Автотесты: неуспешное скачивание → успешная повторная доставка без дубликата; сохранение состояния ошибки между экземплярами сервиса; устаревшие ошибки; восстановление/откат с сохранением истории и защитой от старого callback; параллельное восстановление; транзакционный откат при сбое записи версии; ACL/удаление; валидация callback 3/7. Проверяется также сохранение существующих полей и прав доступа при настройке local.json.

Браузерная приёмка с настоящим DocumentServer ещё необходима: изменить DOCX/XLSX/PPTX, дождаться автосохранения, проверить скачанный снимок; отключить и восстановить связь API, проверить повтор доставки; перезапустить DocumentServer с томами; восстановить последний снимок и откатить прошлую версию при открытой старой вкладке. Проверить, что комментарии и предложения DOC-005 сохранены в снимке.

Источники протокола: [callback](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler/), [autoAssembly и callbackBackoffOptions](https://api.onlyoffice.com/docs/docs-api/get-started/configuration/server-config/).
