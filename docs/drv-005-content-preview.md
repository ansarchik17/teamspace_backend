# DRV-005 — предпросмотр содержимого Drive

Реализован единый просмотрщик в интерфейсе Drive и на публичной странице.
Открытие файла из карточки, таблицы или панели сведений показывает модальное
окно просмотра. PDF отображается во встроенном браузерном вьюере, картинки
поддерживают масштаб 25–300%, аудио и видео — стандартные плееры с перемоткой.
Офисные документы открываются через Collabora Online в режиме чтения. Для пользователя
с правами редактирования есть отдельная кнопка перехода в редактор.

Просмотрщик показывает загрузку, ошибки доступа/декодирования, повторную попытку
и скачивание. Неизвестные форматы предлагают скачивание. Escape закрывает
модальное окно; фокус ограничен диалогом и возвращается при закрытии. Отменённые
запросы не подменяют выбранный файл. Медиа больше не загружается целиком в Blob.
Архивы продолжают использовать существующий просмотр содержимого архива.

Для WOPI-блокировок добавлена миграция `drive_wopi_locks`. Скачивание остаётся
attachment. Редактор получает серверную WOPI-сессию; браузер не формирует ссылки
на внутреннее хранилище.

## Контракт фронтенда

Все пути начинаются с `/api/v1`.

`GET /drive/files/{id}/preview` с авторизацией возвращает 200:

```json
{
  "file_id": "UUID",
  "name": "report.pdf",
  "size": 12345,
  "version": 1,
  "kind": "pdf",
  "mime_type": "application/pdf",
  "supported": true,
  "preview_url": "<PUBLIC_URL>/api/v1/drive/files/UUID/preview/content",
  "download_url": "<PUBLIC_URL>/api/v1/drive/files/UUID/download",
  "auth_required": true
}
```

`kind`: `pdf`, `image`, `audio`, `video`, `office`, `unsupported`. При `unsupported` возвращаются `supported: false`, `reason: unsupported_format`, отсутствует preview_url; download_url остаётся. Метаданные не содержат имени объекта MinIO или подписанных ссылок хранилища.

Компонент ContentViewer выбирает компонент по kind: PDF/office — iframe, image — img, audio/video — медиаплеер. Для неподдерживаемого формата или ошибки декодирования предлагается download_url. Офисный iframe сообщает о готовности/ошибке родительскому компоненту; сообщения проверяются по origin и окну отправителя.

`preview_url` требует той же авторизации, что остальные приватные API: Bearer-заголовок или существующая access_token cookie. Для iframe предпочтительна авторизация cookie через общий origin фронтенда и API. Встраивание разрешено только с того же origin.

## Нативные форматы и поток

`GET|HEAD /drive/files/{id}/preview/content` проверяет viewer-доступ, включая наследование, затем отдаёт байты inline с каноническим Content-Type и корректным Unicode filename.

Поддерживаются PDF; JPEG, PNG, GIF, WebP, AVIF; MP4, WebM, OGV; MP3, M4A, WAV, OGG, FLAC. Это список контейнеров/форматов, а не гарантия наличия нужного кодека в каждом браузере. Перекодирование и генерация миниатюр не выполняются.

Поддерживаются Range (обычный, суффиксный, открытый и multipart), 206, Content-Range, Accept-Ranges и HEAD без тела. Невалидный/недостижимый диапазон — 416. Чтение идёт через seekable MinIO object; файл целиком в память не загружается. Каждый новый запрос, включая Range/HEAD, заново проверяет ACL. Если права отозваны — 403; файл удалён — 404.

HTML, SVG, неизвестные расширения и несовместимый конкретный MIME нативных файлов не отображаются inline. При известных расширениях отсутствующий/application/octet-stream MIME нормализуется; офисные ZIP MIME обрабатываются отдельно. Обращение к нативному потоку для office/unsupported — 415. Ответы имеют no-store, nosniff, no-referrer. Для нативного содержимого запрещены скрипты политикой CSP; общий запрет iframe переопределяется на SAMEORIGIN только для предпросмотра.

## Офисный просмотр

Для DOC/DOCX, XLS/XLSX, PPT/PPTX, ODT/ODS/ODP, RTF descriptor возвращает kind office и `/drive/files/{id}/preview/office`.

Этот GET проверяет публичную ссылку и открывает Collabora с правом только чтения. Для работы требуется `COLLABORA_URL`, доступный backend и браузеру, и настройка WOPI allowlist на стороне Collabora. Backend получает `/hosting/discovery`; браузер отправляет форму запуска на URL из discovery.

Редактор `/drive/collabora/editor` проверяет ACL и выпускает подписанный токен доступа к одному файлу. WOPI `CheckFileInfo` и `GetFile` повторно проверяют ACL. `PutFile` требует edit-токен и активную блокировку файла, затем сохраняет обычную версию Drive с проверкой квоты.

Форма запуска передаёт Collabora `ui_defaults` с `UIMode=compact`, `UITheme=light` и закрытой
боковой панелью для документов, таблиц и презентаций. `SavedUIState=false`
задаёт одинаковый начальный вид при каждом открытии, включая браузеры с ранее
сохранённым режимом вкладок. Пользователь может открыть боковую панель через
меню редактора в текущей сессии. Настройки распространяются на приватный
редактор и офисный просмотр по публичной ссылке. После изменения требуется
обновить Workspace backend и заново открыть документ.

Светлая тема задаётся явно через `UITheme=light` в форме запуска. Параметр
`darkTheme` удаляется из URL: браузерный initializer Collabora считает любое
непустое значение (включая строку `false`) включением тёмной темы и заменяет
`ui_defaults`. Через
`css_variables` заданы размеры текста панелей (12/14 px) и высота верхнего
меню 64 px: в компактном режиме строка последнего сохранения может перенестись
на второй ряд. Эти параметры меняют интерфейс редактора, а не форматирование
документа. Приватная страница редактора выделяет iframe оставшуюся высоту,
не сжимает кнопку «Назад» и не добавляет прокрутку вокруг самого iframe.

При `COLLABORA_URL=https://teamspace.kz/office` форма запуска оставляет
браузерный редактор на текущем хосте Workspace: например,
`https://a.teamspace.kz/office/browser/...`. Это позволяет встроить редактор
в страницу компании с ограничениями `frame-ancestors` Collabora. Discovery
запрашивается только у настроенного Collabora, его origin проверяется до
замены хоста; допускаются только корневой домен, `www` и один DNS-поддомен
под доменом `APP_PUBLIC_URL`. Для отдельного домена Collabora замена не
применяется. WOPISrc остаётся на общем `APP_PUBLIC_URL`, поэтому WOPI allowlist
не требует добавления каждой компании. На корневом и wildcard HTTPS vhost
Nginx должен быть одинаковый `/office/` proxy, как в шаблонах production.

## Совместимость с публичными ссылками

`GET /public/drive/files/{token}/preview/info` возвращает тот же descriptor
с auth_required=false. `GET|HEAD /public/drive/files/{token}/preview` отдаёт
нативный поток. `GET /public/drive/files/{token}/preview/office` строит публичную
Collabora-страницу с edit=false. WOPI повторно проверяет срок и отзыв публичной
ссылки для каждого чтения. Публичный WOPI-токен не может записывать файл.

Все эти endpoints принимают resource_type=file и resource_id для файла внутри
общей папки. Срок, отзыв, принадлежность поддереву и полномочия создателя
проверяются при каждом запросе. Истёкшая ссылка — 403, отозванная — 404.
Папка без выбранного файла — 400; неверный тип для office/native — 415.
Публичный просмотр не создаёт постоянных ACL. Уже полученные байты и открытые
сессии внешнего просмотрщика не могут быть отозваны задним числом.

## Проверки и границы

Предыдущие проверки preview покрывают классификацию MIME, HTTP Range/HEAD и заголовки безопасности. Новая интеграция WOPI не проверена автоматически в этой смене.

`TestDriveStructureIntegration` с PostgreSQL/MinIO: наследование и отзыв ACL, реальный Range из MinIO, публичный просмотр/истечение/отзыв, удаление файла, офисные descriptors/config, запрет сохранения viewer-пользователем и отказ HTML inline. Переменные окружения запуска — как в drv-001-file-structure.md.

Визуальный рендеринг настоящих DOCX/XLSX/PPTX во внешней Collabora этим тестом не подтверждается.


Отдельный `TestDrivePreviewMetadataIntegration` требует только PostgreSQL
(`TEST_MESSENGER_DATABASE_URL`): все типы descriptors, наследование/отзыв ACL,
публичные файлы внутри папок, read-only конфигурации DOCX/XLSX/PPTX, отсутствие
callback, истечение и отзыв ссылок. Создаёт и удаляет изолированную схему.

Frontend build и реальный рендеринг Collabora этим изменением не запускались.
