# Чеклист задачи

База URL: `/api/v1/kanban`. Требуется авторизация и доступ к доске; запись разрешена Editor/Admin, чтение — Viewer тоже.

- GET `/tasks/{taskId}/checklist` — массив пунктов, пустой список `[]`.
- POST `/tasks/{taskId}/checklist` — `{"text":"Проверить","position":0}`, ответ 201 с созданным пунктом.
- PATCH `/checklist-items/{itemId}` — `{"text":"Обновить","completed":true}`, ответ 200 с обновлённым пунктом.
- DELETE `/checklist-items/{itemId}` — ответ 200 `{"status":"deleted"}`.

Старые названия `title`/`is_completed` также принимаются. Ответ содержит обе пары: `title` и `text`, `is_completed` и `completed`, с одинаковыми значениями. POST допускает начальную отметку выполнения. При PATCH отсутствующие поля не меняются, `false` снимает отметку. Противоречащие друг другу алиасы дают 400. Текст: 1–500 символов после trim; position: 0–1000000, без него POST добавляет пункт в конец.

Все вложенные маршруты `/tasks/{taskId}/checklist-items` и `/tasks/{taskId}/checklist/{itemId}` сохранены. Короткий маршрут сначала определяет задачу пункта, затем проверяет права; не обходит аудит и WS `kanban_checklist_changed`.

Если GET возвращает обычный текст `404 page not found`, проверить версию запущенного образа, а не только исходный код. После обновления необходимо пересобрать бэкенд и применить миграции штатным запуском. JSON 404 с сообщением о задаче/пункте означает, что маршрут уже работает, но объект не найден.
