# Счётчик заявок SenimDesk в Workspace

`GET /api/v1/organizations/current/sd-ticket-count` — защищённый Workspace endpoint без query-параметров. Возвращает `{"count":8}` и `Cache-Control: no-store`. Значение — `open_count` существующего SD `GET /dashboard/stats?limit=1`, то есть новые заявки в рамках текущих правил видимости SD, без заявок в работе и завершённых.

Компания, привязка к SD и пользователь определяются по авторизованному Workspace actor через существующий `SDHandoffProfile`. Клиент не передаёт user/company/host. Проверяются активность сотрудника, компании и модуля SD. Затем существующий `/api/internal/workspace/ai-read-token` выдаёт короткоживущий GET-only токен уже связанного пользователя SD и host его тенанта. Общий секрет аутентифицирует этот серверный запрос, но не заменяет пользователя на администратора. Provisioning и browser handoff при чтении счётчика не выполняются.

GET статистики проходит обычные SD auth, tenant-host validation и RBAC для чтения заявок. Токен и Host передаются только настроенному `SD_ACCESS_API_URL`; redirects запрещены. Общий внутренний секрет не отправляется на stats endpoint. Браузер получает только count, без SD токена, внутренних ошибок и содержимого заявок. Операция ограничена общим deadline 10 секунд, тело ответа — 512 КиБ. Отсутствующий/нечисловой/отрицательный/выходящий за JS safe integer count считается ошибкой, не нулём.

При запрете чтения — 403; при недоступности, отсутствии привязки, ошибке авторизации удалённого сервиса или некорректном ответе — безопасная 503 `SD_COUNTER_UNAVAILABLE`. Фронт отображает «—» с пояснением; подтверждённый count=0 показывает как 0. Ошибка не мешает счётчикам ЭДО. Клик «Заявки» сохраняет существующий вход SenimDesk.

Нужен деплой Workspace backend и Workspace front. Новых переменных и миграций нет: используются `SD_ACCESS_API_URL`, `SD_ACCESS_INTERNAL_TOKEN`, действующий модуль, привязка компании и SSO-пользователь SD. На SD должен быть развёрнут существующий endpoint read-only токена. Если сотрудник ещё не связан, он сначала открывает SenimDesk обычной кнопкой; фоновый счётчик не создаёт учётные записи.

Локально проверяются scoped user/Host, две компании, запрет после отключения сотрудника/модуля, ошибки/redirect, некорректный JSON, отмена запроса и запрет подстановки идентичности в query. На production отдельно сравнить счётчик с новыми заявками SenimDesk под тем же пользователем и проверить другую компанию.
