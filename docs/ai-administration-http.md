# HTTP администрации ИИ: задача 14

На 19 октября 2026 года подключены операции задач 10–13 к существующему защищённому router. Авторизация Bearer JWT и локализация остаются в существующем middleware; обработчики используют OrganizationService, без SQL в HTTP-слое.

Префиксы:

- D: `/api/v1/organizations/current/administration`.
- P: `/api/v1/platform/organizations/:organization_id/administration`.

| Метод и путь | Доступ |
| --- | --- |
| GET D/P `/ai-budget` | Директор своей активной компании / платформа выбранной компании |
| PUT P `/ai-budget` | Только платформа; D PUT намеренно не регистрируется |
| GET D/P `/ai-budget/users` | Административный список квот |
| GET D/P `/ai-budget/users/:user_id` | Одна квота, с проверкой текущей принадлежности |
| PUT D/P `/ai-budget/users/:user_id` | Директор своей компании / платформа |

Регистрация общая для production и тестов — RegisterAIBudgetRoutes. Подключена к существующим groups внутри NewRouter. GET возвращает Cache-Control:no-store; изменения — 204 без тела. Права, состояние компании, личная revision и принадлежность проверяются сервером. company_revision принимается для совместимости и не ограничивает личную квоту. Для аккаунтов без компании добавлен отдельный API: [личная политика](ai-personal-access-policy.md).

## Данные и валидация

Контракт находится в `workspace-front/docs/ai-budget-api-contract.md` и обновлён статусом реализации. Все суммы µcr и revision в публичном JSON — десятичные строки, включая вложенные окна/служебные счётчики; отсутствие настройки — null. Поля user_id/total/limit/offset/remaining_percent сохраняют числовой формат контракта. Преобразование не использует float, значения больше безопасного целого JavaScript не теряются.

PUT бюджета требует четыре поля: weekly_budget_microcredits, max_five_hour_microcredits, service_weekly_quota_microcredits, revision. PUT квоты — weekly_quota_microcredits, five_hour_limit_microcredits, revision, company_revision. Все обязательны. Только application/json (допускается charset), максимум 4096 байт. Token-based decoder отклоняет неизвестные/повторные ключи, разные регистры имён, JSON number/bool/null вместо строки, знаки, ведущие нули, дроби, экспоненту, пробелы в числе, int64 overflow, лишний JSON после объекта и превышение суммы 1000000000000000 µcr. Внешний organization_id в JSON не принимается.

Пагинация: limit default 25, 1–100; offset default 0, 0–2147483647. Явные пустые/повторные limit/offset/q и некорректный URL encoding отклоняются. q trim, валидный UTF-8, до 255 символов. user_id в пути — положительная каноническая десятичная запись int64. UUID компании проверяет существующий accessOrganizationID.

GET одной квоты добавлен как адресный repository/service метод поверх общего чтения списка: SQL ограничивается userID до пагинации, не загружает все страницы. Чужой/удалённый пользователь возвращает NOT_FOUND, обычный сотрудник не получает административные данные.

## Периоды и режим

GET не создаёт строки периодов. После простоя возвращается вычисленный объект period с starts_at/ends_at и id=null до первого успешного резервирования этого окна. Когда сохранённого якоря нет, period=null. Это уточнение внесено в API-контракт; UUID не генерируется искусственно при каждом чтении.

enforcement_mode пока observe: ограничения ещё не подключены к провайдерам. Это не утверждение о сборе расхода всех платных путей. Общий переключатель режима и полноценное наблюдение относятся к дальнейшим задачам. PUT не позволяет менять режим. Личный `/api/v1/ai/limits` в задачу 14 не входит и не зарегистрирован.

## Ошибки и проверки

Используется существующий envelope `{"error":{"code","message","user_message","details"}}` и существующие ru/kk-каталоги, включая AI_REVISION_CONFLICT/AI_BUDGET_CONFLICT/AI_CONFIGURATION_REQUIRED/AI_COMPANY_SUSPENDED из задач 11–13. Ошибки парсинга возвращают VALIDATION_ERROR без исходного JSON или диагностических ответов; отсутствие аутентифицированного actor — UNAUTHORIZED. Локализованные подсказки и allowlist details не заменяются сырым err.Error().

Unit-тесты TestAIAdministrationValidation и TestAIAdministrationPayloadPrecision проверяют строгий JSON, media type, размер, строки/overflow, пути/пагинацию, отсутствие tenant PUT и точную сериализацию больших чисел/null/времени.

Интеграционный TestAIAdministrationHTTP использует настоящий handler → service → repository и реальные миграции аудита/блокировок/ИИ в отдельной PostgreSQL-схеме. Проверяет чтение/запись, роли, чужую компанию/сотрудника, обе устаревшие версии, 204, Cache-Control, ru/kk, списки и одну квоту, suspended-компанию и деактивированного администратора. Тестовый middleware подставляет actor вместо реальной выдачи JWT; криптографическая проверка токенов относится к existing auth middleware и не переопределяется.

19 октября интеграционный тест и регрессионные проверки задач 10–13 прошли на отдельном временном PostgreSQL 16; схема очищена, сервер остановлен. Полный production-набор миграций и вызовы внешних провайдеров не проверялись.

Модульные проверки строгой валидации/сериализации также прошли; `go test ./internal/server -run '^$'` подтвердил сборку основного router. Go-файлы отформатированы gofmt, проверка пробелов в изменениях выполнена.

Новых миграций/зависимостей нет. Перед обновлением бэкенда должны быть применены подготовленные миграции 05–07 и существующие миграции администрации. Фронтенд-приложение пока не использует новые маршруты; изменена только его документация API. Commit, push и развёртывание не выполнялись.
