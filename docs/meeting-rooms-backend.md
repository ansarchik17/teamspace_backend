# Переговорные компании: контракт для подключения фронтенда

Все пути ниже относительно `/api/v1/calendar`, с существующей Bearer-авторизацией.
Компания определяется по актуальной записи авторизованного пользователя. `organization_id` из тела не используется.
Только администратор (`role=admin`) и директор компании (`organizations.owner_id`) управляют площадками и комнатами. Остальные сотрудники смотрят и бронируют. Чужие идентификаторы возвращают 404. Ранее сохранённое право `calendar.rooms.manage` не даёт права управления.
Для отображения кнопок создания и редактирования фронтенд может использовать `can_manage_structure` из GET `/api/v1/organizations/current`: он соответствует директору или админу. Сервер повторно проверяет права при каждом изменении. Выбор комнаты и бронирование доступны остальным сотрудникам своей компании.

## Площадки

| Метод | Путь | Результат |
|---|---|---|
| GET | `/sites` | Массив активных площадок своей компании |
| GET | `/sites?include_inactive=true` | Включая отключённые, для управляющих |
| GET | `/sites/{id}` | Площадка своей компании |
| POST | `/sites` | Создание, 201 |
| PATCH | `/sites/{id}` | Частичное изменение, 200 |
| DELETE | `/sites/{id}` | Удаление, 204 |

Тело создания:

```json
{"name":"Главный офис","address":"ул. Достык 1","city":"Алматы","timezone":"Asia/Almaty","working_hours":"09:00–19:00","is_active":true}
```

Обязательно `name`. Значения по умолчанию: пустые адрес/город/часы работы, `Asia/Almaty`, активная площадка. PATCH принимает те же поля выборочно. Ответ дополнительно содержит `id`, `organization_id`, `created_at`, `updated_at`.
Площадка с неудалёнными комнатами: 409 `SITE_HAS_ROOMS`. Отключение площадки скрывает комнаты из активного выбора, запрещает новые брони и уведомляет организаторов будущих броней.

## Переговорные

Существующие ответы `/rooms` и `/rooms/availability` сохранены; добавлены `organization_id`, `site_id`, `site_name`, `address`, `photo_url`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/rooms` | Массив активных комнат на активных площадках |
| GET | `/rooms?site_id={uuid}&min_capacity=5` | Фильтры площадки и вместимости |
| GET | `/rooms?include_inactive=true` | Все комнаты своей компании для управляющих |
| GET | `/rooms/{id}` | Комната своей компании |
| POST | `/rooms` | Создание, 201 |
| PATCH | `/rooms/{id}` | Частичное изменение, 200 |
| DELETE | `/rooms/{id}` | Удаление, 204 |

Старый PUT для изменения комнаты, фильтры `capacity`, `floor`, `search`, `equipment`, `only_active` и endpoints бронирования доступны. Обычный сотрудник не может расширить список до отключённых комнат через фильтры.

```json
{"site_id":"UUID площадки","name":"Байконур","floor":2,"location":"Блок Б, каб. 210","capacity":8,"equipment":["projector","screen"],"description":"Переговорная","color":"#4F46E5","photo_url":"https://example.com/room.jpg","is_active":true}
```

Обязательны `name` и положительная `capacity`. Передавайте `site_id` явно. Для совместимости старого клиента без `site_id` используется первая активная площадка компании.
Название уникально в пределах площадки без учёта регистра и пробелов по краям: 409 `ROOM_NAME_TAKEN`.
Удаление при будущей или текущей подтверждённой брони: 409 `ROOM_HAS_BOOKINGS`. Отключение сохраняет брони, запрещает новые и ставит организаторам уведомление `room.disabled`.

## События и участие

Создание и обновление события допускают одновременно `room_id` и `is_online:true`. Свободное `location` и онлайн-ссылка независимы. Событие без места и без ссылки допустимо.
Для изменения доступен новый PATCH `/events/{id}` и прежний PUT. Явный `room_id:null` снимает комнату; `location:null` очищает свободный адрес. `is_online:false` удаляет сведения онлайн-подключения.
Создание или добавление приглашённых принимает `default_attendance: "offline" | "online" | null`. Этот выбор применяется новым участникам; уже полученные ответы сохраняются.

GET `/events` и `/events/{id}` возвращают участникам:

```json
{
  "room_id":"UUID комнаты",
  "room":{"id":"UUID комнаты","name":"Байконур","site_name":"Главный офис","address":"ул. Достык 1","floor":2,"location":"Блок Б, каб. 210","capacity":8},
  "is_online":true,
  "meeting_url":"https://...",
  "attendees":[{"user_id":123,"status":"accepted","attendance":"online"}],
  "attendance_summary":{"offline":5,"online":3,"unknown":2},
  "warnings":["ROOM_CAPACITY_EXCEEDED"]
}
```

У постороннего GET по ID возвращает 404. Снимок комнаты сохраняет место на момент бронирования после переименования, отключения и мягкого удаления. Новые изменения отдельных повторений тоже сохраняют снимок комнаты.

PATCH `/events/{id}/response`:

```json
{"status":"accepted","attendance":"online"}
```

Существующий POST `/events/{id}/respond` также принимает новое поле. Статусы: `accepted`, `declined`, `tentative`. Ответ успешного RSVP сохраняет прежнее сообщение; актуальные счётчики читать через GET события.
`offline` разрешён только при наличии места; `online` — при наличии ссылки. Недопустимый формат: 422 `ATTENDANCE_NOT_ALLOWED`. При одном доступном формате выбор устанавливается автоматически; у гибридной встречи отсутствие выбора остаётся null.
Счётчики включают организатора и всех не отказавшихся участников. Превышение вместимости — предупреждение, сохранять встречу можно. При отсутствии предупреждений поле `warnings` может отсутствовать.

При смене комнаты, свободного адреса или ссылки все участники получают `event.location_changed`. Удаление места сбрасывает `offline` в null; удаление ссылки сбрасывает `online` в null. Изменения помещаются в транзакционную очередь и доставляются сразу либо при следующем проходе существующего воркера календаря.

## Приглашения и напоминания

Приглашение содержит полное место и доступную ссылку. ICS содержит место в LOCATION, ссылку в URL и описании. По умолчанию создаётся напоминание за 15 минут; прежний `reminder_minutes` позволяет изменить время. Офлайн-напоминание содержит место; онлайн-напоминание — ссылку подключения.

## Миграция и отчёт

Перед запуском обновлённого бэкенда применить `20261014000200_company_meeting_rooms.sql` штатным процессом миграций.
Для существующих компаний создаётся «Основной офис». Старые комнаты привязываются по компаниям организаторов событий и броней, только если все известные владельцы однозначно относятся к одной компании. Неиспользованные комнаты и неоднозначные записи отключаются и остаются без компании.
При старых одинаковых именах на одной площадке второму и последующим именам добавляется UUID; сохранённые снимки событий сохраняют прежние имена.

Отчёт для администратора платформы: GET `/rooms/unassigned`. Для обычных сотрудников и владельцев компаний без роли платформенного admin недоступен. Также в БД доступно представление `calendar_unassigned_rooms`. Реальный список формируется после применения миграции на целевой базе.

Проверено интеграционными тестами на отдельном PostgreSQL: права, изоляция компаний, миграция, гибридное участие, снимки места, сброс выбора, очередь уведомлений, запрет удаления с бронями, сохранение отключённых броней, конкурентное бронирование и ICS.
