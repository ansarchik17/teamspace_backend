# CNT-002 — Карточка сотрудника

## API

Все маршруты требуют BearerAuth и активную компанию текущего пользователя.
Карточки доступны только для активных, неудалённых сотрудников своей компании;
неизвестный/чужой сотрудник — 404.

### GET /api/v1/contacts/{user_id}

Поля справочника CNT-001 (фото, имя, должность, email, подразделение и прочие)
дополнены:

- `work_email`, `phone`: дополнительные рабочие контакты; отсутствуют, если не заданы.
- `manager`: карточка непосредственного активного руководителя той же компании.
- `management_chain`: руководители по порядку от непосредственного к верхнему.
- `hierarchy_truncated`: true при старом цикле или достижении предела 100 переходов.
  Циклический узел и узел на предельном переходе не возвращаются.
- `direct_reports_total`: количество прямых активных подчинённых.

Карточка, цепочка и счётчик читаются в одном согласованном снимке PostgreSQL.
Чужие/удалённые/неактивные руководители не раскрываются, цепочка на них обрывается.
Фото из файлового хранилища получают свежую подписанную ссылку на 24 часа при
каждом чтении карточки или справочника; после истечения нужно запросить карточку снова.
Новые аватары также отображаются в существующих профилях через users.avatar_url.

### PATCH /api/v1/contacts/{user_id}

Редактирование только собственных контактов:

```json
{"work_email":"employee@example.com","phone":"+7 (701) 123-45-67"}
```

Ответ 204. Пропущенное поле или null сохраняет прежнее значение; пустая строка
очищает поле. Допустимы только work_email и phone, неизвестные поля — 400.
Тело ограничено 4 KiB. Email — один адрес без display name, до 254 байт;
проверяется синтаксис, доставляемость не проверяется. Phone — международный номер
с `+` и 7–15 цифрами, первая цифра не ноль; пробелы, скобки и дефисы удаляются.
Неверные контакты — 400, изменение чужой карточки — 403.

Контакты хранятся в employee_contacts. Поле email из CNT-001 остаётся адресом
учётной записи; work_email не меняет login/email в Keycloak и не обязан быть уникальным.
Должность/отдел/руководитель этим PATCH не меняются. Для организационного назначения
используется существующий административный API organizations/current/users/{id}/assignment.

### POST /api/v1/contacts/{user_id}/avatar

Multipart form с полем `file`, только собственный аватар. Ответ 200 — обновлённая
карточка. JPEG/PNG до 5 MiB, разрешение до 2048x2048. Проверяются и декодируются
реальные байты, имя/Content-Type не определяют формат. Изображение перекодируется
для удаления метаданных/лишних байтов; SVG/GIF/WebP не поддерживаются.
Затем объект сохраняется через существующий FileService/MinIO и URL в users.avatar_url.
Если запись профиля после загрузки не удалась, новый объект удаляется с отдельным
контекстом очистки. Прежний объект не удаляется, чтобы не ломать уже выданные ссылки;
очистка старых аватаров в эту задачу не входит. При недоступном хранилище — 500.

### GET /api/v1/contacts/{user_id}/reports?limit=50&offset=0

Прямые подчинённые, формат ContactList из CNT-001. Limit 1–100, offset >= 0;
сортировка/total как в справочнике. Также поддерживаются фильтры q, unit_id, position
из CNT-001. Вложенные подчинённые не включаются.

## Иерархия и развёртывание

Нужна миграция `20261001120000_employee_contacts.sql`: таблица контактов,
индекс прямых подчинённых и DB-trigger для назначения руководителей.
Триггер защищает также legacy/admin записи users: запрет самому себе, циклов,
чужого/неактивного руководителя; перенос руководителя в другую компанию требует
предварительно переназначить его подчинённых. Изменения иерархии сериализуются
advisory-lock по компании, перенос — по обеим компаниям в фиксированном порядке.
Текущие старые данные не переписываются: цепочка защищена от существующих циклов,
ошибочные связи нужно исправлять штатным назначением. Архивация/деактивация
руководителя не переносит подчинённых автоматически: руководитель скрывается.
Новых переменных окружения нет; нужны уже настроенные MinIO и APP_PUBLIC_URL.
Фронтенд и production-конфигурация не менялись.

## Проверки

`go test ./...` и `TEST_MESSENGER_DATABASE_URL=... go test ./internal/service -run TestContactProfileIntegration -v`.
Проверены карточка/отдел/руководители/подчинённые, границы компаний, контакты и
неизменность login email, аватар/некорректные изображения/лимиты/очистка после отказа
записи, миграция Up/Down, прямые и конкурентные циклы, существующий цикл и перенос
компании. В тесте профиля PostgreSQL настоящий, хранилище изображений имитируется.
