# Изменение бюджета суперадмином: задача 11

> Изменение 20.10.2026: отдельная служебная квота отменена. Актуальные правила и совместимость: [Фоновый расход из общего бюджета](ai-background-shared-budget.md). Указания Qservice ниже относятся к предыдущей версии.

Добавлены внутренний `domain.SetAIBudgetRequest`, `OrganizationRepository.SetAdministrationAIBudget` и делегирующий метод OrganizationService. HTTP PUT ещё не зарегистрирован: обработчики и канонические JSON-строки относятся к задаче 14. Интерфейс принимает обязательные указатели на B, Hmax, Qservice, revision; отсутствие значения не смешивается с нулём. Суммы ограничены 0–1000000000000000 µcr, revision неотрицательная.

## Транзакция

Операция требует явный organizationID и актуальную активную роль платформы admin. Директор не может изменять бюджет, включая собственную компанию. Используются existing authorizeAdministrationLocked и writeAdministrationAudit. Все изменения, проверка версии, чтение обязательств и запись аудита выполняются в одной транзакции.

Блокировка строки organizations сериализует первое создание бюджета при ещё отсутствующей записи. Существующая строка organization_ai_budgets также блокируется FOR UPDATE. Проверка активной роли актёра выполняется с блокировкой. Изменение бюджета suspended-компании разрешено платформе по утверждённому контракту; универсальная обёртка auditOrganizationMutation для этого не используется, поскольку она запрещает любые изменения suspended-компаний. Формат и механизм записи административного аудита остаются существующими.

Общее чтение расчёта задачи 10 выделено в aiBudgetSummary, чтобы write-сценарий использовал ту же формулу внутри своей транзакции без вложенного Read Only/Repeatable Read. Внешний метод чтения по-прежнему использует один read-only snapshot. Остальные сценарии назначения/резервирования должны блокировать строку бюджета до изменения обязательств; полный жизненный цикл/конкуренция этих сценариев реализуются последующими задачами.

## Правила изменения

- Отсутствующей настройке соответствует ожидаемая revision=0, созданной — её текущая версия. Конфликт возвращает AI_REVISION_CONFLICT с company/expected_revision/current_revision в безопасных строковых details.
- Проверка revision предшествует no-op: устаревшая версия не принимается даже при совпадающих значениях.
- Реальный no-op с актуальной версией не увеличивает revision и не пишет дублирующий аудит.
- Новая Qservice подставляется в общую формулу обязательств `Σ max(Q,S+R)`, а не прибавляется поверх старой служебной квоты.
- Положительный B должен покрывать итоговые обязательства и общий расход с активными резервами. Проверяются переполнения без float и без обрезания сумм.
- B=0 разрешён как аварийное отключение; при этом увеличивать Qservice запрещено. Назначения сотрудников, расход, резервы и периоды не удаляются.
- Снижение Hmax не перезаписывает сохранённые H сотрудников и не сбрасывает их окна.
- Первое создание получает revision=1, следующие изменения увеличивают её существующим триггером БД; вручную revision не изменяется.

Аудит: action=`ai.budget.update`, object_type=`ai_budget`, object_id=UUID компании. Before/after — явная проекция четырёх настроек из БД; значения сериализованы строками, до первого создания before=null. Данные сотрудников, промпты и диагностические ответы в snapshot не попадают. Ошибка записи аудита откатывает настройку и её revision целиком.

## Ошибки и локализация

Добавлены AI_REVISION_CONFLICT и AI_BUDGET_CONFLICT (409), безопасные сообщения ru/kk. Фильтр PublicDetails разрешает только известный scope, канонические неотрицательные revision int64 и перечисленные business reasons. Произвольная диагностика не показывается. Валидация и запрет доступа используют существующие VALIDATION_ERROR/FORBIDDEN. Остальные поля amounts в details пока не выдаются; расширять allowlist произвольными значениями нельзя.
