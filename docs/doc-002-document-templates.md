# DOC-002 — создание документов и шаблоны компании

Все маршруты требуют Bearer-аутентификацию. Результат создания — обычный файл
Drive с владельцем, версией 1, MIME-типом и отдельным ключом ONLYOFFICE.
Действуют права целевой папки, лимит загрузки, квота, аудит и индексация Drive.
Фронтенд и развёртывание в production в эту задачу не входят.

## Пустой файл

`POST /api/v1/docs/files`

```json
{"name":"Договор","format":"docx","folder_id":null}
```

`format`: `docx`, `xlsx` или `pptx`. Создаётся пустая страница A4, книга с листом
«Лист1» или презентация 16:9 с одним пустым слайдом. Это OOXML-пакеты, а не
пустые байтовые файлы. Имя без расширения получает нужное расширение; явно
указанное расширение должно совпадать с форматом. Ограничение имени — 200
символов с расширением; пути и управляющие символы запрещены.

Ответ `201` — объект `DriveFile`. Чтобы открыть редактор, передать его `id` в
`GET /api/v1/drive/onlyoffice/editor-link?file_id=<id>&mode=edit` (DOC-001).
Создание не зависит от доступности DocumentServer. Личный пустой файл можно
создать и без организации.

## Каталог компании

`POST /api/v1/docs/templates`

```json
{"name":"Типовой договор","file_id":"<uuid существующего DOCX в Drive>"}
```

Публиковать и снимать шаблоны может владелец организации или администратор,
определяемый существующими правилами корпоративной структуры. Для публикации
он должен владеть исходным файлом в Drive своей компании. Форматы — DOCX/XLSX/PPTX.
Одно и то же исходное `file_id` нельзя публиковать в одной компании повторно (`409`).

**Публикация явно разрешает сотрудникам компании копировать содержимое файла.**
Это право каталога шаблонов, даже если исходный файл не расшарен через ACL Drive.
Организация определяется на сервере по пользователю, а не принимается из запроса.
В каталоге используется текущая версия исходного файла: редактирование оригинала
обновляет шаблон для последующих созданий. Уже созданные копии не меняются.

`GET /api/v1/docs/templates?limit=50&offset=0` возвращает массив доступных шаблонов
только текущей активной компании. Максимальный limit — 100.
Удалённый исходник, файл вне Drive, изменённый формат и источник, переданный
владельцу другой организации, недоступны. Восстановленный подходящий исходник
снова появляется в каталоге, если публикация не снята.

`DELETE /api/v1/docs/templates/<id>` снимает публикацию (`204`). Исходник и ранее
созданные файлы не удаляются. Чужой/неизвестный шаблон — `404`; обычный сотрудник
не может управлять каталогом (`403`). Для изменения названия публикацию можно
снять и создать заново; отдельное редактирование метаданных не добавлено.

## Создание по шаблону

`POST /api/v1/docs/files`

```json
{"name":"Договор с клиентом","template_id":"<uuid шаблона>","folder_id":null}
```

Нужно указать ровно одно из `format` и `template_id`. При выборе шаблона формат
берётся из каталога. В MinIO создаётся отдельный объект; у файла новый ID, владелец
и история версий. Права, публичные ссылки и история оригинала не копируются.
В целевой папке требуются права Editor; в личном корне файл принадлежит создателю.

Несколько пустых файлов или копий одного шаблона в одной папке разрешены, включая
одинаковое содержимое. Обычная загрузка Drive сохраняет прежний запрет дублей.
Автоматического заполнения переменных шаблона и генерации текста в DOC-002 нет:
копируется всё содержимое типового документа, включая оформление.

## Развёртывание и проверки

Применить `20260929120000_document_templates.sql` после миграций организаций и Drive.
Новых переменных окружения нет. Миграция Down удаляет каталог, не затрагивая файлы.

- `go test ./...`: общий набор тестов.
- `TEST_MESSENGER_DATABASE_URL=<одноразовая PostgreSQL> go test ./internal/service -run 'TestDocument|TestOnlyOfficeConfigIntegration' -count=1`:
  структура OOXML и связи частей, чтение XLSX библиотекой, имена и параметры;
  создание всех форматов, повторное создание, независимые копии, исходные ACL,
  ограничения организаций и ролей, удалённые исходники, квота и откат миграции.
  Для содержимого файлов используется локальный HTTP S3-эмулятор с настоящим
  MinIO-клиентом; рабочие бакеты не используются.

Структура PPTX сверена с [документацией Microsoft по PresentationML](https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-create-a-presentation-document-by-providing-a-file-name).
Ручная проверка на стенде: создать три пустых файла, открыть через ONLYOFFICE,
внести изменения и проверить сохранение; опубликовать оформленный шаблон компании,
создать копию вторым сотрудником и убедиться, что оригинал остался прежним.
