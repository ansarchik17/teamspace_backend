# Синхронизация перемещения карточек

После успешного `PUT /api/v1/kanban/tasks/:id/move` сервер автоматически
отправляет участникам через `/api/v1/ws` событие:

```json
{
  "type": "kanban_task_moved",
  "board_id": "UUID доски",
  "task_id": "UUID задачи",
  "from_column_id": "UUID исходной колонки",
  "to_column_id": "UUID целевой колонки"
}
```

Клиенту достаточно сохранить перемещение через REST и слушать WS. Дополнительная
отправка события клиентом не требуется. Для совместимости сервер также принимает
этот формат от клиента после успешного REST-запроса (это создаст повторное событие).

Для входящего WS-события все четыре ID обязательны и должны быть ненулевыми UUID. Сервер проверяет
доступ отправителя, принадлежность задачи и обеих колонок доске, а также
текущее положение задачи в целевой колонке. Событие уведомляет о сохранённом
перемещении; оно не изменяет БД и не повторяет побочные эффекты REST-запроса.

Владелец и участники доски получают те же пять полей на всех подключённых
устройствах, включая отправителя. Добавляются `from` (ID авторизованного
пользователя) и `timestamp` (Unix seconds), установленные сервером.
Получатели могут обновить доску через REST. Повторные события допустимы;
после переподключения нужно заново загрузить доску — события не сохраняются.

Отклонённые события никому не рассылаются. Отправитель получает `type: "error"`
с `content.event: "kanban_task_moved"` и `content.code`:
`invalid_payload` (отсутствующий/нулевой ID), `unavailable` (обработчик не
настроен), `move_rejected` (проверка доступа/состояния или запрос к БД не удался).
Невалидный JSON и строки, не являющиеся UUID, игнорируются общим WS-парсером.

Порядок колонок сохраняется через `PUT /api/v1/kanban/columns/:id/move`
с телом `{"new_position": 0}` (индекс с нуля). После сохранения сервер отправляет
`{"type":"kanban_column_moved","board_id":"UUID","column_id":"UUID","from":123,"timestamp":1234567890}`.
По этому событию клиент заново загружает доску, чтобы получить фактический порядок
всех колонок. Входящие `kanban_column_moved` от клиента не нужны и не принимаются.

События отправляются только после успешной записи. Ошибка поиска получателей
логируется и не превращает уже выполненное перемещение в ошибку REST.
WS-доставка не гарантируется для отключённых клиентов или при заполнении буфера;
после восстановления соединения нужно загрузить актуальную доску через REST.
Перемещение задачи обновляет её колонку и соответствующий статус существующим
REST-методом; произвольный порядок карточек внутри одной колонки API не сохраняет.
