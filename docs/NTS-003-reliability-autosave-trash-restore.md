# NTS-003 — Надежность: Автосохранение и восстановление удалённых заметок

Реализация расширяет функционал модуля заметок на backend (Go) в рамках задачи **NTS-003: Надежность**. Обеспечивается отказоустойчивое сохранение правок при вводе текста, предотвращение потери данных при конфликтах версий, перемещение заметок в корзину с окном удержания (retention) 30 дней и возможность безопасного отката (восстановления) удалённых заметок. Изменения выполнены строго в `workspace-backend`.

---

## 1. Возможности API

### Автосохранение при вводе (Autosave)
- `POST /api/v1/notes/autosave` — универсальный эндпоинт автосохранения:
  - **Создание черновика**: если `id` отсутствует или равен `00000000-0000-0000-0000-000000000000`, сервер создаёт новую заметку со статусом `201 Created` и `version = 1`.
  - **Автосохранение существующей заметки**: если передан `id`, сервер обновляет заголовок, текст, `content_doc`, цвет, теги и папку.
  - **Оптимистичная блокировка**: для обновления существующей заметки обязательна `version > 0`. При несовпадении возвращается `409 Conflict` с расширенными сведениями `server_note` (текущий текст, заголовок, документ и версия сервера), что позволяет клиенту разрешить конфликт без потери введённых данных.
  - JSON ограничен 4 МиБ (включая запросы с неизвестной длиной тела), заголовок — 4096 байт. Цвет проверяется так же, как при обычном обновлении.
  - **Защита корзины**: попытка автосохранения или обновления (`PATCH /notes/{id}`) заметки, находящейся в корзине (`is_deleted = true`), отклоняется с ошибкой `400 Bad Request` («cannot autosave note in trash; restore it first»).
- `PUT /api/v1/notes/{id}/autosave` — автосохранение конкретной заметки по идентификатору в URL.

### Хранение в корзине и откат (Trash & Restore)
- `GET /api/v1/notes/trash` — постраничный список удалённых заметок текущего пользователя, отсортированный по времени удаления `COALESCE(deleted_at, updated_at) DESC`. Поддерживает поиск `?q={query}`, ограничение `?limit={n}` и пагинацию курсором `?cursor={cursor}`.
- `GET /api/v1/notes/trash/count` — получение количества заметок, находящихся в корзине пользователя (`{"count": N}`).
- `DELETE /api/v1/notes/{id}` — перемещение заметки в корзину (soft-delete):
  - Выставляет `is_deleted = true`, фиксирует `deleted_at = NOW()`, сбрасывает `is_pinned = false`.
  - Рассчитывает дату окончания срока восстановления `expires_at = deleted_at + 30 days`.
  - Инкрементирует версию и логирует аудит-событие `delete`.
- `POST /api/v1/notes/{id}/restore` и `POST /api/v1/notes/trash/{id}/restore` — восстановление (откат удаления) заметки из корзины:
  - Проверяет, что заметка действительно находится в корзине.
  - Проверяет срок удержания (30 дней): если срок истёк, возвращает ошибку `400 Bad Request`.
  - Если исходная папка заметки была удалена, восстанавливает заметку в корень (`folder_id = NULL`), предотвращая ошибки внешнего ключа.
  - Сбрасывает флаги: `is_deleted = false`, `deleted_at = NULL`, `expires_at = NULL`.
  - Инкрементирует версию и логирует аудит-событие `restore`.
  - Поддерживает как явную передачу `{"version": N}`, так и вызов без тела для быстрого отката по уведомлению в UI.
- `DELETE /api/v1/notes/trash` и `POST /api/v1/notes/trash/empty` — полная очистка корзины:
  - Безвозвратно удаляет все помеченные как удалённые заметки пользователя.
  - Блокирует конкретный набор заметок в транзакции; одновременное восстановление не может привести к удалению файлов сохранённой заметки.
  - Ставит связанные вложения и фотографии в долговечную очередь очистки объектного хранилища. Очистка асинхронная, при сбое повторяется, в том числе после перезапуска сервера.
  - Возвращает количество очищенных заметок: `{"purged_count": N}`.
- `DELETE /api/v1/notes/{id}/hard` и `DELETE /api/v1/notes/trash/{id}` — окончательное физическое удаление конкретной заметки из корзины.
  - Активные заметки удалить этим способом нельзя. Состояние и версия проверяются под блокировкой строки.

Для очереди очистки обязательна миграция `20260929000900_note_object_cleanup.sql` перед запуском новой версии. Worker запускается вместе с API, обрабатывает до 20 объектов за проход и повторяет неудачные удаления через минуту. При остановке API завершает работу по общему контексту.

## 2. Примеры запросов и ответов

### Автосохранение нового черновика
```http
POST /api/v1/notes/autosave HTTP/1.1
Content-Type: application/json

{
  "title": "Черновик отчета",
  "content": "Начальный текст...",
  "type": "text"
}
```

Ответ `201 Created`:
```json
{
  "id": "c1f76d29-c731-4dd9-a590-7d63870624a9",
  "user_id": 1,
  "title": "Черновик отчета",
  "content": "Начальный текст...",
  "type": "text",
  "is_pinned": false,
  "is_archived": false,
  "is_favorite": false,
  "is_deleted": false,
  "version": 1,
  "created_at": "2026-09-29T12:00:00Z",
  "updated_at": "2026-09-29T12:00:00Z"
}
```

### Автосохранение существующей заметки при вводе
```http
POST /api/v1/notes/autosave HTTP/1.1
Content-Type: application/json

{
  "id": "c1f76d29-c731-4dd9-a590-7d63870624a9",
  "title": "Черновик отчета (дополнено)",
  "content": "Дополненный текст заметки во время набора...",
  "version": 1
}
```

Ответ `200 OK`:
```json
{
  "id": "c1f76d29-c731-4dd9-a590-7d63870624a9",
  "user_id": 1,
  "title": "Черновик отчета (дополнено)",
  "content": "Дополненный текст заметки во время набора...",
  "type": "text",
  "is_deleted": false,
  "version": 2,
  "created_at": "2026-09-29T12:00:00Z",
  "updated_at": "2026-09-29T12:00:05Z"
}
```

### Просмотр корзины
```http
GET /api/v1/notes/trash HTTP/1.1
```

Ответ `200 OK`:
```json
{
  "items": [
    {
      "id": "c1f76d29-c731-4dd9-a590-7d63870624a9",
      "user_id": 1,
      "title": "Удалённая заметка",
      "content": "Содержимое",
      "is_deleted": true,
      "deleted_at": "2026-09-29T12:10:00Z",
      "expires_at": "2026-10-29T12:10:00Z",
      "version": 3,
      "created_at": "2026-09-29T12:00:00Z",
      "updated_at": "2026-09-29T12:10:00Z"
    }
  ],
  "next_cursor": ""
}
```

### Восстановление заметки (Откат из корзины)
```http
POST /api/v1/notes/trash/c1f76d29-c731-4dd9-a590-7d63870624a9/restore HTTP/1.1
```

Ответ `200 OK`:
```json
{
  "id": "c1f76d29-c731-4dd9-a590-7d63870624a9",
  "user_id": 1,
  "title": "Удалённая заметка",
  "content": "Содержимое",
  "is_deleted": false,
  "deleted_at": null,
  "version": 4,
  "created_at": "2026-09-29T12:00:00Z",
  "updated_at": "2026-09-29T12:15:00Z"
}
```

### Очистка всей корзины
```http
DELETE /api/v1/notes/trash HTTP/1.1
```

Ответ `200 OK`:
```json
{
  "purged_count": 5
}
```

## 3. Миграция базы данных

Добавлена миграция `db/migrations/20260929000800_notes_reliability_trash_autosave.sql`:
- Создаёт частичный индекс `idx_notes_user_trash_deleted` для ускорения выборки и фильтрации корзины по `deleted_at`:
```sql
CREATE INDEX IF NOT EXISTS idx_notes_user_trash_deleted
    ON notes(user_id, deleted_at DESC, id DESC)
    WHERE is_deleted = TRUE;
```
