# NTS-001 — backend заметок с форматированием

Реализация расширяет существующий API заметок. Фронтенд не изменён.

## API

- `POST /api/v1/notes` — создание.
- `GET /api/v1/notes/{id}` и `GET /api/v1/notes` — получение и список.
- `PATCH /api/v1/notes/{id}` — редактирование с обязательной текущей `version`.
- `GET /api/v1/notes/sync`, `POST /api/v1/notes/sync/batch` — синхронизация.

Все маршруты требуют авторизации. Изменять заметку может только владелец, в том числе через batch-sync; получатель общей заметки имеет только право просмотра.

## Пример создания

```json
{
  "title": "План встречи",
  "type": "rich",
  "color": "#1687FF",
  "content_doc": {
    "type": "doc",
    "version": 1,
    "blocks": [
      {"id":"h1","type":"paragraph","runs":[{"text":"План","marks":["heading1","bold"]}]},
      {"id":"p1","type":"paragraph","runs":[{"text":"Важный текст","marks":["italic","color:#DC2626"]}]},
      {"id":"b1","type":"paragraph","list_type":"bullet","runs":[{"text":"Обсудить бюджет"}]},
      {"id":"n1","type":"paragraph","list_type":"ordered","runs":[{"text":"Подготовить отчёт"}]},
      {"id":"c1","type":"checklist","items":[{"id":"i1","text":"Отправить приглашение","checked":true}]}
    ]
  }
}
```

`list_type` — необязательный атрибут paragraph: `bullet` или `ordered`. Соседние элементы одного вида образуют список; отрисовка и нумерация выполняются клиентом. Отсутствие атрибута означает обычный абзац. Заголовки представлены marks `heading1`, `heading2`, `heading3` для совместимости с существующим форматированием клиента. Поддерживаются `bold`, `italic`, `strike`, проверенные `color:#RRGGBB` и `color:rgb(r, g, b)` (каналы 0–255).

## Цвет самой заметки

`color` хранится независимо от документа и цвета папки, возвращается в деталях, списках, синхронизации и ответах изменения.

- Отсутствие `color` при создании: `""` (без метки).
- PATCH без `color`: существующая метка сохраняется.
- PATCH с `"color":""`: снять метку.
- Значение цвета: строго `#RRGGBB`; произвольные CSS и HTML запрещены.
- Batch-sync без `color`: при изменении сохраняет метку, при создании оставляет пустой.

```json
{"version":1,"color":"#19B96B"}
```

Успешное изменение увеличивает `version`. Устаревшая версия возвращает существующий конфликт `NOTE_VERSION_CONFLICT` с серверной заметкой. `content_text` формируется сервером из `content_doc` для поиска; заголовки, текст списков и чекбоксов не теряются.

## Миграция и безопасность

Применить `db/migrations/20260929000600_notes_formatting_color.sql` перед запуском обновлённого приложения. Старые заметки получают пустой цвет. CHECK в PostgreSQL дополнительно ограничивает значение цвета. Структура документа, допустимые marks, размеры таблиц и чекбоксов проверяются сервером; произвольный HTML не является форматом paragraph.

Цвета текста с кавычками, CSS-инъекциями или URL отклоняются. Старые JSON-документы без новых атрибутов остаются совместимыми. Клиент по-прежнему обязан экранировать текст при HTML-отрисовке.

`go test ./internal/domain ./internal/service ./internal/handler ./internal/repository ./cmd/migrate`

Для production-пути на одноразовом PostgreSQL:

`TEST_MESSENGER_DATABASE_URL=<test DSN> go test ./internal/service -run TestNTS001Integration -count=1`

Интеграционный тест применяет реальные миграции, проверяет сохранение форматирования/цвета, очистку метки, список/синхронизацию, конфликт версии и запрет изменения чужой общей заметки.
