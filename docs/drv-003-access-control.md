# DRV-003 — права Drive

| Уровень | API | Читать/скачивать | Создавать/редактировать | Выдавать/отзывать доступ и ссылки |
|---|---|---|---|---|
| Просмотр | viewer | Да | Нет | Нет |
| Редактирование | editor | Да | Да | Нет |
| Управление доступом | manager (алиас owner) | Да | Да | Да |

Для совместимости ACL хранит и возвращает третью роль как `owner`; во входном role также принимается `manager`. Это делегированное управление, а не смена `owner_id`. Передать владение может только фактический владелец через отдельный маршрут; изменить/отозвать права фактического владельца через ACL нельзя. Правила согласования удаления из общей папки сохранены.

## Наследование

Права наследуются вниз от всех живых предков папки. Эффективное право — наиболее сильное из прямых и унаследованных. Прямой viewer не понижает унаследованный editor/owner. Отзыв прямого ACL не убирает права родителя: для полного отзыва требуется убрать источник на родителе. Отрицательных ACL/запрета наследования нет.

Право на отдельный файл не открывает родительскую папку, её остальные файлы или возможность загрузки в неё. Публичность папки даёт только viewer для потомков. После снятия публичности доступ пропадает, если нет другого прямого/унаследованного права. Просмотр ACL списка по существующему API доступен читателям ресурса; изменение — только менеджерам.

## API

База `/api/v1/drive`, требуется авторизация.

- POST/PUT `/permissions`: `{"resource_type":"folder","resource_id":"UUID","user_id":[42,43],"role":"manager"}`. Пользователи должны существовать; роль проверяется сервисом. Ответ 204.
- DELETE `/permissions`: существующий формат resource_type/resource_id/user_id; удаляет прямые права.
- GET `/permissions/my?resource_type=file&resource_id=UUID`: `{"role":"owner","can_view":true,"can_edit":true,"can_manage_access":true}`. Поле role сохранено, возможности добавлены. Без доступа role пустой, возможности false.
- POST `/share/link`: создание ссылки требует управления доступом; Editor больше не может выдавать доступ, включая ссылку owner. Отрицательный срок запрещён.
- DELETE `/share/link/{token}`: отзыв ссылки менеджером ресурса, 204. После отзыва публичное чтение/скачивание даёт 404.

Ссылки проверяют существование ресурса, срок и сохранение права управления у создателя при каждом чтении/скачивании/принятии. Потеря создателем управления делает ссылку недоступной. Принятие более слабой ссылки не понижает уже имеющееся прямое право. Ранее принятое по ссылке право становится обычным прямым ACL: отзыв ссылки сам по себе его не удаляет, используйте DELETE /permissions.

## Проверки

Интеграционный сценарий PostgreSQL/MinIO проверяет три уровня, запрет Editor выдавать права и создавать ссылки, наследование менеджера и viewer, отсутствие доступа вверх от отдельного файла, отзыв родительского права, сохранение наследования после отзыва прямого, публичный viewer, неизменность владения, несуществующих получателей, принятие слабой ссылки без понижения, отзыв ссылки и блокировку ссылки после потери прав создателем. Запуск — как DRV-001. Фронтенд и схема БД не изменяются.
