# DRV-004 — публичные ссылки

В настройках доступа доступны создание, копирование, список и отзыв ссылок.
Срок: 1 час, 1 день (по умолчанию), 7 дней, 30 дней или без ограничения.
Истёкшие ссылки остаются в списке до отзыва. Список разбит на страницы.

Управление доступно владельцу ресурса и пользователям с правом управления.
Токен — UUID v4, полученный из криптографического генератора случайных чисел.
Даты новых ссылок записываются в UTC, включая таблицу с полями TIMESTAMP.

Публичная страница `/web/drive/share/:token` открывается без входа. Ссылки дают
просмотр и скачивание; открытие и старый endpoint `accept` больше не создают
постоянные разрешения. Папки можно просматривать рекурсивно. При каждом запросе
проверяются токен в БД, срок, права создателя и принадлежность запрошенного
файла/папки поддереву общей папки. Перемещённый за пределы поддерева ресурс
через эту ссылку недоступен.

API (относительно `/api/v1`):

- `POST /drive/share/link`: `resource_type`, `resource_id`, `role`,
  `expires_in_sec` (0 — бессрочно); UI создаёт роль `viewer`.
- `GET /drive/share/link`: `resource_type`, `resource_id`, `limit`, `offset`.
- `DELETE /drive/share/link/:token`: отзыв, ответ 204.
- `GET /public/drive/items/:token`: метаданные, для папок — `children`.
- `GET /public/drive/files/:token/download`: скачивание.
- `GET|HEAD /public/drive/files/:token/preview`: встроенный просмотр.

Публичные endpoints принимают необязательную пару query-параметров
`resource_type` и `resource_id` для ресурса внутри общей папки. Частичные,
невалидные параметры и нулевой UUID отвергаются. Файловая ссылка не позволяет
обратиться к родительской папке или соседним файлам. Публичный `access_role`
всегда `viewer`; legacy-параметр создания `role` сохраняется для совместимости,
но не выдаёт права редактирования или управления.

Отзыв действует на следующий запрос, включая скачивание и Range/HEAD просмотра.
Ответы публичных endpoints используют `Cache-Control: no-store`,
`Referrer-Policy: no-referrer` и `X-Content-Type-Options: nosniff`.
Уже полученные байты и уже открытая сессия внешнего просмотрщика не отзываются.
Независимые разрешения пользователей остаются действующими. Постоянные ACL,
выданные старой реализацией `accept`, не имеют признака происхождения в БД:
при необходимости их следует отозвать в списке пользователей с доступом.

Проверки:

```sh
go test ./internal/service ./internal/handler ./internal/repository
TEST_MESSENGER_DATABASE_URL='postgres://.../test?sslmode=disable' \
  go test ./internal/service -run '^TestDrivePublicLinksIntegration$' -count=1 -v
```

Отдельный интеграционный тест создаёт и удаляет изолированную схему PostgreSQL;
MinIO не требуется. Проверяются уникальность токенов, точность срока после
чтения из БД, пагинация, ACL, отсутствие постоянного доступа после `accept`,
доступ к вложенным ресурсам, запрет выхода за пределы папки, перенос ресурса,
истечение и отзыв. Полный тест `TestDriveStructureIntegration` дополнительно
проверяет скачивание байтов с MinIO.
