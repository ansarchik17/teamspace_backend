# DOC-007 — импорт, экспорт и PDF

## Импорт

`POST /api/v1/docs/import`, Bearer, multipart/form-data:

- `file`: ровно один DOC/DOCX/XLS/XLSX/PPT/PPTX/PDF, не более 100 MiB;
- `folder_id`: необязательный UUID папки с правом editor.

Ответ 201 — обычный DriveFile с ID, MIME и начальной версией. Квоты Drive сохраняются. Файл записывается без перепаковки: стили, изображения и XML исходника не изменяются. Повторный импорт разрешён как независимый файл. Проверяются размер, расширение и базовая структура контейнера: основные части OOXML, сигнатура PDF/OLE. Это не полная проверка корректности документа; повреждённые или зашифрованные документы могут быть отклонены редактором/конвертером позднее.

DOCX/XLSX/PPTX открываются через editor-link. Старый формат можно экспортировать в соответствующий OOXML и импортировать результат как новый файл. PDF хранится в Drive и доступен для просмотра/скачивания.

## Экспорт

`GET /api/v1/docs/files/:id/export?format=pdf&version=3`, Bearer, минимум viewer.

Если `version` отсутствует, фиксируется актуальная сохранённая версия на начало запроса. Несохранённые изменения текущего редактора в экспорт не входят: перед экспортом проверить checkpoint из DOC-006 или дождаться сохранения.

| Исходник | Доступные результаты |
| --- | --- |
| DOC | DOC (оригинал), DOCX, PDF |
| DOCX | DOCX (оригинал), PDF |
| XLS | XLS (оригинал), XLSX, PDF |
| XLSX | XLSX (оригинал), PDF |
| PPT | PPT (оригинал), PPTX, PDF |
| PPTX | PPTX (оригинал), PDF |
| PDF | PDF (оригинал) |

Несовместимые преобразования, включая PDF → DOCX и DOCX → XLSX, возвращают 415. Нативный формат отдаётся из истории Drive без конвертации и изменения байтов.

Для конвертации используется асинхронный ONLYOFFICE `/converter`. Пока результат не готов, API возвращает 202, `Retry-After: 2` и `{"status":"processing","version":3}`. Повторять запрос **с полученной version**, чтобы новые сохранения не переключили экспорт на другой снимок. Ключ операции стабилен для file_id/версии/исходного/целевого формата, хранение очереди и результата обеспечивает DocumentServer.

Ответ 200 содержит файл, корректный Content-Type, attachment filename, `X-Document-Version` и `Cache-Control: no-store`. Источник, его версии и сессия не меняются. Результат не создаётся в Drive автоматически. Скачать можно и историческую версию. Экспорт фиксируется в существующем аудите скачиваний; загрузка исходника самим DocumentServer также может создать событие скачивания.

Перед выдачей сконвертированного файла заново проверяются права и наличие источника. Размер исходника для конвертации и результата ограничен 100 MiB; данные буферизуются во временном файле, который удаляется после ответа/ошибки. Ошибки: 404 нет версии, 413 превышен размер, 422 отказ движка (числовой conversion_error), 502 некорректный ответ/недоступность, 503 нет адреса сервера, 504 таймаут/отмена. Повтор после таймаута должен указывать ту же версию. Общее время одной операции ограничено 120 секундами; меньшие таймауты API/прокси/клиента имеют приоритет.

## Настройка

`ONLYOFFICE_INTERNAL_URL` — абсолютный HTTP(S) адрес DocumentServer, доступный бэкенду. Если не задан, используется абсолютный `ONLYOFFICE_PUBLIC_URL`; относительного `/onlyoffice` недостаточно. Docker overlay задаёт `http://workspace-onlyoffice`. `ONLYOFFICE_DOWNLOAD_BASE_URL` — обратный адрес API для загрузки исходника сервером документов. JWT использует существующий `ONLYOFFICE_JWT_SECRET`; секрет должен совпадать с DocumentServer.

Результат принимается только с того же origin, что настроенный адрес конвертера. HTTP-редиректы не выполняются: подписанный исходный URL/JWT не перенаправляются на посторонний сервер. Прокси DocumentServer должен возвращать fileUrl с доступным бэкенду origin, соответствующим настройке. Клиент API не передаёт произвольные URL.

Новых миграций нет. API и Swagger готовы; фронтенд приложения и рабочий DocumentServer не менялись.

## Стили и приёмка

При импорте и скачивании исходного формата сохранность байтов проверяется автоматически. Конвертация выполняется офисным движком, без промежуточного HTML/текста. Для таблиц учитывается заданная область печати (`ignorePrintArea=false`), регион отображения — ru-RU. Остальная компоновка определяется документом и движком.

Утверждение «без потери стилей» для всех файлов пока не подтверждено: нужны реальные шрифты компании на DocumentServer и визуальная проверка на согласованной версии движка. Сложные формулы, диаграммы, переходы/анимации и динамические поля могут не иметь эквивалента в статическом PDF. PDF → редактируемый документ не реализован.

Автотесты с PostgreSQL и HTTP-имитацией ONLYOFFICE/S3 проверяют сохранность исходника, MIME, матрицу форматов, подписанный запрос и версию download-токена, 202 → 200 с неизменным ключом, отказ движка, неподходящее содержимое результата, запрещённый origin, отзыв ACL во время конвертации и ограничения импорта. Эти тесты не подтверждают визуальное качество PDF.

Ручная приёмка на настоящем DocumentServer: DOCX с фирменными стилями/таблицами/изображениями/колонтитулами; XLSX с формулами/диаграммами/областями печати; PPTX с темой/нестандартными шрифтами/изображениями. Сравнить итоговые PDF с эталонами, проверить старые DOC/XLS/PPT → OOXML, казахский/русский текст и экспорт прошлой версии во время редактирования. Этот прогон ещё не выполнен.

Протокол: [Conversion API](https://api.onlyoffice.com/docs/docs-api/additional-api/conversion-api/request/).
