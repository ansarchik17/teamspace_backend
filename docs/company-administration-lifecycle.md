# BAS-017 BE-02: компании и назначение директора

Все endpoints требуют Bearer JWT и актуальную активную серверную роль `admin`.
Директор компании не имеет доступа к этим операциям.

| Действие | Endpoint | Тело |
| --- | --- | --- |
| Создать компанию без директора | POST /api/v1/platform/organizations | `{"name":"Компания","slug":"company"}` |
| Приостановить компанию | PATCH /api/v1/platform/organizations/:id | `{"status":"suspended"}` |
| Возобновить компанию | PATCH /api/v1/platform/organizations/:id | `{"status":"active"}` |
| Изменить название | PATCH /api/v1/platform/organizations/:id | `{"name":"Новое название"}` |
| Назначить или сменить директора | PUT /api/v1/platform/organizations/:id/owner | `{"user_id":123}` |
| Найти кандидатов | GET /api/v1/platform/organizations/owner-candidates | query: `organization_id`, `q`, `limit` |

Директор — `organizations.owner_id`. Смена владельца и прикрепление нового
директора к компании выполняются в одной транзакции. Допускается активный
сотрудник этой компании или пользователь без компании. Пользователь другой
компании, удалённый/неактивный пользователь и администратор платформы не
могут быть назначены. При отказе владелец и данные сотрудника не меняются.

Предыдущий директор остаётся сотрудником, но теряет административные права.
Глобальная роль пользователя не меняется. Назначение сотрудника своей компании
сохраняет его подразделение и руководителя; повторное назначение также безопасно.

На время изменения проверяется и блокируется актуальная роль инициатора.
Назначение директора и изменение статуса сериализуются блокировкой компании.
Приостановка блокирует доступ директора к административным операциям своей
компании; платформа сохраняет возможность восстановить компанию и сменить
директора. После восстановления назначенный директор снова получает доступ.

Существующие URL и форматы ответов сохранены. Ошибки используют контракт
BAS-010: `FORBIDDEN` / 403 при отсутствии прав, `NOT_FOUND` / 404 для отсутствующих
объектов, `CONFLICT` / 409 для недопустимого назначения, `VALIDATION_ERROR` / 400
для неверных входных данных. Конкретные коды следует сверять с общим каталогом
`docs/localization-api-contract.md`.
