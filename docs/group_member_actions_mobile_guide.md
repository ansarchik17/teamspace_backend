# Руководство по интеграции групповых действий для мобильных приложений (Android / iOS)

В этом документе подробно описано, как в мессенджере реализована отправка сообщений и синхронизация в реальном времени при добавлении, выходе или удалении пользователей из групповых чатов.

---

## 1. Архитектурная концепция: Сервисные сообщения (Service Messages)

Вместо того чтобы слать разрозненные WebSocket-сигналы, которые мобильное приложение должно обрабатывать вне истории чата, бэкенд использует концепцию **системных/сервисных сообщений** (Service Messages).

Когда происходит групповое действие (добавление участника, выход или удаление), бэкенд:
1. Автоматически выполняет действие с базой данных (добавляет/удаляет запись о членстве).
2. Формирует специальное сообщение в таблицу сообщений с типом `"text"`.
3. Записывает в поле `metadata` сериализованную JSON-строку с признаком `"is_service": true` и типом действия.
4. Отправляет это сообщение через WebSocket (событие `new_message`) всем участникам группы, включая тех, кого это коснулось.

### В чём преимущество этой архитектуры?

* **Обратная совместимость (Graceful Degradation):** Если старая версия приложения не знает о новых полях метаданных, она просто отобразит системное сообщение как стандартное текстовое сообщение с человекочитаемым текстом (например, *"Иван Иванов вышел из группы"*). Приложение не упадет и пользователь увидит корректную историю.
* **Кастомизация интерфейса (Premium UI):** Новые версии мобильного приложения могут распарсить строку `metadata`, увидеть `"is_service": true`, скрыть стандартный пузырь сообщения (bubble), аватарку отправителя, выровнять текст по центру экрана и отобразить его в красивом системном стиле.
* **Персистентность истории:** Системные сообщения хранятся в общей истории сообщений. При прокрутке истории (через GET-запрос истории) они придут ровно в те моменты времени, когда происходили действия.

## 2. Формат данных сервисного сообщения

Любое системное сообщение приходит в виде объекта `MessageView` (расширяющего `Message`), в котором:
* `"type"`: `"text"`
* `"metadata"`: JSON-строка (escape-последовательности) с метаданными.

### Структура JSON внутри поля `metadata`:
```json
{
  "is_service": true,
  "system_type": "add_member" | "remove_member" | "leave_group"
}
```

### Пример полного объекта сообщения (из API или WebSocket `new_message`):

```json
{
  "id": "7fa123d2-45e3-4f89-8dcb-129cd5f488a1",
  "conversation_id": "c30fa51b-4d43-41bb-b5bf-7cb96417775a",
  "sender_id": 10,
  "content": "Аскар Абылхаиров добавил Арман Арманов в группу",
  "type": "text",
  "metadata": "{\"is_service\":true,\"system_type\":\"add_member\"}",
  "created_at": "2026-05-18T14:30:00Z",
  "sender_username": "askar",
  "sender_full_name": "Askar Abylkhaiyrov",
  "sender_avatar": "https://host/avatars/askar.png",
  "reactions": []
}
```

## 3. Детальный разбор сценариев

### Сценарий 1: Добавление участника (Add Member)

**Инициатор:** Владелец группы (`owner`) или Администратор (`admin`).

#### REST API запрос
```http
POST /api/v1/groups/{group_id}/members
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json
X-Device-ID: <DEVICE_ID>
```

**Body:**
```json
{
  "user_ids": [77, 98]
}
```
*(Также поддерживается старый формат с одним `"user_id": 77`, но для мобильных рекомендуется использовать массив `"user_ids"`).*

#### Что происходит на бэкенде:
1. Выполняются проверки на права доступа (`owner` / `admin`) и лимит участников группы.
2. Новые участники добавляются в БД в таблицу членов группы.
3. Бэкенд генерирует системное текстовое сообщение:
   * Текст сообщения (`content`): `"<Имя инициатора> добавил <Имя нового участника> в группу"`
   * Метаданные (`metadata`): `{"is_service":true,"system_type":"add_member"}`
4. Системное сообщение записывается в БД.
5. Бэкенд рассылает WebSocket-событие `new_message` **всем текущим участникам группы**, включая только что добавленных пользователей.
6. **Резервный канал:** Для добавленного пользователя (`newMemberID`) отправляется отдельное WebSocket-событие `"added_to_group"`. Это нужно на случай, если у добавленного пользователя ещё не загружен список чатов в кэше — так мобильное приложение сразу узнает, что нужно получить детали нового группового чата и добавить его в UI списка чатов.

#### Пример WebSocket события `added_to_group` для добавленного пользователя:
```json
{
  "type": "added_to_group",
  "to": 77,
  "conversation_id": "c30fa51b-4d43-41bb-b5bf-7cb96417775a",
  "title": "Added to group",
  "body": "You have been added to a new group",
  "category": "group",
  "timestamp": 1775037900,
  "content": {
    "group_id": "c30fa51b-4d43-41bb-b5bf-7cb96417775a",
    "user_id": 77,
    "action": "added"
  }
}
```

### Сценарий 2: Выход из группы (Leave Group)

**Инициатор:** Сам участник, который хочет выйти.

#### REST API запрос
```http
POST /api/v1/groups/{group_id}/leave
Authorization: Bearer <ACCESS_TOKEN>
X-Device-ID: <DEVICE_ID>
```

#### Что происходит на бэкенде:
1. Выполняются проверки. **Критическое ограничение:** Владелец группы (`owner`) не может просто так выйти из группы, не передав права владельца другому участнику или не удалив группу целиком (возвращается `403 Forbidden`).
2. Составляется список участников **до удаления** пользователя из группы.
3. Бэкенд удаляет пользователя из участников группы в БД.
4. Генерируется системное сообщение:
   * Текст сообщения (`content`): `"<Имя пользователя> вышел из группы"`
   * Метаданные (`metadata`): `{"is_service":true,"system_type":"leave_group"}`
5. Сообщение сохраняется в БД.
6. Бэкенд рассылает событие `new_message` по списку участников, который был зафиксирован **до выхода** (это значит, что сам выходящий пользователь тоже получит это сообщение по WebSocket и поймет, что процедура выхода завершена).

---

### Сценарий 3: Удаление (кик) участника (Remove Member)

**Инициатор:** Владелец группы (`owner`) или Администратор (`admin`).

#### REST API запрос
```http
DELETE /api/v1/groups/{group_id}/members/{target_user_id}
Authorization: Bearer <ACCESS_TOKEN>
X-Device-ID: <DEVICE_ID>
```

#### Что происходит на бэкенде:
1. Выполняется проверка прав. Только `owner` или `admin` могут удалять участников. Владельца группы удалить нельзя.
2. Составляется список участников **до удаления** пользователя.
3. Бэкенд удаляет указанного участника из БД.
4. Генерируется системное сообщение:
   * Текст сообщения (`content`): `"<Имя инициатора> удалил <Имя удаленного> из группы"`
   * Метаданные (`metadata`): `{"is_service":true,"system_type":"remove_member"}`
5. Сообщение сохраняется в БД.
6. Бэкенд рассылает событие `new_message` по WebSocket всем участникам по списку, зафиксированному **до удаления**. Удаленный пользователь также получает это событие, благодаря чему его мобильный клиент мгновенно узнает, что его выгнали, и может ограничить интерфейс.

## 4. Как обрабатывать эти события на мобильном клиенте

Ниже приведены практические рекомендации по реализации логики на клиенте для Android и iOS.

### 4.1. Парсинг `metadata`
При получении сообщения (через HTTP-историю или WebSocket `new_message`) всегда проверяйте поле `metadata`:
1. Если `metadata == null` или пустой — это обычное текстовое сообщение.
2. Если `metadata` не пустой, попробуйте его десериализовать.
3. Если после десериализации вы обнаружили `"is_service": true`:
   * Не отображайте аватарку и имя отправителя слева/справа.
   * Не рисуйте стандартное облачко сообщения.
   * Отцентруйте текст `content` по горизонтали.
   * Сделайте шрифт меньше и используйте приглушённый цвет текста (например, серый).
   * Опционально добавьте красивую закруглённую полупрозрачную подложку вокруг текста.

### Пример UI-компонента на Kotlin (Jetpack Compose):
```kotlin
@Composable
fun MessageItem(message: MessageView) {
    val serviceMeta = remember(message.metadata) {
        parseServiceMetadata(message.metadata)
    }

    if (serviceMeta?.isService == true) {
        // Системное сообщение по центру
        Box(
            modifier = Modifier
                .fillMaxWidth()
                .padding(vertical = 8.dp),
            contentAlignment = Alignment.Center
        ) {
            Card(
                colors = CardDefaults.cardColors(containerColor = MaterialTheme.colorScheme.surfaceVariant.copy(alpha = 0.6f)),
                shape = RoundedCornerShape(12.dp)
            ) {
                Text(
                    text = message.content ?: "",
                    style = MaterialTheme.typography.bodySmall,
                    color = MaterialTheme.colorScheme.onSurfaceVariant,
                    modifier = Modifier.padding(horizontal = 12.dp, vertical = 6.dp),
                    textAlign = TextAlign.Center
                )
            }
        }
    } else {
        // Обычный пузырь сообщения (слева или справа)
        StandardMessageBubble(message)
    }
}
```

### 4.2. Обработка удаления или выхода текущего пользователя
Когда текущий авторизованный пользователь выходит из группы сам или его удаляет администратор, по WebSocket прилетит системное сообщение, где:
* `system_type` равно `"leave_group"` или `"remove_member"`
* Идентификатор того, кого коснулось действие (вы можете узнать это по тексту или запросить обновлённый список участников, либо отслеживать событие в WebSocket).
* **Событие `new_message`:** Бэкенд присылает сообщение, где `SenderID` — это инициатор удаления, а текст содержит информацию о выходе/кике.

**Что делать в UI чата, если текущий пользователь больше не состоит в группе:**
1. Заблокировать поле ввода текста (`EditText` / `TextField`).
2. Вместо поля ввода отобразить плашку: *"Вы больше не являетесь участником этой группы"*.
3. Скрыть кнопку вызова звонка и меню настроек группы (за исключением опции "Удалить чат").

### 4.3. Синхронизация списка чатов при получении `added_to_group`
Когда пользователя добавляют в новую группу, на мобилку приходит WebSocket событие `"added_to_group"`:
1. Извлеките `group_id` из поля `content.group_id`.
2. Вызовите REST-запрос `GET /api/v1/groups/{group_id}`, чтобы загрузить актуальные данные этой группы (название, аватарку, список участников).
3. Добавьте полученный групповой чат в локальный список чатов (в базу данных Room/Realm) и обновите экран списка чатов с плавной анимацией появления.
