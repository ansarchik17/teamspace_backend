# Приёмка прав и ЭДО — задача 10

Дата: 22.10.2026. Проверены локальные рабочие копии; это не акт приёмки развёрнутой системы. Коммиты, публикация образов и развёртывание не выполнялись. Порядок выпуска: [access-rollout.md](access-rollout.md).

## Матрица ролей

Роль в таблице — участие в процессе и явно выданный набор должности. Название должности не назначает участника маршрута. Любое действие дополнительно ограничено компанией, документом, текущим этапом и назначением. Для обычного чтения нужен один из `document.read`, `document.read_department`, `document.read_all`; широкое чтение не даёт полномочий согласующего или подписанта.

| Участник | Разрешение при корректных условиях | Запреты |
| --- | --- | --- |
| Автор | `document.create`; изменение своего черновика/доработки с `document.update`; вложения с `attachment.upload` | Чужой черновик; изменение после подписи; регистрация, решение и подпись без отдельных прав/назначений |
| Регистратор | `document.register`, доступный документ, допустимое резервирование/назначение; управление маршрутом в разрешённом состоянии | Повторная регистрация подписанного документа; пропуск этапов; изменение активного маршрута |
| Согласующий | Текущий участник этапа и `approval.approve`; возврат/отказ требуют отдельных прав | Решение за другого, будущий этап, самосогласование автора, повторное противоречащее решение |
| Исполнитель | Текущий исполнитель, `assignment.read` + `assignment.complete`, доступ к документу; обязательный результат | Выполнение чужого/переназначенного поручения; обход revision; выполнение закрытого/отменённого поручения |
| Подписант | Назначенный подписант, `signature.sign`, чтение документа/содержимого; допустимый этап и метод подписи | Самоподпись автора, подмена лица, сертификат без подписи; отказ без `signature.reject` |
| Наблюдатель | Чтение выданного по ACL документа с `document.read` | Создание, регистрация, решения, выполнение, подпись, экспорт без соответствующих прав |
| Без прав | Нет рабочих операций, даже при старой роли admin или сохранённом ACL | Прямой URL/API не обходит отсутствие набора; владение компанией не выдаёт рабочие права |

Для всех семи ролей новые тесты проверяют чтение своего доступного документа, отказ для закрытого от пользователя документа своей компании, другой компании (включая совпадающий user ID и ACL), отсутствие доступа после отзыва чтения. Отдельная HTTP-матрица проверяет допустимый вход в обработчик и запрет остальных операций, повторяя запросы с тем же токеном после отзыва набора. Подмена `X-Organization-ID` не меняет доверенную компанию. Успешный вход в обработчик в этом тесте не равен успешной бизнес-операции: изменение состояния проверяют интеграционные lifecycle/command/signing тесты.

Директор и суперадмин сохраняют административное назначение людей в своей разрешённой области Workspace. Уточнение от 27.10.2026: действующий владелец получает все реализованные рабочие права сервисов своей компании автоматически. Суперадмин и должность «директор» без владения этого исключения не получают.

## Повторяемый локальный gate

Из `workspace-front` выполнить `node scripts/test-access-acceptance.cjs`. Перед запуском указать:

```powershell
$env:ODO_TEST_DATABASE_DISPOSABLE = 'true'
$env:TEST_MESSENGER_DATABASE_URL = '<DSN отдельной одноразовой PostgreSQL>'
$env:TEST_WORKFLOW_DATABASE_URL = '<DSN отдельной workflow-БД с миграциями ЭДО>'
$env:ODO_TEST_WORKSPACE_REPO = '<абсолютный путь workspace-backend>'
$env:ODO_TEST_SOURCE_REPO = '<абсолютный путь проверяемого backend ЭДО>'
$env:ODO_TEST_FRONTEND_REPO = '<абсолютный путь проверяемого frontend ЭДО>'
$env:ACCESS_CONTRACT_SD_REPO = '<абсолютный путь backend SenimDesk>'
$env:ACCESS_CONTRACT_IFORM_REPO = '<абсолютный путь корня iform>'
node scripts/test-access-acceptance.cjs
```

Runner включает проверки доступа Workspace и реестра миграций, полный `go test ./...` ЭДО, frontend-сценарии Workspace, TypeScript обоих фронтендов, все Vitest-тесты ЭДО и локализацию. Любой фактический skipped test, ошибка или отсутствие тестов блокирует успех. Пакеты без test files не считаются пропущенным тестом. Тесты Workspace отобраны по доступу/интеграции; это не полный запуск всех AI/прочих пакетов Workspace. DSN, токены и тела результата runner не печатает. iForm DSN внутри gate указывает на одноразовую БД и отдельные схемы; самостоятельному iForm Java-тесту нужна своя пустая БД.

Дополнительные проверки:

```powershell
# В backend SenimDesk:
go test ./internal/delivery/http ./internal/delivery/http/middleware ./internal/usecase ./internal/repository/postgres -run 'Test.*(Workspace|Managed|ExactPermission|ClientTypeCRUD)' -count=1
# В iform/backend; JDK >= 21, отдельная пустая PostgreSQL:
# IFORM_TEST_JDBC_URL, IFORM_TEST_DB_USER, IFORM_TEST_DB_PASSWORD задать вне отчёта.
mvn '-Dtest=WorkspaceSecurityTest,WorkspaceOperationsTest,WorkspaceIntegrationTest' test
# В frontend ЭДО, путь указывает на Swagger именно проверяемого backend:
# BACKEND_OPENAPI_PATH=<backend ЭДО>/internal/bff/handler/docs/documentolog.swagger.json
npm run api-contract-check
```

Java-набор iForm выполнен: 15 тестов, 0 failures/errors/skipped, включая реальные Flyway/Flowable и локальный авторитетный источник Workspace. В SenimDesk прошли затронутые HTTP/middleware/usecase-тесты; в repository/postgres по выбранному фильтру тестов нет. Это не полная приёмка всех операций СД.

## Браузер

Проверен настоящий `AssignmentsPanel` и `useAssignments` Workspace с изолированным синтетическим API: обязательный результат, временный 503, восстановление формы после reload, повтор сохранённой команды, receipt до source update, последующее обновление статуса, 409 и отдельное создание новой команды, отзыв права в открытой форме, сохранение текста и блокировка отправки. Ширина 390 px проверена отдельно. Контрольные элементы тестового API не входят в продукт.

Это не проверка всех семи пользователей в развёрнутом UI ЭДО. Для неё остаётся обязательная стендовая матрица из инструкции выпуска: реальные пользовательские сессии, handoff/JWT, межсервисная сеть, редакторы, sender и подпись через установленного провайдера.
