# BE-04: системные и push-уведомления

Язык выбирается из профиля адресата (`users.language`), с fallback на `ru`.
Язык инициатора HTTP-запроса и `language` внешней системы не переопределяют
язык получателя серверного шаблона.

Переводы находятся в `internal/i18n/system_notifications.json`. Покрыты
приглашения, изменения, отмены и напоминания календаря; назначение, создание
и сроки задач; доступ, владение и согласование удаления на диске; звонки;
системные превью сообщений, упоминания, письма и срочные публикации;
уведомления о входе в веб-клиент. Внешние события используют общий каталог
`catalog.json`.

Для `CreateNotificationRequest` серверный заголовок и текст задаются через
`TitleTemplate` / `ContentTemplate` (`domain.NotificationTemplate`). `Source`
идентифицирует шаблон, а `Args` содержит параметры. Значения параметров,
например имена людей и названия встреч, не переводятся. Серверные параметры
(тип ресурса, роль) помечаются `NotificationLabel`; время до встречи —
`NotificationCountdown`. Новые шаблоны должны иметь версии `ru` и `kk`.

Шаблон рендерится отдельно для `UserID` до сохранения уведомления. Один и тот
же текст используется для списка уведомлений, WebSocket и push. В metadata
сохраняется `language`; исходная map вызывающего кода не изменяется.
Тексты уже сохранённых уведомлений не переводятся заново при смене языка.

Звонки и прямые push проходят отдельные пути, где язык тоже определяется
по получателю. Для iOS alert и Android data используются локализованные
заголовок и текст; идентификаторы событий, ссылки и технические поля
сохраняют свой формат. Пользовательский контент чатов, каналов и публикаций
не переводится.

Миграции БД не требуются. Тесты проверяют выбор языка разных получателей,
fallback, сохранность пользовательских параметров, шаблоны звонков, единицы
времени и наличие двух версий отмеченных серверных шаблонов.
