# MSG-005 — Статусы сообщений, счётчики непрочитанного

Документ описывает backend-контракт для web/mobile frontend: статусы доставки и прочтения, счётчики непрочитанного, бейджи и WebSocket-события.

## Общие правила

- Base URL: `/api/v1`.
- Все HTTP-запросы требуют `Authorization: Bearer <access_token>`.
- WebSocket: `/ws?token=<access_token>`.
- UUID передаются строкой.

---

## 1. Поля статуса в объекте сообщения

Каждый объект `MessageView` в ответе содержит:

| Поле | Тип | Описание |
|---|---|---|
| `is_read` | `bool` | `true` — хотя бы один получатель прочитал сообщение |
| `read_by_count` | `int` | Количество участников, прочитавших сообщение |
| `delivered_count` | `int` | Количество участников, которым сообщение доставлено |

**Рекомендованная логика бейджей (аналог Telegram):**

- Одна галочка (`✓`) — сообщение отправлено на сервер.
- Две галочки (`✓✓`) — `delivered_count >= 1`: доставлено хотя бы одному получателю.
- Две синие галочки (`✓✓`) — `is_read == true`: хотя бы один получатель прочитал.

Для личных чатов (2 участника) это полностью соответствует поведению Telegram/WhatsApp.
Для групп `read_by_count` показывает точное число прочитавших.

---

## 2. Отметить сообщение как доставленное

```http
POST /api/v1/messages/{message_id}/delivered
```

Frontend вызывает этот endpoint, когда пользователь получил сообщение (например, при открытии чата или после получения push-уведомления в фоне).

**Ответ `200`:**
```json
{"message": "marked as delivered"}
```

Сервер отправляет событие `delivery_receipt` отправителю только при первом успешном подтверждении. Повторный запрос идемпотентен и не создаёт повторное событие.

> **Примечание.** При отправке сообщения онлайн-получателям статус `delivered` проставляется автоматически — вызов этого endpoint нужен только для офлайн-получателей (при следующем открытии приложения).

---

## 3. Отметить сообщение как прочитанное

```http
POST /api/v1/messages/{message_id}/read
```

Отмечает как прочитанные все сообщения в данном чате/группе **до указанного включительно**.

Работает для личных чатов, групп и каналов (для каналов используйте `POST /channels/posts/:post_id/view`).

**Ответ `200`:**
```json
{"message": "marked as read"}
```

После вызова:
- Счётчик непрочитанных пересчитывается. При частичном прочтении более новые сообщения остаются непрочитанными.
- Автору каждого впервые прочитанного сообщения приходит отдельное WebSocket-событие `read_receipt`.
- Всем устройствам читателя приходит `unread_count_updated`.

## 4. WebSocket-события

### 4.1 `delivery_receipt` — доставка

Приходит **отправителю** сообщения, когда получатель получил его через WebSocket (онлайн) или явно вызвал `POST /delivered`.

```json
{
  "type": "delivery_receipt",
  "from": 42,
  "to": 10,
  "message_id": "11111111-1111-1111-1111-111111111111",
  "conversation_id": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
  "content": {
    "delivered_count": 1
  },
  "timestamp": 1790157600
}
```

| Поле | Описание |
|---|---|
| `from` | ID пользователя, которому доставлено |
| `to` | ID отправителя сообщения |
| `message_id` | ID сообщения |
| `conversation_id` | ID чата/группы |

**Действие фронтенда:** присвоить сообщению абсолютное значение `content.delivered_count`. Не выполнять `+1`: повторная или переупорядоченная доставка WebSocket-событий не должна искажать счётчик.

---

### 4.2 `read_receipt` — прочтение

Приходит **отправителю** сообщения, когда получатель вызвал `POST /read`.

```json
{
  "type": "read_receipt",
  "from": 42,
  "to": 10,
  "message_id": "11111111-1111-1111-1111-111111111111",
  "conversation_id": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
  "content": {
    "read_by_count": 1,
    "is_read": true
  },
  "timestamp": 1790157600
}
```

| Поле | Описание |
|---|---|
| `from` | ID пользователя, прочитавшего |
| `to` | ID отправителя сообщения |
| `message_id` | Конкретное сообщение, впервые отмеченное прочитанным |
| `conversation_id` | ID чата/группы |

**Действие фронтенда:** присвоить указанному сообщению абсолютные значения `content.is_read` и `content.read_by_count`. Один вызов `/read` может породить несколько событий — по одному для каждого впервые прочитанного сообщения и его автора. Повторный HTTP-запрос событий не создаёт.

---

### 4.3 `unread_count_updated` — бейдж непрочитанных

Приходит **всем устройствам пользователя**, вызвавшего `POST /read`, для синхронизации бейджа на других вкладках/устройствах.

```json
{
  "type": "unread_count_updated",
  "to": 42,
  "conversation_id": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
  "content": {
    "conversation_id": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
    "unread_count": 3
  },
  "timestamp": 1790157600
}
```

**Действие фронтенда:** присвоить абсолютный счётчик непрочитанных в заголовке/списке чатов. Значение не обязательно равно нулю при частичном прочтении.

---

## 5. Счётчик непрочитанных (`unread_count`)

### 5.1 Личные чаты

Счётчик хранится в таблице `conversation_participants.unread_count`.

- **Увеличивается** автоматически при каждом новом входящем сообщении.
- **Пересчитывается** при вызове `POST /messages/:id/read`; сообщения новее указанного остаются в счётчике.

Поле `unread_count` возвращается в `ConversationView` (список чатов `GET /chats/unified`).

### 5.2 Группы

Счётчик вычисляется динамически: количество сообщений группы, у которых **нет** записи `message_status.read_at` для данного пользователя.

- **Пересчитывается** автоматически при вызове `POST /messages/:id/read` (строки `message_status` вставляются только для впервые прочитанных сообщений).

Поле `unread_count` возвращается в `GroupView`.

### 5.3 Каналы

Счётчик вычисляется из таблицы `channel_post_views`: число постов, не попавших в `channel_post_views` для данного пользователя.

- **Обнуляется** при вызове `POST /channels/posts/:post_id/view` для каждого просмотренного поста.

Поле `unread_count` возвращается в `ChannelView`.

## 6. Просмотр читателей сообщения

Для группового чата можно получить список тех, кто прочитал конкретное сообщение:

```http
GET /api/v1/messages/{message_id}/viewers
```

```json
[
  {
    "user_id": 42,
    "full_name": "Анна Иванова",
    "avatar_url": "https://...",
    "read_at": "2026-09-23T12:00:00Z"
  }
]
```

Для постов канала:

```http
GET /api/v1/channels/posts/{post_id}/viewers
```

## 7. Ошибки

```json
{
  "error": {
    "code": "MESSAGE_NOT_FOUND",
    "message": "message not found",
    "user_message": "Сообщение не найдено."
  }
}
```

| HTTP | `error.code` | Смысл |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Неверный UUID |
| 401 | `UNAUTHORIZED` | Нет/неверный токен |
| 403 | `FORBIDDEN` / `NOT_PARTICIPANT` | Пользователь не состоит в чате/группе либо отправитель пытается подтвердить доставку собственного сообщения |
| 404 | `MESSAGE_NOT_FOUND` | Сообщение не существует |
