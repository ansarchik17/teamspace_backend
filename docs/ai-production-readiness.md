# Подготовка ИИ-учёта без production-контрактов

## Что готово и что остаётся внешним условием

Автоматического read-only lookup API Nitec в предоставленных материалах нет. Нельзя восстановить расход по таймауту, повторить генерацию для проверки или считать неизвестный исход бесплатным. Lookup-реестр остаётся пустым; worker отправляет неподтверждённые результаты в `manual`, сохраняя удержание. Ни TTL, ни MaxClaims не освобождают такой резерв.

Добавлена операторская CLI `cmd/ai-accounting`. Она не регистрирует HTTP-маршрутов, не обращается к провайдеру и использует отдельное явное подключение `AI_OPS_DATABASE_URL`. Имя БД дополнительно обязательно передавать через `--database-name`; оно сверяется и с DSN, и с `current_database()`. Для чтения используйте DB-роль с SELECT, для разрешения операций — отдельную утверждённую роль с минимальными правами существующего учёта. Не передавайте DSN в аргументах команд и не выдавайте операторские credentials браузеру.

Успешная проверка тестовой среды не заменяет проверку production-копии. Ни production-копия, ни начальные бюджеты компаний не предоставлены. Их нельзя выдумать или автоматически выдать существующим пользователям. Подключение неподтверждённых интеграций также нельзя объявлять завершённым: до появления контрактов они закрыты для генерации.

## Операторские команды

Все команды запускаются из backend-репозитория. `AI_OPS_DATABASE_URL` оператор передаёт через защищённое окружение процесса; CLI не подхватывает произвольную БД из `.env`. В примерах `DATABASE_NAME`, `ORG_UUID`, `ATTEMPT_UUID` и `evidence.json` нужно заменить проверенными значениями.

```text
go run ./cmd/ai-accounting preflight --database-name DATABASE_NAME
go run ./cmd/ai-accounting inspect --database-name DATABASE_NAME --organization ORG_UUID --attempt ATTEMPT_UUID
go run ./cmd/ai-accounting reconcile --database-name DATABASE_NAME
go run ./cmd/ai-accounting reconcile --database-name DATABASE_NAME --apply
go run ./cmd/ai-accounting resolve --database-name DATABASE_NAME --evidence evidence.json
go run ./cmd/ai-accounting resolve --database-name DATABASE_NAME --evidence evidence.json --apply
```

`preflight` выполняет только чтение в согласованном снимке БД: проверяет последние записи Goose для AI-миграций, отсутствие ненастроенных активных компаний/сотрудников, превышенных обязательств, неизвестных и зависших резервов. Порог stale — 15 минут. При проблемах выводит количества и завершает работу с ненулевым кодом. Команда не создаёт квот, периодов и якорей, не меняет enforcement. `0` остаётся явно заданным запретом, а не отсутствующей настройкой. Это проверка данных БД, а не сертификация rollout, конфигурации всех API или доступности провайдера.

`inspect` читает метаданные конкретной исторической попытки только в указанной компании; сообщения и промпты не читает. `reconcile` без `--apply` лишь показывает режим запуска. С `--apply` делает один проход существующего worker: обнаружение/локальная сверка, неизвестные отправленные операции остаются удержанными и переходят в manual. Команда не добавляет отсутствующий lookup провайдера.

`resolve` без `--apply` проверяет подтверждение и привязку к журналу, но не меняет данные. С `--apply` вызывает существующий `AIAccountingService.Fail` → транзакционный repository, сохраняющий событие подтверждения, фактический расход и освобождение остатка резерва. Автор и ссылка на доказательство записываются в `ai_usage_failure_events.evidence_reference`. Цены берутся из закреплённой политики/снимка попытки, а не из файла оператора. Если preview допустим, применение всё равно может получить конфликт при изменении состояния: окончательное решение принимает транзакция.

Файл подтверждённого расхода (числа ниже — только пример формата):

```json
{
  "organization_id": "11111111-1111-4111-8111-111111111111",
  "attempt_id": "22222222-2222-4222-8222-222222222222",
  "operator": "operator-1",
  "evidence_reference": "provider-ticket-42",
  "provider_confirmed": true,
  "outcome": "usage",
  "provider_id": "nitec",
  "endpoint_kind": "chat",
  "actual_model": "openai/gpt-oss-120b",
  "usage_adapter_version": "VERSION_FROM_INSPECT",
  "provider_request_id": "REQUEST_ID_FROM_PROVIDER",
  "usage": {
    "input_tokens": 2,
    "output_tokens": 1,
    "total_tokens": 3
  }
}
```

Используйте только подтверждённые реальные счётчики. Отсутствующее значение не заменяется нулём. Опциональные `cached_input_tokens` и `reasoning_output_tokens` являются подмножествами input/output, а не добавочными токенами. Provider ID, endpoint, компания, попытка, версия адаптера и записанный request ID должны совпадать с журналом; фактическая модель должна иметь цену в закреплённой политике. Поле `provider_request_id` можно не передавать, только если его нет в журнале и провайдер дал другое однозначное подтверждение этой попытки.

Для явно подтверждённого неисполнения задайте `outcome: "not_executed"`, сохраните поля компании, попытки, провайдера, endpoint, автора и ссылки, `provider_confirmed: true`, а `usage` не передавайте. Таймаут, отмена и 404 таким подтверждением не являются. Никакой команды «освободить по возрасту» или «списать приблизительно» нет.

При потере ответа повторяйте **тот же файл**: event ID детерминирован, одинаковое подтверждение не списывает повторно. Изменённые доказательства могут получить конфликт; не меняйте автора/ссылку, чтобы обойти его. После ручного завершения очередной sweep сверки закроет запись очереди; для немедленного sweep доступна команда `reconcile --apply`.

## Покрытие платных границ

| Путь | Текущее безопасное поведение |
| --- | --- |
| Основной AlemAI, unified chat, Notebook, прямые модели Smart Agent | Существующий общий исполнитель: резерв, реальные usage, фактическая проводка; неизвестный результат удерживается. Реальные контракты провайдеров ещё требуют проверки владельцем аккаунта. |
| Drive rewrite/HyDE/embeddings/rerank/индексация векторов | Production-конструктор больше не создаёт прямой Alem-клиент: неподключённый provider отклоняет платные запросы. Обычный текстовый поиск и локальная индексация продолжают работать. Тестовые injected embedders не подтверждают production-контракт. |
| Adaptive web search | HTTP-граница закрыта до появления отдельного контракта расхода внутреннего RAG-сервиса. |
| 2slides | Создание заданий закрыто; существующие GET статуса/тем не изменены. Согласованной job-based цены пока нет. |
| DocumentParse | Production HTTP-парсер закрыт; существующие локальные PDF/OCR/Office fallback остаются. Это может уменьшить поддержку сложных документов, но не создаёт бесплатный удалённый вызов. |
| AxisMail AI | Сервер отклоняет новые задания; транспорт также запрещает выполнение старого задания до отправки. Токен провайдера/URL сами по себе не включают генерацию. Требуются маппинг tenant/user и серверный accounting bridge. Чтение писем не блокируется. |
| Legacy `/api/ask`, `/api/tools` во frontend nginx | Изменяющие методы закрыты с 503 `AI_ACCOUNTING_UNAVAILABLE`, ru/kk. Метаданные/история GET/HEAD и DELETE не меняются. Стандартные бюджетируемые маршруты Go API `/api/v1/...` не перекрываются. |
| Proxy embeddings/rerank | Существующий серверный отказ до подтверждённого usage-контракта сохраняется. |

Снятие любого запрета требует интеграции общего учёта и тестов доказанного usage/стоимости, а не нового env-переключателя обхода. Устанавливаемый пакет `internal/aiaccess` не даёт публичным запросам управлять защитой. Новый nginx-конфиг должен попасть в frontend-образ и пройти обычный отдельный процесс rollout; удалённые шлюзы, опубликованные вне этого ingress, нужно отдельно закрыть на их стороне.

## Повторяемая репетиция обновления

Backend, Docker и Go:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-ai-release.ps1
```

Скрипт не принимает production DSN. Он создаёт PostgreSQL-контейнер со случайным именем/меткой, отдельной БД и случайным портом только на `127.0.0.1`; устанавливает временные env только своего процесса и восстанавливает их. Применяет **весь каталог миграций** дважды, создаёт синтетические бюджет/квоту и два реальных журнальных сценария, проверяет preview и повтор ручной проводки. Затем делает `pg_dump --format=custom`, восстанавливает в другую БД, сравнивает числа строк и контрольные суммы 16 таблиц учёта/Goose и повторяет подтверждение после восстановления. Неизвестный активный резерв должен сохраниться, повторное списание — отсутствовать. Созданный контейнер удаляется после проверки собственной метки; production-контейнеры и базы не затрагиваются.

Frontend, Docker:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-ai-ingress.ps1
```

Проверяет nginx-конфиг и реальные HTTP-отказы внешних генераций на ru/kk в контейнере **без внешней сети**, затем удаляет свой контейнер. Даже дефект правила не может вызвать платный upstream во время теста.

20 октября 2026 года оба скрипта прошли. Отдельно прошли тесты CLI, защитных транспортов, repository readiness/manual resolution, reconciliation, Drive, парсинга и adaptive web search на временной PostgreSQL и локальных HTTP fixtures; почтовый TypeScript и тест запрета отправки также прошли. Платные провайдеры не вызывались. Проверка пустой БД и синтетических записей не является проверкой обновления реальной старой production-схемы или production backup.

## Перед реальным включением

1. Владелец среды предоставляет обезличенную production-копию и проводит тот же migration/restore план на ней.
2. Платформа утверждает бюджеты и служебные выделения; директор/платформа назначают личные квоты через существующий API. Самовольных начальных бюджетов CLI не создаёт.
3. На всех API сохраняется `AI_ACCOUNTING_ENABLED=true`, сначала `AI_ENFORCEMENT_MODE=observe`; мониторинг защищён существующей авторизацией. Глобальный `enforced` включается только после проверки всех компаний, а пилот проводится в отдельной среде.
4. `preflight` должен пройти, а нерешённые unknown — получить доказательства и ручную проводку. При отсутствии доказательств резерв остаётся активным; решение о запуске с такими удержаниями требует отдельной согласованной политики.
5. Реальные usage/lookup-контракты и внешний доступ к обходным шлюзам проверяются отдельно. Без них соответствующие генерации остаются закрытыми. Откат приложения не удаляет журнал, применённые миграции или неизвестные удержания.
# Подготовка релиза 20.10.2026

Перед production номера AI-миграций перенесены в диапазон
20261020100100–20261020101000; выпущенная iForm-миграция
20261019000100 сохраняется без изменений. См. полный порядок в
`ai-budgets-rollout-task-43.md`.

Docker-образ теперь содержит `/app/ai-accounting`. Операторская команда
`defaults --database-name NAME --organization UUID --actor-id ID` показывает
план первичного распределения: 100 кредитов в неделю и 20 на пять часов.
Для записи нужен `--apply`. Соединение задаётся только через явно переданную
`AI_OPS_DATABASE_URL`, имя БД сверяется с реальным подключением. Значение DSN
не выводить в чат, историю команд или журналы.

Сначала суперадминистратор назначает бюджет компании через существующий
интерфейс/API. Команда проверяет его права, состояние компании, максимум
пятичасового лимита и достаточность нераспределённого бюджета. Она не создаёт
бюджет компании самостоятельно. Инициализируются только активные,
незаблокированные сотрудники без обеих настроек квоты. Существующие квоты,
включая нули, журнал, периоды и резервы не меняются.

Каждое назначение использует штатную транзакцию проверки квоты и аудита.
Массовая выдача не является одной общей транзакцией: при конкурентном
изменении процесс останавливается и сообщает количество уже записанных
назначений. Повторить сначала предпросмотр, затем применение; ранее
настроенные сотрудники пропускаются. Не увеличивать бюджет автоматически
для обхода отказа. После изменения квот директором повторный запуск defaults
не возвращает их к стартовым значениям. Для новых сотрудников выдача также
требует явного повторного запуска; автоматической выдачи при найме здесь нет.

`scripts/rehearse-ai-production.sh IMAGE DUMP` восстанавливает архив в
собственном временном PostgreSQL без внешней сети и проверяет миграции
переданного локального образа, сохранность квитанций iForm и повторный запуск.
Рабочая БД, её volume и `.env` не подключаются. Архив остаётся только на сервере.

`scripts/prepare-ai-observe.sh` — отдельный изменяющий настройки шаг оператора:
сохраняет защищённую копию `/opt/workspace/.env`, атомарно задаёт учёт,
наблюдение и worker сверки, проверяет одинаковые значения в разрешённом
Compose для API и document worker. Контейнеры не перезапускает. При ошибке
проверки восстанавливает исходный файл. При текущем пустом реестре lookup
сверка всё ещё требует ручных доказательств для неизвестного расхода.
